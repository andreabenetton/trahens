It defines bounded route discovery, deterministic route-state activation, a concrete classical cryptographic profile, and one fixed-size adjacent-link record. \begin{abstract}
Route discovery can disclose endpoint relationships, local topology, and stable correlation handles before an anonymous data path is established. \ProtoName{} is a privacy-enabled control-plane protocol that discovers an eligible responder within a bounded graph radius and installs hop-local bidirectional forwarding state without transmitting a complete route or a network-wide discovery identifier.

The protocol binds four profiles. \Uone{} requires every forwarded branch to replace its adjacent capability, additively tweak its reply key, universally rerandomize its destination-eligibility capsule, reconstruct the message, and cross a declared mixing boundary. \Eone{} defines half-open deadlines, equal-time event precedence, candidate windows, delayed responses, cancellation races, tentative state, forward \textsc{Commit}, reverse \textsc{Ready}, and deterministic cleanup. \Cone{} instantiates the cryptographic operations with the RFC~9496 \code{ristretto255} group, a Golle--Jakobsson--Juels--Syverson universal re-encryption construction, an additively tweakable reply KEM, HKDF-SHA-256, ChaCha20-Poly1305, and Ed25519. \Wone{} encodes every control message in one 1,052-byte adjacent-link record comprising a 12-byte public link header, a 1,024-byte encrypted body, and a 16-byte authentication tag.

The paper separates record-length equality, passive wire-image unlinkability, conditional batch-local message unlinkability, lifecycle correctness, active-adversary unlinkability, and traffic-flow unlinkability. The integrated reference model executes the wire codec and cryptography inside the event lifecycle. It accepts every clean five-node route in the tracked experiment, rejects adjacent-link tampering, and reaches zero residual state. The analysis also identifies a persistent algebraic ratio tag in the current eligibility capsule: a compromised relay can create a relation that survives honest rerandomization and can be recognized by a colluding downstream relay. Active-adversary unlinkability is therefore not claimed. The results constitute a precise, falsifiable research baseline rather than a security proof or production benchmark.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

\subsection{Motivation}

Anonymous communication is commonly described in terms of a protected data path. Before that path exists, however, a control plane must locate a destination or service, discover one or more usable routes, and install forwarding state. That preparatory process may disclose the same information that the eventual anonymity mechanism is intended to hide: which endpoint is sought, which relays are topologically close, which messages belong to one exploration, and which reverse response corresponds to which forward branch.

The problem is especially visible in decentralized and path-aware networks. A conventional routing protocol may distribute a global or regional topology view. A source-routing system may return a complete path to the sender. A directory may provide a stable lookup handle. Each design can be operationally sound while creating a durable correlation surface. \ProtoName{} investigates a different structure: relays maintain only adjacent capabilities, the initiator receives candidates rather than a topology map, and every branch representation is independently transformed at each forwarding hop.

Privacy cannot be inferred from encryption alone. A stable token inside an encrypted link becomes visible to a compromised relay; a unique record length reveals message class; a deterministic retry handle links expanding rings; a route may be activated before end-to-end confirmation; and a malleable ciphertext may permit active tagging even though every honest rerandomization changes its bytes. The protocol therefore treats privacy, lifecycle correctness, resource safety, wire encoding, and active-adversary behavior as separate objects of specification and measurement.

\subsection{Contributions}

This paper makes the following contributions:

\begin{enumerate}
  \item It defines a bounded route-discovery control plane in which logical discoveries and expanding-ring policy remain local to the initiator, while relays see only peer-bound branch contexts.
  \item It separates six properties that must not be conflated: record-length equality, passive wire-image unlinkability, conditional batch-local message unlinkability, lifecycle correctness, active-adversary unlinkability, and traffic-flow unlinkability.
  \item It specifies the \Uone{} branch-local transformation: branch, candidate, cancellation, and route capabilities are replaced at every hop; reply keys are tweaked; eligibility capsules are rerandomized; and outgoing bodies are reconstructed.
  \item It specifies the \Eone{} event lifecycle, including half-open deadlines, deterministic equal-time precedence, delayed candidates, cancellation races, tentative mappings, \textsc{Commit}, \textsc{Ready}, and cleanup after loss.
  \item It defines the concrete \Cone{} research suite with distinct eligibility, responder-signing, branch-reply, and adjacent-link key roles, canonical encodings, transcript domains, and generic failure behavior.
  \item It defines the \Wone{} fixed-size wire record and exact layouts for \textsc{Discover}, \textsc{Candidate}, route-control, and chaff messages.
  \item It integrates \Uone{}, \Eone{}, \Cone{}, and \Wone{} in one deterministic event model that performs actual cryptographic and codec operations before state activation.
  \item It gives an executable active-tagging counterexample, states the resulting claim boundary, and identifies replacement of the eligibility construction as a mandatory security gate.
\end{enumerate}

It does not define global name resolution, inter-domain routing policy, application-data congestion control, economic incentives, a new physical or link layer, or a replacement for IP.
\end{claimbox}

\section{Related work and cryptographic context}
\label{sec:background}

\subsection{Network-layer anonymity and mix packets}

HORNET demonstrates high-speed anonymous forwarding with symmetric cryptography on the data-plane fast path and no per-flow forwarding state in intermediate routers~\cite{hornet}. TARANET adds setup mixing and coordinated constant-rate transmission to resist traffic analysis at the network layer~\cite{taranet}. Sphinx provides a compact mix packet format with per-hop transformation, path-length hiding, reply support, and formal security goals~\cite{sphinx}. Loopix combines Sphinx packets with stochastic mixing and cover traffic~\cite{loopix}.

These systems begin with a route or layered packet structure already selected by the sender or supplied by another mechanism. \ProtoName{} addresses a prior problem: the sender initially knows the endpoint descriptor but not the path. The protocol must explore a branching graph while avoiding a stable cross-hop identifier. Consequently, techniques designed for a single precomputed onion cannot be copied without modification.

\subsection{Universal re-encryption}

Ordinary rerandomizable ElGamal permits ciphertext rerandomization when the public key is known. Universal re-encryption (URE) additionally permits a mixer to transform a ciphertext without knowing which public key protects it~\cite{gjjs}. That property is useful for \ProtoName{} because including the destination public key beside each discovery capsule would itself create a stable selector. The Golle--Jakobsson--Juels--Syverson construction doubles the ElGamal representation: one pair carries the message and a second pair carries an encryption of the identity, enabling public-key-free rerandomization.

Security terminology for URE has evolved. Recent work emphasizes encryption anonymity, minimal security notions, and composable application behavior rather than rerandomization correctness alone~\cite{ure2023}. C1 therefore treats the 2004 construction as a concrete research candidate and states its claim boundary. It does not infer active security merely because the equations are correct.

\subsection{HPKE and the custom reply KEM}

HPKE standardizes hybrid public-key encryption from a KEM, KDF, and AEAD and gives precise context binding and test vectors~\cite{hpke}. The C1 reply construction follows that discipline but requires a public key that can be additively tweaked at each hop and whose corresponding secret can later be reconstructed by the initiator. RFC~9180 does not register a \code{ristretto255} KEM with this property. C1 therefore defines an HPKE-inspired custom KEM and explicitly refrains from claiming RFC~9180 interoperability.

\section{System model, adversary, and claims}
\label{sec:model}

\subsection{Network model}

Let the communication substrate be an undirected graph
\begin{equation}
G=(V,E),
\label{eq:graph}
\end{equation}
where a node $n\in V$ may act as initiator, relay, responder, or any combination of these roles. An edge $(u,v)\in E$ denotes an authenticated adjacent-link association. A route of length $d$ is a sequence
\begin{equation}
\rho=(n_0,n_1,\ldots,n_d), \qquad (n_i,n_{i+1})\in E.
\label{eq:route}
\end{equation}
The initiator is $n_0$ and the responder is $n_d$. The protocol never transmits $\rho$ as one object.

The adjacent-link transport supplies peer authentication, confidentiality and integrity, exact record boundaries, a directional link epoch, a monotonically managed sequence, and notification of connection failure. The W1 profile fixes the record length and authenticated body. A separate scheduling profile defines batching, permutation, release delay, and cover traffic. Adjacent-link protection prevents an external observer from reading or modifying an honest-to-honest edge; it does not make a compromised relay honest or constrain the content of a new record emitted by that relay.

\subsection{Adversary}

The adversary may:

\begin{itemize}
  \item observe links not protected by the stated underlay profile;
  \item compromise a bounded set of nodes and inspect their keys, state, queues, and local timing;
  \item inject, drop, delay, duplicate, reorder, redirect, or modify records at compromised nodes;
  \item generate fresh syntactically valid branches rather than only replaying old records;
  \item coordinate observations from multiple compromised relays;
  \item attempt resource exhaustion, candidate spam, and active ciphertext tagging.
\end{itemize}

The adversary cannot break the selected cryptographic assumptions, forge uncompromised adjacent-link authentication, or read an honest-to-honest protected link. Traffic-flow claims require a separate observation and scheduling profile; C1 alone does not conceal timing.

\subsection{Separated properties}

\begin{definition}[Record-length equality]
Every control message has the same complete adjacent-link length, independently of message type, candidate depth, protected-body length, or chaff status.
\end{definition}

\begin{definition}[Passive wire-image unlinkability]
For passively observed messages processed by at least one honest relay, protocol fields exposed after adjacent-link decryption do not provide a deterministic equality test linking an incoming representation to a non-adjacent outgoing representation.
\end{definition}

\begin{definition}[Batch-local message unlinkability]
After an honest per-hop cryptographic transformation and a mixing boundary containing $k\ge2$ records with the same observable treatment, a passive observer cannot match a designated input to its output with advantage exceeding the relevant cryptographic advantage and information exposed by the batching policy.
\end{definition}

\begin{definition}[Lifecycle correctness]
Every accepted control event produces one deterministic state transition or rejection, every state has a finite local deadline, and loss of any cleanup message cannot create permanent state.
\end{definition}

\begin{definition}[Active-adversary unlinkability]
Compromised relays cannot install a persistent recognizable relation, selective-failure marker, or other active tag that links non-adjacent representations of one branch with non-negligible advantage.
\end{definition}

\begin{definition}[Traffic-flow unlinkability]
An observer cannot reliably correlate communication endpoints using timing, direction, volume, queue behavior, topology, retries, or long-lived observation.
\end{definition}

\section{Protocol overview}
\label{sec:overview}

\subsection{Phase structure}

A responder returns a candidate through stored branch contexts. Candidate return installs only tentative route state. The selected route becomes usable only after \textsc{Commit} travels forward and \textsc{Ready} returns.

\subsection{Local state versus wire state}

The initiator maintains a \emph{logical discovery}: application request, destination descriptor, ring schedule, cumulative budget, candidate set, and selection deadline. None of its identity fields appears on the wire. The only relay-visible discovery object is a \emph{branch context}, bound to one ingress peer, one branch token, one link epoch, one incoming reply public key, one URE capsule, a finite expiry, and bounded child mappings.

This distinction permits retries without a network-wide attempt identifier. It also creates a cost: a relay cannot collapse two converging branches merely because they belong to the same logical discovery. That loss of global duplicate suppression is deliberate and is bounded by explicit quotas.

\subsection{One branch in plain language}

For one outgoing branch, the initiator generates a random link-local token, an ephemeral reply key, and a URE capsule addressed to the endpoint eligibility key. A relay that accepts the record creates a local context. For each selected child it generates a new token, adds a random scalar multiple of the group generator to the reply key, universally rerandomizes the four-point eligibility capsule, reconstructs every mutable field, pads the record, and sends a fresh adjacent-link ciphertext. The child cannot compare a stable token, reply key, or destination ciphertext with the parent's input.

An eligible endpoint decrypts the URE capsule to a fixed marker. It signs a candidate transcript and encrypts the candidate to the final reply key. On the reverse path each relay encrypts its stored key tweak and the child capsule to the prior reply key. The initiator opens one layer, learns the tweak, derives the next secret key, and repeats until it verifies the responder.

\begin{warningbox}[Cryptographic gate]
C1 resolves ambiguity and enables interoperability tests. It does not close the production-security gate. The URE construction requires modern proof alignment and active-tagging analysis; the reply KEM is custom and unregistered; the complete suite is classical rather than post-quantum.
\end{warningbox}

\subsection{Canonical encodings and domain separation}

Every C1 group element has the canonical 32-byte encoding defined by RFC~9496. Scalars are canonical 32-byte little-endian integers less than $q$; zero is rejected where a secret, tweak, or ephemeral scalar is required. Public keys and KEM encapsulations reject the identity element.

Let \code{LP16(x)} be a two-byte unsigned big-endian length followed by $x$. C1 defines
\begin{equation}
\operatorname{EF}(\ell;x_1,\ldots,x_m)
 = \code{``Trahens-C1-v1''}\concat \operatorname{LP16}(\ell)
   \concat \operatorname{LP16}(x_1)\concat\cdots\concat\operatorname{LP16}(x_m).
\label{eq:encodefields}
\end{equation}
All KDF and transcript labels use \cref{eq:encodefields}. Implicit concatenation, JSON serialization, locale-dependent text, and alternate integer encodings are non-conforming.

\subsection{Endpoint descriptor and address}

An endpoint has independent eligibility and signing key pairs:
\begin{equation}
(a,A=aB), \qquad (sk_S,vk_S).
\end{equation}
The 67-byte C1 descriptor is
\begin{equation}
D=\code{version}_{1}\concat\code{suite}_{2}\concat\bytes{A}_{32}\concat vk_{S,32},
\label{eq:descriptor}
\end{equation}
and its address is
\begin{equation}
\mathsf{addr}=\operatorname{SHA256}(\operatorname{EF}(\code{endpoint-address};D)).
\label{eq:address}
\end{equation}
A discovery initiator needs the descriptor, not merely the address hash, because it must encrypt to $A$ and later verify signatures under $vk_S$. Any directory supplying $D$ must authenticate the binding in \cref{eq:address}.

\subsection{Universal eligibility capsule}
\label{sec:ure}

C1 represents eligibility by one fixed group element $M_\star$, derived from a domain-separated 64-byte hash using the RFC~9496 element-derivation interface. Encrypting a fixed marker is sufficient: only the holder of the intended eligibility secret obtains $M_\star$ after the consistency check; a wrong key produces a failed check or an unrelated group element with overwhelming probability.

\subsubsection{Encryption}

For public key $A=aB$, sample $r_0,r_1\sample\Zq^*$ and compute
\begin{equation}
\begin{aligned}
U_0 &= M_\star+r_0A, & V_0 &= r_0B,\\
U_1 &= r_1A,         & V_1 &= r_1B.
\end{aligned}
\label{eq:ureenc}
\end{equation}
The capsule is
\begin{equation}
Q=((U_0,V_0),(U_1,V_1)),
\end{equation}
encoded as four consecutive 32-byte group elements. It is therefore exactly 128 bytes.

\subsubsection{Public-key-free rerandomization}

A relay samples $s_0\sample\Zq^*$ and $s_1\sample(\Zq^*\setminus\{1\})$, then computes
\begin{equation}
\begin{aligned}
U'_0 &= U_0+s_0U_1, & V'_0 &= V_0+s_0V_1,\\
U'_1 &= s_1U_1,     & V'_1 &= s_1V_1.
\end{aligned}
\label{eq:urerand}
\end{equation}
The relay does not need $A$. For a valid input, the effective randomness becomes $r'_0=r_0+s_0r_1$ and $r'_1=s_1r_1$. The restrictions $s_0\ne0$ and $s_1\ne1$ ensure that all four point encodings change; an implementation rejects an unchanged result.

\begin{proposition}[URE correctness]
For every valid C1 capsule $Q$ encrypted under $A=aB$, decryption of any rerandomization $Q'$ produced by \cref{eq:urerand} yields the same marker $M_\star$ and passes the consistency check.
\end{proposition}

\begin{proof}
Using $U'_1=s_1r_1A$ and $V'_1=s_1r_1B$,
$U'_1-aV'_1=s_1r_1(aB)-a(s_1r_1B)=\Identity$.
Similarly,
$U'_0-aV'_0=M_\star+(r_0+s_0r_1)A-a(r_0+s_0r_1)B=M_\star$.
\end{proof}

\subsubsection{Decryption}

The endpoint computes
\begin{equation}
T=U_1-aV_1
\end{equation}
and rejects unless $T=\Identity$. It then computes $M=U_0-aV_0$ and declares itself eligible only if $M=M_\star$. Invalid encodings, consistency failure, marker mismatch, and wrong-key failure all map to the same local result.

\begin{algorithm}[ht]
\caption{C1 eligibility processing at a potential responder}
\label{alg:eligibility}
\begin{algorithmic}[1]
\Require eligibility secret $a$, encoded capsule $Q$
\If{any of the four group elements fails canonical decoding}
  \State \Return \textsc{Invalid-Crypto}
\EndIf
\State $T\gets U_1-aV_1$
\If{$T\ne\Identity$}
  \State \Return \textsc{Not-Eligible}
\EndIf
\State $M\gets U_0-aV_0$
\If{$M\ne M_\star$}
  \State \Return \textsc{Not-Eligible}
\EndIf
\State \Return \textsc{Eligible}
\end{algorithmic}
\end{algorithm}

\subsection{Reply-key tweaking}
\label{sec:tweak}

For every first-hop branch, the initiator samples $x_0\sample\Zq^*$ and publishes $X_0=x_0B$. A relay forwarding to a child samples $\delta_i\sample\Zq^*$ and computes
\begin{equation}
X_{i+1}=X_i+\delta_iB.
\label{eq:tweakpublic}
\end{equation}
The relay stores $\delta_i$ only in the corresponding child context. It resamples if the result is the identity. The initiator later computes
\begin{equation}
x_{i+1}=x_i+\delta_i\pmod q.
\label{eq:tweaksecret}
\end{equation}

\begin{proposition}[Tweak consistency]
The secret update in \cref{eq:tweaksecret} corresponds to the public update in \cref{eq:tweakpublic}.
\end{proposition}
\begin{proof}
$(x_i+\delta_i)B=x_iB+\delta_iB=X_i+\delta_iB=X_{i+1}$.
\end{proof}

\subsection{TR-KEM-R255 and reply encryption}
\label{sec:replykem}

To encrypt to $X=xB$, the sender samples $e\sample\Zq^*$ and computes
\begin{equation}
R=eB, \qquad Z=eX.
\label{eq:kemdh}
\end{equation}
The receiver computes the same $Z=xR$. The KEM context binds the suite, encapsulated element, recipient public key, and a caller-provided \code{info} value:
\begin{align}
\mathsf{ctx} &= \operatorname{EF}(\code{reply-kem-context};\code{suite},\bytes R,\bytes X,\mathsf{info}),\\
\mathsf{prk} &= \operatorname{HKDFExtract}(0^{32},\operatorname{EF}(\code{reply-kem-dh};\bytes Z)),\\
\mathsf{ss} &= \operatorname{HKDFExpand}(\mathsf{prk},\operatorname{EF}(\code{reply-kem-secret};\mathsf{ctx}),32).
\end{align}
The AEAD key and nonce are independently labeled HKDF expansions of $\mathsf{ss}$ and $\mathsf{ctx}$. The output is $\bytes R$ followed by a ChaCha20-Poly1305 ciphertext with the complete 16-byte tag.

The nonce is deterministic under the encapsulation-derived secret. This is safe only if $e$ is fresh. Reusing $e$ for the same recipient and \code{info} repeats both key and nonce and is prohibited. Deterministic ephemerals appear only in published test vectors.

\subsection{Responder authentication and transcript binding}

The responder signs
\begin{equation}
\mathsf{CandidateTH}=
\operatorname{SHA256}(\operatorname{EF}(\code{candidate-transcript};\mathcal F)),
\label{eq:candidateth}
\end{equation}
where the ordered field list $\mathcal F$ includes protocol and profile versions, endpoint address and descriptor, final reply public key, offer class, route limits, offer expiry, commit challenge, and responder nonce. The Ed25519 key must equal $vk_S$ in the descriptor, and the descriptor must hash to the requested endpoint address.

The response includes a random commit challenge. Later, \textsc{Commit} and \textsc{Ready} carry end-to-end HMAC proofs over domain-separated transcript hashes. Relays treat those protected bodies as opaque and route them using local labels.

\subsection{Failure normalization}

C1 exposes one state-machine outcome, \textsc{Invalid-Crypto}, for invalid points, identity public keys, non-canonical scalars, URE failure, AEAD failure, AAD or \code{info} mismatch, invalid signatures, and transcript mismatch. The detailed reason may be logged locally but is never sent as a differentiated response. Record-size, replay, rate, and capacity checks precede expensive cryptographic work.

This rule limits explicit oracles; it does not prove constant-time behavior. Production code would require side-channel review, constant-time group and comparison operations, memory-clearing policy, and a uniform scheduling analysis.

\section{Forward discovery}
\label{sec:forward}

\subsection{Initiator behavior}

A logical discovery selects a local expanding-ring policy
\begin{equation}
\mathcal R_r=(d_r,f_r^{(0)},f_r,\Delta_r),
\end{equation}
where $d_r$ is the hop limit, $f_r^{(0)}$ the first-hop fan-out, $f_r$ the relay fan-out, and $\Delta_r$ the local candidate window. Neither $r$ nor the tuple is transmitted directly; only bounded propagation and fan-out classes required by the relay appear in the branch record.

For every first-hop peer, the initiator creates independent state. It does not reuse a branch token, root reply key, URE randomness, padding, or adjacent-link ciphertext.

\begin{algorithm}[ht]
\caption{Initiator: create one C1 DISCOVER branch}
\label{alg:init}
\begin{algorithmic}[1]
\Require first-hop peer $n_1$, destination descriptor $D$, local budget $\mathcal B$
\If{$\mathcal B$ cannot reserve one branch and one transmission}
  \State \Return failure
\EndIf
\State parse and validate $(A,vk_S)$ from $D$; verify the requested address
\State $x_0\sample\Zq^*$; $X_0\gets x_0B$
\State $\tau_0\sample\{0,1\}^{128}$
\State $Q_0\gets\mathsf{URE.Enc}(A,M_\star)$
\State $M_0\gets\Encode(\textsc{Discover},\tau_0,X_0,Q_0,\mathsf{bounds},\mathsf{expiry})$
\State reconstruct and pad $M_0$ to the DISCOVER record class
\State store $(n_1,\tau_0,x_0,\mathsf{expiry})$ in initiator-local branch state
\State enqueue a fresh adjacent-link encryption of $M_0$
\end{algorithmic}
\end{algorithm}

\subsection{Relay validation order}

The relay processes cheap and local checks before expensive group operations:

\begin{enumerate}
  \item record-class length, byte rate, and adjacent-link replay;
  \item adjacent-link authentication and protocol/profile identifiers;
  \item canonical framing, lifetime class, and branch-token replay;
  \item ingress-peer token bucket and node-global work budget;
  \item provisional state reservation;
  \item C1 point decoding, URE validation for rerandomization, and reply-key processing;
  \item full state allocation and bounded outgoing work.
\end{enumerate}

A failure at one stage does not consume resources reserved for a later stage. No invalid branch generates an amplified error response.

\subsection{Per-child transformation}

For each selected child, the relay performs all transformations independently. Reusing one tweak or rerandomization across several children would allow sibling equality tests and is prohibited.

\begin{algorithm}[ht]
\caption{Relay: transform one admitted DISCOVER branch}
\label{alg:relay}
\begin{algorithmic}[1]
\Require ingress peer $p$, token $\tau_i$, key $X_i$, capsule $Q_i$, bounds
\State allocate branch context $b\gets\BranchT[p,\tau_i]$
\State $S\gets\mathsf{SelectChildren}(N(n_i)\setminus\{p\},f)$
\ForAll{$c\in S$}
  \State $\tau_c\sample\{0,1\}^{128}$
  \Repeat
    \State $\delta_c\sample\Zq^*$; $X_c\gets X_i+\delta_cB$
  \Until{$X_c\ne\Identity$}
  \State $s_{0,c}\sample\Zq$; $s_{1,c}\sample\Zq^*$
  \State $Q_c\gets\Rerand(Q_i;s_{0,c},s_{1,c})$
  \State store $(c,\tau_c,\delta_c,X_c)$ in $b$
  \State reconstruct all mutable fields and generate fresh padding
  \State enqueue a fresh adjacent-link encryption to $c$ through the mixing queue
\EndFor
\end{algorithmic}
\end{algorithm}

\subsection{Loops and converging branches}

Immediate backtracking to the ingress peer is excluded. Exact duplicates on the same link epoch are rejected. A branch arriving over another peer or under another token is a different branch context, even if it belongs to the same initiator-local discovery. Longer cycles and converging branches therefore cause repeated state. The hop limit, fan-out, per-peer token bucket, per-node context ceiling, cumulative transmission budget, and expiry bound the amplification.

Attempt-wide first-parent suppression would reduce cost but requires an equality domain shared across hops. the current protocol chooses the privacy structure and measures the resulting cost rather than hiding it.

\section{Candidate return and route activation}
\label{sec:reverse}

\subsection{Responder candidate}

A node first evaluates the C1 eligibility capsule. If eligible and willing to respond, it constructs a candidate payload containing the endpoint descriptor, offer and limit classes, expiry, commit challenge, responder nonce, final reply key, and Ed25519 signature over \cref{eq:candidateth}. It encrypts the payload to $X_d$ using \code{TR-KEM-R255}.

The responder does not reveal its identity to intermediate relays. Those relays see only a fixed-class candidate record, local capabilities, and an opaque reverse capsule.

\subsection{Relay reverse layer}

Suppose relay $n_i$ previously transformed $X_i$ into $X_{i+1}=X_i+\delta_iB$ for the selected child. On receiving the child candidate capsule $C_{i+1}$, the relay creates a fresh parent candidate token $\gamma_i$ and forward label $\lambda_i^{\rightarrow}$, then computes
\begin{equation}
C_i=\Seal_{X_i}\left(
\Encode(\delta_i,C_{i+1},\lambda_i^{\rightarrow},\mathsf{limits},\mathsf{padding});
\mathsf{info}_i,\mathsf{aad}_i
\right).
\label{eq:reversewrap}
\end{equation}
The \code{info} and AAD bind the protocol version, suite, depth class, parent token, parent label, record class, link epoch, and offer expiry. A mutation of those fields causes AEAD failure.

The relay stores a tentative mapping from the parent-facing candidate capability and forward label to the child branch. It does not learn the responder payload or the contents of $C_{i+1}$.

\subsection{Initiator opening procedure}

The initiator begins with $x_0$. After opening $C_0$, it obtains $\delta_0$ and $C_1$, computes $x_1=x_0+\delta_0\bmod q$, and continues. At the innermost layer it verifies the endpoint descriptor, address, Ed25519 signature, final reply key, responder nonce, offer limits, and expiry.

\begin{algorithm}[ht]
\caption{Initiator: open the C1 candidate chain}
\label{alg:open}
\begin{algorithmic}[1]
\Require root secret $x_0$, outer capsule $C_0$, maximum depth $d_{\max}$
\State $i\gets0$
\While{$i\le d_{\max}$}
  \State $Y\gets\Open_{x_i}(C_i;\mathsf{info}_i,\mathsf{aad}_i)$
  \If{$Y$ is a responder candidate}
    \State verify descriptor, address, signature, final $X_i$, nonce, limits, and expiry
    \State \Return authenticated candidate
  \ElsIf{$Y=\Encode(\delta_i,C_{i+1},\Lambda_i)$}
    \State validate canonical non-zero $\delta_i$ and local transcript context
    \State $x_{i+1}\gets x_i+\delta_i\pmod q$
    \State $i\gets i+1$
  \Else
    \State \Return \textsc{Invalid-Crypto}
  \EndIf
\EndWhile
\State \Return \textsc{Invalid-Crypto}
\end{algorithmic}
\end{algorithm}

\subsection{Worked three-hop example}
\label{sec:workedexample}

Consider $n_0\rightarrow n_1\rightarrow n_2\rightarrow n_3$, where $n_3$ is the responder. The initiator creates $(x_0,X_0)$. Relay $n_1$ chooses $\delta_0$ and sends $X_1=X_0+\delta_0B$. Relay $n_2$ chooses $\delta_1$ and sends $X_2=X_1+\delta_1B$. The responder encrypts its candidate to $X_2$.

On the reverse path, $n_2$ seals $(\delta_1,C_2)$ to $X_1$ and $n_1$ seals $(\delta_0,C_1)$ to $X_0$. The initiator opens $C_0$ with $x_0$, derives $x_1=x_0+\delta_0$, opens $C_1$, derives $x_2=x_1+\delta_1$, and finally opens the responder candidate. Neither relay learns $x_0$, any later secret, or the responder payload.

\subsection{Commit and readiness}

A candidate creates only tentative state. The initiator selects at most one candidate and sends \textsc{Commit} through its first-hop forward label. Each relay validates the peer, label, route generation, local transcript digest, and capacity class; reserves route capacity; changes the mapping to \textsc{Pending-Ready}; assigns a finite deadline; and forwards the opaque end-to-end commit body.

The responder verifies the commit HMAC derived from the challenge embedded in the signed candidate. It returns \textsc{Ready} through reverse labels. Relays change the matching pending mapping to \textsc{Active}. The initiator exposes the route to the data plane only after verifying the final ready proof. If either control message is lost, all partial state expires locally.

\section{Event lifecycle profile E1}
\label{sec:lifecycle}

\subsection{Half-open deadlines}

A local state created at $t_c$ with deadline $t_e$ is valid exactly on
\begin{equation}
[t_c,t_e)=\{t\mid t_c\le t<t_e\}.
\label{eq:halfopen}
\end{equation}
It is invalid at $t=t_e$ and cannot be revived. Received lifetime classes are converted to local deadlines; synchronized clocks are unnecessary. If a valid transition replaces a deadline, an old timer is associated with the previous state generation and cannot shorten the new state.

\subsection{Equal-time precedence}

Events assigned the same local timestamp follow the strict order
\begin{equation}
\mathsf{Expire}\prec\mathsf{Cancel}\prec\mathsf{RouteControl}
\prec\mathsf{Candidate}\prec\mathsf{Discover}\prec\mathsf{WindowClose}.
\label{eq:precedence}
\end{equation}
A message at its state deadline therefore fails, but a candidate at the exact window boundary remains eligible because candidate processing precedes window closure.

\subsection{Candidate windows and delayed responses}

A ring begins at local time $a_r$ and closes at $w_r=a_r+\Delta_r$. A candidate from any already-started ring is eligible at $w_r$ if no route has been selected, its signed offer has not expired, and every required tentative mapping survived the reverse traversal. Thus a delayed candidate from an earlier ring may win during a later ring without exposing a ring identifier on the wire.

Selection is immutable. After choosing one candidate, the initiator sends \textsc{Commit} on the selected path and sends transformed \textsc{Cancel} messages through stored adjacent mappings into maximal off-route subtrees that belong to its own discovery. Cancel is an optimization; expiry remains authoritative.

\section{Wire protocol W1 and relay state}
\label{sec:messages}

\subsection{Fixed adjacent-link envelope}

W1 gives every control message one complete wire length. Let $H_W$ be the public link header, $P_W$ the authenticated plaintext, and $T_W$ the AEAD tag. The reference record is
\begin{equation}
R_W=H_W\concat\operatorname{AEAD.Seal}(K_\ell,N_\ell,H_W,P_W),
\qquad |R_W|=12+1024+16=1052\ \text{bytes}.
\label{eq:w1record}
\end{equation}
The public header is $H_W=e_\ell\concat s_\ell$, where the epoch is a four-byte unsigned integer and the sequence is an eight-byte unsigned integer, both in network byte order. The pair is scoped to one direction of one adjacent association. Reuse of a link key and nonce pair is prohibited.

The encrypted body begins with an eight-byte common prefix. The message type and all protocol-classifying values are therefore hidden from an observer without the adjacent-link key.

\subsection{Receive pipeline}

A receiver applies the following order:

\begin{enumerate}
  \item reject a record whose length is not exactly 1,052 bytes;
  \item apply directional epoch, sequence, byte-rate, and exact-replay admission;
  \item authenticate and open the adjacent-link AEAD;
  \item validate the common prefix, reserved byte, message type, and canonical lengths;
  \item enforce E1 expiry, per-peer token-bucket, node-global state, and cryptographic-work budgets;
  \item validate C1 points, capsules, nested layers, signatures, or route-control proofs;
  \item allocate or transition protocol state only after all required validation succeeds;
  \item construct a new plaintext and new adjacent-link ciphertext for each outgoing record.
\end{enumerate}

This order prevents malformed length and link ciphertexts from allocating branch or route state. Detailed cryptographic failure remains local and maps to one externally visible behavior: bounded silent discard unless a separately specified non-amplifying control response is required.

\section{Unlinkability analysis}
\label{sec:unlinkability}

\subsection{Elimination of explicit equality handles}

Between an admitted incoming \textsc{Discover} and each outgoing child record, an honest relay changes:

\begin{enumerate}
  \item the branch token;
  \item the reply public key;
  \item all four URE group elements;
  \item the bounded propagation representation;
  \item the padding;
  \item the adjacent-link nonce and ciphertext;
  \item the output timing position within the declared batch policy.
\end{enumerate}

It also reconstructs the body rather than forwarding received bytes. Candidate tokens and route labels are likewise replaced on reverse and activation paths.

\begin{proposition}[No explicit stable handle]
Assume canonical C1 processing, independently sampled per-child randomness, and no implementation-added identifier. A conforming honest relay copies no protocol field unchanged from an incoming DISCOVER record into a non-adjacent outgoing DISCOVER record.
\end{proposition}

The proposition is syntactic. It does not imply that timing, topology, message scarcity, or maliciously chosen transformations cannot correlate the records.

\subsection{Conditional batch-local argument}

Let an honest relay release a batch of $k$ records with identical observable class and scheduling treatment. If the C1 reply-key transformation and URE rerandomization are unlinkable under their assumptions, link ciphertexts are fresh, and no hidden implementation field survives, then a passive observer's matching information is limited to cryptographic advantage and batch-policy information. In the ideal uniform batch, the baseline guessing probability is $1/k$.

The argument fails when $k=1$, when one record has a distinct length or release time, when a stable logging or tracing field leaks, or when the observer uses end-to-end timing. Accordingly, U1 conformance is profile-specific rather than a property of C1 alone.

\subsection{Persistent active ratio tag}
\label{sec:active-tagging}

The passive transformation argument does not extend to a compromised relay. In a valid C1 consistency pair,
\begin{equation}
(U_1,V_1)=(r_1A,r_1B), \qquad A=aB.
\label{eq:validconsistency}
\end{equation}
A malicious relay chooses a known non-zero scalar $c$ and replaces the pair by
\begin{equation}
(\widetilde U_1,\widetilde V_1)=(cV_1,V_1).
\label{eq:ratiotag}
\end{equation}
Both values remain canonical non-identity group elements. After an honest relay rerandomizes with non-zero scalar $s$, the pair becomes
\begin{equation}
(\widetilde U'_1,\widetilde V'_1)=(scV_1,sV_1).
\end{equation}
A colluding downstream relay tests
\begin{equation}
\widetilde U'_1\stackrel{?}=c\widetilde V'_1,
\label{eq:tagtest}
\end{equation}
which always holds. The relation is therefore a deterministic cross-hop tag that survives the honest transformation.

The destination computes the consistency value
\begin{equation}
T=\widetilde U'_1-a\widetilde V'_1=(c-a)sV_1.
\label{eq:tagfailure}
\end{equation}
Except when $c=a$, the destination rejects the capsule and returns no candidate. The attack combines linkability and denial of service; observation of the missing candidate or missing route activation may also provide confirmation.

\begin{proposition}[Active-unlinkability counterexample]
Under the present C1 eligibility construction, two colluding compromised relays separated by any number of honest rerandomizing relays can link a tagged branch by the test in \Cref{eq:tagtest}. Consequently, the protocol does not satisfy active-adversary message unlinkability.
\end{proposition}

Adjacent-link authentication does not prevent the attack. It rejects modification by a third party on an edge, but a compromised relay can originate a new syntactically valid outgoing W1 record containing the tagged pair. Fixed length, canonical point encoding, non-identity checks, fresh link encryption, and generic endpoint failure are necessary controls but do not erase the algebraic relation.

The active-security gate remains closed until a replacement destination-eligibility mechanism has a precise active-adversary definition, reviewed security argument, bounded verification cost, fixed-size encoding, and negative tests for algebraic, substitution, replay, truncation, and selective-failure tags.

\subsection{Timing limitation}

Fixed record sizes and per-hop cryptographic changes do not hide timing. TARANET's coordinated constant-rate approach and Loopix's stochastic mixing with cover traffic represent different latency--bandwidth trade-offs~\cite{taranet,loopix}. \ProtoName{} treats batching, release cadence, and cover traffic as separate scheduling profiles. Each profile must state its observer, latency, bandwidth cost, minimum anonymity set, and measured matching success.

\section{Resource and denial-of-service model}
\label{sec:resources}

\subsection{Why privacy increases state}

Without a shared attempt identifier, a relay cannot recognize all converging copies of one logical discovery. In a tree approximation with relay fan-out $f$ and depth $d$, the number of branch transmissions can approach
\begin{equation}
T(f,d)=\sum_{i=1}^{d}f^i=\frac{f^{d+1}-f}{f-1}, \qquad f>1.
\label{eq:treegrowth}
\end{equation}
Cycles and duplicate graph paths can increase repeated visits further. Privacy therefore requires hard limits rather than optimistic assumptions about deduplication.

\subsection{Required limits}

Every node defines finite limits for:

\begin{itemize}
  \item accepted branch contexts per ingress peer and globally;
  \item fresh branches per peer and time window;
  \item outgoing children per branch and total queued records;
  \item URE rerandomizations, group multiplications, KEM operations, and signature checks;
  \item candidate responses per branch and per endpoint identity;
  \item tentative, pending-ready, and active route capacity;
  \item record bytes, setup duration, retries, and cleanup retention.
\end{itemize}

Exact replay rejection occurs before token-bucket consumption. A fresh valid token is not a replay and consumes an ingress token before expensive cryptography. Per-peer buckets mitigate concentrated sources but do not provide Sybil or distributed-denial resistance.

\subsection{Amplification condition}

For one admitted branch $b$, define
\begin{equation}
\alpha_b=\frac{W_{\mathrm{out}}(b)+W_{\mathrm{state}}(b)+W_{\mathrm{crypto}}(b)}{W_{\mathrm{in}}(b)},
\end{equation}
where the numerator represents normalized outgoing, state, and cryptographic work. A profile must bound each component independently. A small response byte count does not compensate for unbounded group operations or retained state.

\section{Limitations and open problems}
\label{sec:limitations}

\subsection{Eligibility construction and active security}

The ratio-tag counterexample is the principal blocking defect. Correct URE rerandomization and passive ciphertext anonymity are insufficient when a relay can deliberately install a homogeneous relation that an honest transformation preserves. A replacement must hide the destination key, permit public per-hop transformation, resist persistent tagging and selective failure, fit a fixed wire envelope, and have bounded verification cost. Detection only at the destination is insufficient because colluding relays have already linked the branch.

\subsection{Independent cryptographic review}

The remaining C1 equations are executable and internally consistent, but correctness is not equivalent to security. Review must address recipient anonymity, the additive related-key behavior of the custom reply KEM, CCA behavior of nested layers, transcript and key privacy, point-encoding assumptions, failure timing, and side-channel behavior. The custom reply construction is HPKE-inspired and is not an RFC~9180 HPKE suite.

\subsection{Candidate depth and wire capacity}

W1 fixes one 1,024-byte plaintext. The current 960-byte candidate region accommodates the 256-byte responder payload and up to five relay wrappers. A target topology requiring greater setup depth needs either a larger fixed profile, a compact shifting construction, or a separately analyzed fragmentation scheme. A deployment must not silently vary the W1 length because doing so would reintroduce a record-class fingerprint.

\subsection{Post-quantum migration}

C1 is entirely classical. A hybrid KEM replacement is not enough because the eligibility selector must also preserve destination-key privacy and safe public transformation. Post-quantum rerandomization or a different private eligibility mechanism is therefore a separate research problem.

\subsection{Directory and descriptor distribution}

Long-range descriptor resolution is outside the protocol defined here. A future directory must provide authenticated descriptor binding, freshness, replication, poisoning resistance, selective-denial analysis, enumeration resistance, and private queries. Repeated deterministic hashing of an endpoint address is not sufficient query privacy.

\subsection{Distributed abuse and fairness}

Per-peer token buckets remain vulnerable to Sybil distribution. Candidate and responder spam require quotas independent of branch admission. Evaluation must vary attacker distribution, peer churn, adaptive refill, honest convergence, and fairness by ingress peer rather than report only aggregate success.

\subsection{Traffic privacy}

Timing, direction, volume, and topology remain major correlation surfaces. A traffic-privacy profile must define batching, release cadence, cover traffic, overflow behavior, and observable classes, then measure bandwidth, latency, and matching success against a named adversary. Encryption and fixed length alone do not imply traffic-flow unlinkability.

\section{Implementation and review strategy}
\label{sec:strategy}

Development should proceed through explicit gates:

\begin{enumerate}
  \item replace or strengthen the eligibility construction against the ratio-tag and selective-failure class;
  \item state a precise active-adversary game and obtain independent review of the eligibility and reply-key mechanisms;
  \item generate the W1 parser and encoder from a reviewed schema and implement an independent second codec;
  \item cross-check canonical records, C1 vectors, and a malformed-input corpus across implementations;
  \item add fuzzing for record lengths, nested candidate boundaries, point encodings, transcript substitutions, and state races;
  \item build a user-space overlay prototype over an existing authenticated transport;
  \item test interoperability under loss, duplication, reordering, link churn, malicious peers, and distributed resource pressure;
  \item specify and evaluate traffic-scheduling profiles before making timing or flow claims;
  \item design long-range descriptor resolution as a separate protocol with its own threat model.
\end{enumerate}

The first overlay prototype should use ordinary IP connectivity only as an experimental transport. It should not require special routers or a new link technology. Protocol state, privacy transformations, failure behavior, and resource limits should be evaluated before lower-layer integration is considered.

\section{Conclusion}
\label{sec:conclusion}

\ProtoName{} defines a privacy-enabled route-discovery control plane rather than a replacement for IP or BGP. Its current form has a precise operational boundary. U1 removes explicit cross-hop equality handles under passive observation; E1 gives deterministic bounded route setup and cleanup; C1 defines concrete classical cryptographic operations and transcripts; and W1 gives every control message one exact adjacent-link representation.

The integrated model shows that codec, cryptography, and lifecycle can be exercised together: clean routes activate only after authenticated candidate, \textsc{Commit}, and \textsc{Ready} processing; link tampering fails before state allocation; and every evaluated scenario reclaims all state. The same integration exposes a material defect. The C1 eligibility consistency pair admits a persistent ratio tag, so active-adversary message unlinkability is not achieved. This negative result narrows the next task: redesign the private eligibility mechanism, preserve the fixed-size branch-local structure, and require evidence against active tagging before advancing the security claim.

The protocol is therefore suitable as a falsifiable research specification and interoperability target, but not as a production anonymity system.

\section{Normative requirement summary}
\label{app:normative}

The keywords ``MUST'', ``MUST NOT'', ``REQUIRED'', ``SHOULD'', ``SHOULD NOT'', and ``MAY'' are interpreted according to BCP~14~\cite{rfc2119,rfc8174}.

An implementation claiming U1, E1, C1, and W1 conformance MUST:

\begin{enumerate}
  \item omit logical discovery, attempt, ring, global candidate, and global route identifiers from the wire;
  \item replace branch, candidate, cancellation, and route capabilities at every hop;
  \item use independent reply root keys and URE randomness for every first-hop branch;
  \item validate canonical RFC~9496 point encodings and C1 scalar encodings;
  \item reject identity public keys and KEM encapsulations;
  \item apply the exact C1 URE encryption, rerandomization, and eligibility equations;
  \item use independent rerandomization scalars with $s_0\ne0$ and $s_1\notin\{0,1\}$ for every child;
  \item apply the exact C1 reply-key tweak and \code{TR-KEM-R255} context derivation;
  \item bind candidate fields in the exact ordered transcript and verify Ed25519 under the descriptor key;
  \item map cryptographic failures to one external state-machine result;
  \item encode every control message as one exact 1,052-byte W1 record, reconstruct and pad every outgoing body, and use fresh adjacent-link encryption;
  \item enforce finite per-peer, node-global, time, byte, state, queue, and cryptographic-work limits;
  \item treat state lifetimes as half-open intervals and follow E1 equal-time precedence;
  \item create tentative state on \textsc{Candidate}, reserve pending state on \textsc{Commit}, and authorize data only after final \textsc{Ready};
  \item reclaim all setup state by local expiry without remote cooperation;
  \item make batch-local unlinkability claims only for a declared fixed-size mixing profile;
  \item refrain from active-adversary, traffic-flow, post-quantum, or production-security claims until separately reviewed and tested;
  \item expose no detailed error behavior that distinguishes tagged eligibility failure from other invalid cryptographic input.
\end{enumerate}

\section{Canonical integer and length encoding note}

W1 fixes the public outer record length and uses fixed-width unsigned big-endian integers in the link header. Encrypted nested lengths use their specified fixed-width fields and must be minimally consistent with the containing message: no trailing protected bytes, no length beyond the W1 capacity, and no alternative representation of the same value. Variable-length integers may be introduced only inside a future encrypted profile with a one-to-one canonical encoding and explicit parser bounds. They must not alter the public W1 record length.

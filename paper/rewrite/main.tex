\begin{statusbox}
\textbf{Document status.} This document specifies the current research draft of the \ProtoName{} protocol. It defines bounded route discovery, deterministic route-state activation, a receiver-anonymous rerandomizable RCCA security contract for destination eligibility, canonical suite-agile logical messages, and fixed-size authenticated adjacent-link cells with bounded reassembly. The eligibility contract is integrated through an executable ideal functionality. A separate $k=2$ transcription audits the concrete construction of Wang et al.~\cite{anonrcca2021}. The audit proves that the construction's literal finite-field map $\mu(u)=u\bmod q$ is not multiplicative under ordinary quadratic-residue-group multiplication; concrete rerandomization is therefore disabled. The protocol is not suitable for production deployment, and no concrete active-adversary unlinkability claim is made.
\end{statusbox}

\begin{abstract}
Route discovery can disclose endpoint relationships, local topology, and stable correlation handles before an anonymous data path is established. \ProtoName{} is a privacy-enabled control-plane protocol that discovers an eligible responder within a bounded graph radius and installs hop-local bidirectional forwarding state without transmitting a complete route or a network-wide discovery identifier.

The protocol binds five profiles. \Uone{} requires every forwarded branch to replace its adjacent capability, additively tweak its reply key, rerandomize its destination-eligibility capsule, reconstruct the logical message, and cross a declared mixing boundary. \Eone{} defines half-open deadlines, equal-time event precedence, candidate windows, delayed responses, cancellation races, tentative state, forward \textsc{Commit}, reverse \textsc{Ready}, and deterministic cleanup. \Ctwo{} specifies the destination-eligibility algorithms \textsf{KeyGen}, \textsf{Enc}, \textsf{ReRand}, and \textsf{Dec}, together with receiver anonymity, replayable chosen-ciphertext security, replay equivalence, and an explicit cross-hop tagging game. The currently executable reply-key, candidate-encryption, transcript, signature, KDF, and AEAD components are retained from \Cone{}. \Mtwo{} defines one canonical suite-agile variable-length representation for each logical control message without semantic padding. \Wtwo{} fragments an M2 message into one or more fixed 1,052-byte adjacent-link cells, authenticates every cell independently, binds the cryptographic suite during reassembly, and enforces explicit byte, fragment, concurrency, and time limits.

This separation avoids treating a fixed transmission unit as the logical message format. A short control message usually occupies one cell, whereas a deeply nested candidate may occupy several. Individual cell length no longer reveals message type or exact logical length, but cell count and timing remain observable unless a separate scheduling profile conceals them. The integrated reference model executes cryptography, canonical encoding, fragmentation, reassembly, and route-state transitions in one event lifecycle. It demonstrates clean multi-cell route activation, bounded cleanup after fragment loss, and rejection of malformed or unauthenticated cells before route-state allocation.

The analysis retains the C1 eligibility capsule as a negative control. Its persistent algebraic ratio tag survives an honest rerandomizing relay and is recognizable by a separated colluder. In the symbolic C2 experiment, an arbitrary mutation is rejected by the first honest transformation and no transformed capsule reaches that colluder. The concrete audit fixes $k=2$, related quadratic-residue groups, a canonical 412-byte ciphertext, and deterministic vectors from the source equations~\cite{anonrcca2021}; key generation, encryption, decryption, mutation rejection, and the linear strand equations execute successfully. The source also explains the inner tag by the integer reduction $u\bmod q$ and states that this operation supplies the required homomorphism~\cite{anonrcca2021}. An exact counterexample disproves that literal multiplicative claim, so the implementation fails closed. These results validate protocol composition and isolate a concrete algebraic blocker; they do not establish the security of a deployable cryptosystem or refute the paper's generic framework. The paper therefore presents a falsifiable research baseline rather than a security proof or production benchmark.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

\subsection{Motivation}

Anonymous communication is commonly described in terms of a protected data path. Before that path exists, however, a control plane must locate a destination or service, discover one or more usable routes, and install forwarding state. That preparatory process may disclose the same information that the eventual anonymity mechanism is intended to hide: which endpoint is sought, which relays are topologically close, which messages belong to one exploration, and which reverse response corresponds to which forward branch.

The problem is especially visible in decentralized and path-aware networks. A conventional routing protocol may distribute a global or regional topology view. A source-routing system may return a complete path to the sender. A directory may provide a stable lookup handle. Each design can be operationally sound while creating a durable correlation surface. \ProtoName{} investigates a different structure: relays maintain only adjacent capabilities, the initiator receives candidates rather than a topology map, and every branch representation is independently transformed at each forwarding hop.

Privacy cannot be inferred from encryption alone. A stable token inside an encrypted link becomes visible to a compromised relay; variable ciphertext length reveals the length of the padded plaintext; a multi-cell burst may reveal a candidate's approximate depth; a deterministic retry handle links expanding rings; a route may be activated before end-to-end confirmation; and a malleable ciphertext may permit active tagging even though every honest rerandomization changes its bytes. The protocol therefore treats privacy, lifecycle correctness, resource safety, logical encoding, cell framing, reassembly, scheduling, and active-adversary behavior as separate objects of specification and measurement.

\subsection{Contributions}

This paper makes the following contributions:

\begin{enumerate}
  \item It defines a bounded route-discovery control plane in which logical discoveries and expanding-ring policy remain local to the initiator, while relays see only peer-bound branch contexts.
  \item It separates seven properties that must not be conflated: per-cell length equality, passive wire-image unlinkability, conditional batch-local message unlinkability, lifecycle correctness, reassembly safety, active-adversary unlinkability, and traffic-flow unlinkability.
  \item It specifies the \Uone{} branch-local transformation: branch, candidate, cancellation, and route capabilities are replaced at every hop; reply keys are tweaked; eligibility capsules are rerandomized; and outgoing logical messages are reconstructed.
  \item It specifies the \Eone{} event lifecycle, including half-open deadlines, deterministic equal-time precedence, delayed candidates, cancellation races, tentative mappings, \textsc{Commit}, \textsc{Ready}, and cleanup after loss.
  \item It defines the \Ctwo{} active-security contract for eligibility, including receiver anonymity, rerandomizable RCCA behavior, replay equivalence, cross-hop tag resistance, composition, and generic failure behavior.
  \item It retains \Cone{} as an executable negative-control eligibility construction and as the concrete component set for reply-key tweaking, nested candidates, responder signatures, transcripts, KDF, and AEAD.
  \item It defines \Mtwo{} as a canonical variable-length logical-message codec and \Wtwo{} as a fixed-size encrypted-cell profile with deterministic fragmentation and bounded out-of-order reassembly.
  \item It formalizes the boundary between per-cell length equality and message-size leakage: a message of length $L$ occupies $\lceil L/992\rceil$ W2 cells unless a scheduling profile pads or obscures that count.
  \item It integrates \Uone{}, \Eone{}, \Ctwo{}, \Mtwo{}, and \Wtwo{} in one deterministic event model while preserving the executable C1 reply and authentication components.
  \item It gives both an executable C1 ratio-tag counterexample and a symbolic C2 rejection experiment, then transcribes the selected $k=2$ construction into canonical bytes and records the exact related-group operation that still requires independent interoperability review.
\end{enumerate}

It does not define global name resolution, inter-domain routing policy, application-data congestion control, economic incentives, a new physical or link layer, or a replacement for IP.
\end{claimbox}

\section{Related work and cryptographic context}
\label{sec:background}

\subsection{Network-layer anonymity and mix packets}

HORNET demonstrates high-speed anonymous forwarding with symmetric cryptography on the data-plane fast path and no per-flow forwarding state in intermediate routers~\cite{hornet}. TARANET adds setup mixing and coordinated constant-rate transmission to resist traffic analysis at the network layer~\cite{taranet}. Sphinx provides a compact mix packet format with per-hop transformation, path-length hiding, reply support, and formal security goals~\cite{sphinx}. Loopix combines Sphinx packets with stochastic mixing and cover traffic~\cite{loopix}.

These systems begin with a route or layered packet structure already selected by the sender or supplied by another mechanism. \ProtoName{} addresses a prior problem: the sender initially knows the endpoint descriptor but not the path. The protocol must explore a branching graph while avoiding a stable cross-hop identifier. Consequently, techniques designed for a single precomputed onion cannot be copied without modification.

\subsection{Universal re-encryption and active security}

Universal re-encryption (URE) augments public-key encryption with a transformation that does not require the recipient public key and preserves the encrypted plaintext. Golle, Jakobsson, Juels, and Syverson introduced this mechanism for mixnets by adding an auxiliary encryption of the identity to an ElGamal-style ciphertext~\cite{gjjs}. This property is relevant to \ProtoName{} because forwarding the destination public key beside every discovery branch would create a stable recipient selector.

Rerandomization correctness alone is not an adequate anonymity definition. Banfi, Maurer, and Ritsch distinguish the minimal secrecy and unlinkability properties of URE and formulate a composable application-level notion for mixnet use~\cite{ure2023}. Their analysis reinforces the protocol distinction between byte-changing rerandomization, recipient anonymity, and resistance to active relations that survive an honest transform.

Replayable chosen-ciphertext security (RCCA) was introduced by Canetti, Krawczyk, and Nielsen as a relaxation of CCA security that permits transformations yielding the same plaintext while retaining chosen-ciphertext protection against other modifications~\cite{rcca2003}. Key privacy, introduced for public-key encryption by Bellare et al., asks that a ciphertext not reveal which admissible public key was used~\cite{keyprivacy2001}. Prabhakaran and Rosulek combined perfect rerandomization with RCCA security and formulated the stronger receiver-anonymity objective, but their concrete scheme did not realize that objective~\cite{rcca2007}.

Wang et al. subsequently constructed the first receiver-anonymous rerandomizable RCCA-secure public-key encryption framework. Their construction extends the smooth projective hash-function paradigm of Cramer and Shoup~\cite{sphf2002} with rerandomizable tag-SPHFs and supplies a concrete $k$-linear instantiation~\cite{anonrcca2021}. \Ctwo{} adopts that combined security contract as the eligibility target. The protocol also uses the paper's concrete construction as the subject of the byte-level audit in \cref{sec:c2audit}; the audit is not treated as a proof or as deployment approval.

\subsection{HPKE and the custom reply KEM}

HPKE standardizes hybrid public-key encryption from a KEM, KDF, and AEAD and gives precise context binding and test vectors~\cite{hpke}. The C1 reply construction follows that discipline but requires a public key that can be additively tweaked at each hop and whose corresponding secret can later be reconstructed by the initiator. RFC~9180 does not register a \code{ristretto255} KEM with this property. C1 therefore defines an HPKE-inspired custom KEM and explicitly refrains from claiming RFC~9180 interoperability.

\section{System model, adversary, and claims}
\label{sec:model}

\subsection{Network model}

Let the communication substrate be an undirected graph
\begin{equation}
G=(V,E),
\label{eq:graph}
\end{equation}
where a node $n\in V$ may act as initiator, relay, responder, or any combination of these roles. An edge $(u,v)\in E$ denotes an authenticated adjacent-link association. A route of length $d$ is a sequence
\begin{equation}
\rho=(n_0,n_1,\ldots,n_d), \qquad (n_i,n_{i+1})\in E.
\label{eq:route}
\end{equation}
The initiator is $n_0$ and the responder is $n_d$. The protocol never transmits $\rho$ as one object.

The adjacent-link transport supplies peer authentication, confidentiality and integrity, exact cell-record boundaries, a directional link epoch, a monotonically managed sequence, and notification of connection failure. W2 fixes the complete cell-record length while M2 remains a variable-length logical representation. A separate scheduling profile defines cell batching, fragment interleaving, release delay, cell-count padding, and cover traffic. Adjacent-link protection prevents an external observer from reading or modifying an honest-to-honest edge; it does not make a compromised relay honest or constrain the content of new cells emitted by that relay.

\subsection{Adversary}

The adversary may:

\begin{itemize}
  \item observe links not protected by the stated underlay profile;
  \item compromise a bounded set of nodes and inspect their keys, state, queues, and local timing;
  \item inject, drop, delay, duplicate, reorder, redirect, or modify records at compromised nodes;
  \item generate fresh syntactically valid branches rather than only replaying old records;
  \item coordinate observations from multiple compromised relays;
  \item attempt resource exhaustion, candidate spam, and active ciphertext tagging.
\end{itemize}

The adversary cannot break the cryptographic assumptions explicitly assigned to a concrete profile, forge uncompromised adjacent-link authentication, or read an honest-to-honest protected link. The symbolic C2 functionality is an idealized test oracle and is not included among such assumptions. Traffic-flow claims require a separate observation and scheduling profile; neither C2 nor W2 alone conceals timing.

\subsection{Separated properties}

\begin{definition}[Per-cell length equality]
Every W2 adjacent-link cell has the same complete length, independently of logical message type, candidate depth, fragment position, protected-body length, or chaff status.
\end{definition}

\begin{definition}[Canonical logical-message representation]
For every accepted semantic control message and selected cryptographic suite, M2 admits exactly one byte representation. Length integers are minimal, the suite and capsule length are explicit, fragmentation metadata is absent from the logical message, and no trailing bytes or semantic padding are permitted.
\end{definition}

\begin{definition}[Passive wire-image unlinkability]
For passively observed messages processed by at least one honest relay, protocol fields exposed after adjacent-link decryption do not provide a deterministic equality test linking an incoming representation to a non-adjacent outgoing representation.
\end{definition}

\begin{definition}[Batch-local message unlinkability]
After an honest per-hop cryptographic transformation and a mixing boundary containing $k\ge2$ cells with the same observable treatment, a passive observer cannot match a designated input logical message to its output with advantage exceeding the relevant cryptographic advantage and information exposed by cell count and scheduling.
\end{definition}

\begin{definition}[Lifecycle correctness]
Every accepted control event produces one deterministic state transition or rejection, every state has a finite local deadline, and loss of any cleanup message cannot create permanent state.
\end{definition}

\begin{definition}[Reassembly safety]
An adversarial stream of authenticated or unauthenticated fragments cannot make a node allocate route-semantic state before complete canonical M2 decoding and M2/W2 suite agreement, and incomplete-message memory is bounded by explicit context, byte, fragment, and time limits.
\end{definition}

\begin{definition}[Active-adversary unlinkability]
Compromised relays cannot install a persistent recognizable relation, selective-failure marker, or other active tag that links non-adjacent representations of one branch with non-negligible advantage.
\end{definition}

\begin{definition}[Traffic-flow unlinkability]
An observer cannot reliably correlate communication endpoints using timing, direction, volume, cell count, fragment bursts, queue behavior, topology, retries, or long-lived observation.
\end{definition}

\subsection{Local state versus wire state}

The initiator maintains a \emph{logical discovery}: application request, destination descriptor, ring schedule, cumulative budget, candidate set, and selection deadline. None of its identity fields appears on the wire. The only relay-visible discovery object is a \emph{branch context}, bound to one ingress peer, one branch token, one link epoch, one incoming reply public key, one suite-selected eligibility capsule, a finite expiry, and bounded child mappings.

This distinction permits retries without a network-wide attempt identifier. It also creates a cost: a relay cannot collapse two converging branches merely because they belong to the same logical discovery. That loss of global duplicate suppression is deliberate and is bounded by explicit quotas.

\subsection{One branch in plain language}

For one outgoing branch, the initiator generates a random link-local token, an ephemeral reply key, and an eligibility capsule under the selected suite. A relay admits the branch only after complete W2 reassembly, canonical M2 decoding, and suite agreement. For each selected child it generates a new token, adds a random scalar multiple of the group generator to the reply key, applies the suite's public rerandomization algorithm, reconstructs the M2 message, assigns a new link-local W2 message identifier, fragments the message canonically, and sends freshly padded adjacent-link cells. The child cannot compare a stable token, reply key, destination ciphertext, message identifier, or received padding with the parent's input.

An eligible endpoint decrypts the capsule to a fixed marker using the suite's secret key. It signs a candidate transcript and encrypts the candidate to the final reply key. On the reverse path each relay encrypts its stored key tweak and the child capsule to the prior reply key. The initiator opens one layer, learns the tweak, derives the next secret key, and repeats until it verifies the responder.

\subsection{Canonical encodings and domain separation}

Every C1 group element has the canonical 32-byte encoding defined by RFC~9496. Scalars are canonical 32-byte little-endian integers less than $q$; zero is rejected where a secret, tweak, or ephemeral scalar is required. Public keys and KEM encapsulations reject the identity element.

Let \code{LP16(x)} be a two-byte unsigned big-endian length followed by $x$. C1 defines
\begin{equation}
\operatorname{EF}(\ell;x_1,\ldots,x_m)
 = \code{``Trahens-C1-v1''}\concat \operatorname{LP16}(\ell)
   \concat \operatorname{LP16}(x_1)\concat\cdots\concat\operatorname{LP16}(x_m).
\label{eq:encodefields}
\end{equation}
All KDF and transcript labels use \cref{eq:encodefields}. Implicit concatenation, JSON serialization, locale-dependent text, and alternate integer encodings are non-conforming.

\subsection{Endpoint descriptor and address}

An endpoint has independent eligibility and signing key pairs:
\begin{equation}
(sk_D,pk_D)\sample\mathsf{C2.KeyGen}(1^\lambda),
\qquad (sk_S,vk_S)\sample\mathsf{Ed25519.KeyGen}().
\end{equation}
The canonical descriptor is suite-specific and has the generic form
\begin{equation}
D=\code{version}_{1}\concat\code{suite}_{2}\concat
  \operatorname{LP16}(\Encode(pk_D))\concat\operatorname{LP16}(vk_S),
\label{eq:descriptor}
\end{equation}
and its address is
\begin{equation}
\mathsf{addr}=\operatorname{SHA256}(\operatorname{EF}(\code{endpoint-address};D)).
\label{eq:address}
\end{equation}
A discovery initiator needs the descriptor, not merely the address hash, because it must encrypt the eligibility marker to $pk_D$ and later verify signatures under $vk_S$. Any directory supplying $D$ must authenticate the binding in \cref{eq:address}. The public key $pk_D$ is used only at initiation; it is not copied into \textsc{Discover}.

\subsection{C2 eligibility syntax and security contract}
\label{sec:c2}

Following the receiver-anonymous rerandomizable RCCA syntax of Wang et al.~\cite{anonrcca2021}, C2 defines four algorithms:
\begin{align}
\mathsf{KeyGen}(1^\lambda)&\rightarrow(pk,sk),\\
\mathsf{Enc}(pk,m;r)&\rightarrow Q,\\
\mathsf{ReRand}(Q;\rho)&\rightarrow Q',\\
\mathsf{Dec}(sk,Q)&\rightarrow m\mid\mathsf{replay}\mid\bot.
\end{align}
The only eligibility plaintext is a fixed domain-separated marker $m_\star$. A destination is eligible exactly when decryption returns $m_\star$. The rerandomization algorithm receives neither $pk$ nor $sk$. For an honestly generated $Q$, every honest rerandomization decrypts to the same marker and belongs to the scheme-defined replay-equivalence class.

\begin{definition}[Receiver anonymity]
Given two admissible public keys and one equal-length marker, an adaptive adversary with the decryption access permitted by the selected RCCA definition cannot determine which key was used with non-negligible advantage. This extends the key-privacy objective of Bellare et al.~\cite{keyprivacy2001} to the RCCA setting formalized by Canetti et al.~\cite{rcca2003} and used by the selected construction~\cite{anonrcca2021}.
\end{definition}

\begin{definition}[Protocol tag resistance]
Let two compromised relays be separated by at least one honest transforming relay. After the upstream relay replaces a valid capsule by arbitrary same-profile bytes, the honest relay either rejects or emits a canonical rerandomization. Conditioned on emission, the downstream relay cannot identify the upstream branch from capsule contents with non-negligible advantage beyond replay-equivalence information allowed by the construction.
\end{definition}

C2 also requires that no stable recipient selector, ciphertext digest, proof identifier, or rerandomization counter be placed beside the capsule. Detailed failures are local only. A malformed input, wrong recipient, invalid proof, non-replay-equivalent mutation, and marker mismatch all use the same externally visible rejection behavior.

\subsection{Executable C2 ideal functionality}

The reference model represents a valid C2 capsule by an opaque 640-byte string stored in a process-local semantic registry. \textsf{ReRand} returns a fresh independently distributed string associated with the same hidden recipient, marker, and replay-equivalence class. Arbitrary byte mutation is absent from the registry and is rejected before an honest relay emits a child branch. The 640-byte length is a planning budget, not a canonical encoding of the selected construction.

This ideal functionality tests suite agility, state-machine composition, generic failure, and the active-tag game. It cannot test group or ring encodings, proof verification, concrete receiver anonymity, hardness assumptions, side channels, or real computational cost. A conforming implementation must replace it with exact algorithms, canonical encodings, deterministic vectors, negative tests, and an independently reviewed security mapping.

\subsection{Concrete \texorpdfstring{$k=2$}{k=2} transcription and finite-field audit}
\label{sec:c2audit}

The concrete audit targets the $k$-linear public-key encryption construction given in Section~6.3 and Figure~6 of Wang et al.~\cite{anonrcca2021}. The source construction combines two outer strands carrying the eligibility plaintext with an inner malleable encryption of a random mask. Its security analysis uses rerandomizable tag-SPHFs; the smoothness results needed by the instantiation require $k\geq2$~\cite{anonrcca2021}. The audit therefore selects the smallest admissible value,
\begin{equation}
k=2.
\end{equation}

The source proposes two related quadratic-residue groups obtained from a Cunningham chain of the first kind of length three~\cite{anonrcca2021}. For the deterministic audit, let
\begin{equation}
\begin{aligned}
q &= 175513086009046434629810696245711941989,\\
p &= 2q+1,\\
r &= 2p+1=4q+3,
\end{aligned}
\label{eq:c2chain}
\end{equation}
where $q,p,r$ are prime. Define the inner group $\overline{\Group}=\operatorname{QR}^{*}_{p}$ of order $q$ and the outer group $\Group=\operatorname{QR}^{*}_{r}$ of order $p$. The chain in \cref{eq:c2chain} is a fast conformance parameter set only; it is not proposed as a production security parameter.

The finite-field explanation in the source uses the integer representative of an inner-group element as an exponent modulo $q$. In particular, it identifies the relevant exponent with $u\bmod q$ and states that modular reduction supplies the homomorphism required by rerandomization~\cite{anonrcca2021}. The literal map under audit is therefore
\begin{equation}
\mu:\operatorname{QR}^{*}_{p}\longrightarrow \mathbb{Z}_{q},
\qquad \mu(u)=u\bmod q.
\label{eq:tagmap}
\end{equation}
For a rerandomization multiplier $v\in\operatorname{QR}^{*}_{p}$, the source-shaped inner proof update requires the multiplicative compatibility condition
\begin{equation}
\mu(vu\bmod p)=\mu(v)\mu(u)\bmod q.
\label{eq:taghom}
\end{equation}

\begin{proposition}[The literal reduction is not multiplicative]
The map in \cref{eq:tagmap} is not, in general, a multiplicative group homomorphism from $\operatorname{QR}^{*}_{p}$ to $\mathbb{Z}_{q}$ when $p=2q+1$ and group multiplication is taken modulo $p$.
\end{proposition}

\begin{proof}
Take $q=5$ and $p=11$. Both $3$ and $4$ are elements of $\operatorname{QR}^{*}_{11}$. Their group product is $3\cdot4\bmod11=1$, hence $\mu(3\cdot4\bmod11)=1$. By contrast, $\mu(3)\mu(4)\bmod5=3\cdot4\bmod5=2$. Thus \cref{eq:taghom} fails. The same failure occurs for the deterministic conformance parameters and is recorded with the exact operands in the machine-readable audit report.
\end{proof}

This proposition is deliberately narrow. It blocks the literal finite-field action described above and explains the failed full-rerandomization test. It does not invalidate the generic rerandomizable tag-SPHF framework, an author-confirmed corrected action, or a different instantiation of that framework~\cite{anonrcca2021}.

For $k=2$, each language vector contains three group elements. The transcription maps Figure~6 to four strands: two outer strands $(x_1,e_1,\pi^b_1)$ and $(x_2,\pi_2,\pi^e_2)$, and two inner strands $(x_3,e_3,\pi^b_3)$ and $(x_4,\pi_4,\pi^e_4)$. The complete ciphertext contains the components summarized in \cref{tab:c2auditshape}.

\subsection{C1 negative-control eligibility capsule}
\label{sec:ure}

C1 represents eligibility by one fixed group element $M_\star$, derived from a domain-separated 64-byte hash using the RFC~9496 element-derivation interface. Its two-pair construction follows the universal re-encryption pattern of Golle et al.~\cite{gjjs}. It remains implemented because its equations are useful as a passive-rerandomization baseline and because its active ratio tag is a mandatory negative test. It is not the active-security eligibility profile.

\subsubsection{Encryption}

For public key $A=aB$, sample $r_0,r_1\sample\Zq^*$ and compute
\begin{equation}
\begin{aligned}
U_0 &= M_\star+r_0A, & V_0 &= r_0B,\\
U_1 &= r_1A,         & V_1 &= r_1B.
\end{aligned}
\label{eq:ureenc}
\end{equation}
The capsule is
\begin{equation}
Q=((U_0,V_0),(U_1,V_1)),
\end{equation}
encoded as four consecutive 32-byte group elements. It is therefore exactly 128 bytes.

\subsubsection{Public-key-free rerandomization}

A relay samples $s_0\sample\Zq^*$ and $s_1\sample(\Zq^*\setminus\{1\})$, then computes
\begin{equation}
\begin{aligned}
U'_0 &= U_0+s_0U_1, & V'_0 &= V_0+s_0V_1,\\
U'_1 &= s_1U_1,     & V'_1 &= s_1V_1.
\end{aligned}
\label{eq:urerand}
\end{equation}
The relay does not need $A$. For a valid input, the effective randomness becomes $r'_0=r_0+s_0r_1$ and $r'_1=s_1r_1$. The restrictions $s_0\ne0$ and $s_1\ne1$ ensure that all four point encodings change; an implementation rejects an unchanged result.

\begin{proposition}[URE correctness]
For every valid C1 capsule $Q$ encrypted under $A=aB$, decryption of any rerandomization $Q'$ produced by \cref{eq:urerand} yields the same marker $M_\star$ and passes the consistency check.
\end{proposition}

\begin{proof}
Using $U'_1=s_1r_1A$ and $V'_1=s_1r_1B$,
$U'_1-aV'_1=s_1r_1(aB)-a(s_1r_1B)=\Identity$.
Similarly,
$U'_0-aV'_0=M_\star+(r_0+s_0r_1)A-a(r_0+s_0r_1)B=M_\star$.
\end{proof}

\subsubsection{Decryption}

The endpoint computes
\begin{equation}
T=U_1-aV_1
\end{equation}
and rejects unless $T=\Identity$. It then computes $M=U_0-aV_0$ and declares itself eligible only if $M=M_\star$. Invalid encodings, consistency failure, marker mismatch, and wrong-key failure all map to the same local result.

\begin{algorithm}[ht]
\caption{C1 eligibility processing at a potential responder}
\label{alg:eligibility}
\begin{algorithmic}[1]
\Require eligibility secret $a$, encoded capsule $Q$
\If{any of the four group elements fails canonical decoding}
  \State \Return \textsc{Invalid-Crypto}
\EndIf
\State $T\gets U_1-aV_1$
\If{$T\ne\Identity$}
  \State \Return \textsc{Not-Eligible}
\EndIf
\State $M\gets U_0-aV_0$
\If{$M\ne M_\star$}
  \State \Return \textsc{Not-Eligible}
\EndIf
\State \Return \textsc{Eligible}
\end{algorithmic}
\end{algorithm}

\subsection{Reply-key tweaking}
\label{sec:tweak}

For every first-hop branch, the initiator samples $x_0\sample\Zq^*$ and publishes $X_0=x_0B$. A relay forwarding to a child samples $\delta_i\sample\Zq^*$ and computes
\begin{equation}
X_{i+1}=X_i+\delta_iB.
\label{eq:tweakpublic}
\end{equation}
The relay stores $\delta_i$ only in the corresponding child context. It resamples if the result is the identity. The initiator later computes
\begin{equation}
x_{i+1}=x_i+\delta_i\pmod q.
\label{eq:tweaksecret}
\end{equation}

\begin{proposition}[Tweak consistency]
The secret update in \cref{eq:tweaksecret} corresponds to the public update in \cref{eq:tweakpublic}.
\end{proposition}
\begin{proof}
$(x_i+\delta_i)B=x_iB+\delta_iB=X_i+\delta_iB=X_{i+1}$.
\end{proof}

\subsection{TR-KEM-R255 and reply encryption}
\label{sec:replykem}

To encrypt to $X=xB$, the sender samples $e\sample\Zq^*$ and computes
\begin{equation}
R=eB, \qquad Z=eX.
\label{eq:kemdh}
\end{equation}
The receiver computes the same $Z=xR$. The KEM context binds the suite, encapsulated element, recipient public key, and a caller-provided \code{info} value:
\begin{align}
\mathsf{ctx} &= \operatorname{EF}(\code{reply-kem-context};\code{suite},\bytes R,\bytes X,\mathsf{info}),\\
\mathsf{prk} &= \operatorname{HKDFExtract}(0^{32},\operatorname{EF}(\code{reply-kem-dh};\bytes Z)),\\
\mathsf{ss} &= \operatorname{HKDFExpand}(\mathsf{prk},\operatorname{EF}(\code{reply-kem-secret};\mathsf{ctx}),32).
\end{align}
The AEAD key and nonce are independently labeled HKDF expansions of $\mathsf{ss}$ and $\mathsf{ctx}$. The output is $\bytes R$ followed by a ChaCha20-Poly1305 ciphertext with the complete 16-byte tag.

The nonce is deterministic under the encapsulation-derived secret. This is safe only if $e$ is fresh. Reusing $e$ for the same recipient and \code{info} repeats both key and nonce and is prohibited. Deterministic ephemerals appear only in published test vectors.

\subsection{Responder authentication and transcript binding}

The responder signs
\begin{equation}
\mathsf{CandidateTH}=
\operatorname{SHA256}(\operatorname{EF}(\code{candidate-transcript};\mathcal F)),
\label{eq:candidateth}
\end{equation}
where the ordered field list $\mathcal F$ includes protocol and profile versions, endpoint address and descriptor, final reply public key, offer class, route limits, offer expiry, commit challenge, and responder nonce. The Ed25519 key must equal $vk_S$ in the descriptor, and the descriptor must hash to the requested endpoint address.

The response includes a random commit challenge. Later, \textsc{Commit} and \textsc{Ready} carry end-to-end HMAC proofs over domain-separated transcript hashes. Relays treat those protected bodies as opaque and route them using local labels.

\subsection{Failure normalization}

The protocol exposes one state-machine outcome, \textsc{Invalid-Crypto}, for C2 decryption or proof failure, recipient mismatch, non-replay-equivalent mutation, invalid C1 points, identity public keys, non-canonical scalars, negative-control URE failure, AEAD failure, AAD or \code{info} mismatch, invalid signatures, and transcript mismatch. The detailed reason may be logged locally but is never sent as a differentiated response. Cell length and rate checks precede adjacent-link authentication. A receiver may perform a non-mutating replay-window precheck from the public link header, but it commits replay state only after authentication; an unauthenticated record cannot reserve a sequence number. Authenticated replay rejection, W2 fragmentation checks, M2 syntax and suite agreement, and capacity admission all precede expensive route cryptography.

This rule limits explicit oracles; it does not prove constant-time behavior. Production code would require side-channel review, constant-time group and comparison operations, memory-clearing policy, and a uniform scheduling analysis.

\section{Forward discovery}
\label{sec:forward}

\subsection{Initiator behavior}

A logical discovery selects a local expanding-ring policy
\begin{equation}
\mathcal R_r=(d_r,f_r^{(0)},f_r,\Delta_r),
\end{equation}
where $d_r$ is the hop limit, $f_r^{(0)}$ the first-hop fan-out, $f_r$ the relay fan-out, and $\Delta_r$ the local candidate window. Neither $r$ nor the tuple is transmitted directly; only bounded propagation and fan-out classes required by the relay appear in the branch record.

For every first-hop peer, the initiator creates independent state. It does not reuse a branch token, root reply key, eligibility encryption randomness, padding, M2 message identifier, or adjacent-link ciphertext.

\begin{algorithm}[ht]
\caption{Initiator: create one suite-bound DISCOVER branch}
\label{alg:init}
\begin{algorithmic}[1]
\Require first-hop peer $n_1$, destination descriptor $D$, local budget $\mathcal B$
\If{$\mathcal B$ cannot reserve one branch and the required cell transmissions}
  \State \Return failure
\EndIf
\State parse and validate $(\sigma,pk_D,vk_S)$ from $D$; verify the requested address
\State $x_0\sample\Zq^*$; $X_0\gets x_0B$
\State $\tau_0\sample\{0,1\}^{128}$
\State $Q_0\gets\mathsf{C2.Enc}(pk_D,m_\star)$
\State $M_0\gets\Encode_{\mathsf{M2}}(\sigma,\textsc{Discover},\tau_0,X_0,Q_0,\mathsf{bounds},\mathsf{expiry})$
\State fragment $M_0$ canonically into W2 cells with fresh local identifier and padding
\State store $(n_1,\tau_0,x_0,\mathsf{expiry})$ in initiator-local branch state
\State enqueue fresh adjacent-link encryption of every W2 cell
\end{algorithmic}
\end{algorithm}

\subsection{Relay validation order}

The relay processes cheap and local checks before expensive group operations:

\begin{enumerate}
  \item record-class length, byte rate, and adjacent-link replay;
  \item adjacent-link authentication and protocol/profile identifiers;
  \item canonical framing, lifetime class, and branch-token replay;
  \item ingress-peer token bucket and node-global work budget;
  \item provisional state reservation;
  \item M2/W2 suite agreement, suite-selected eligibility validation and rerandomization, and reply-key processing;
  \item full state allocation and bounded outgoing work.
\end{enumerate}

A failure at one stage does not consume resources reserved for a later stage. W2 reassembly state is accounted separately and does not imply route-semantic admission. No invalid branch generates an amplified error response.

\subsection{Per-child transformation}

For each selected child, the relay performs all transformations independently. Reusing one tweak or rerandomization across several children would allow sibling equality tests and is prohibited.

\begin{algorithm}[ht]
\caption{Relay: transform one admitted DISCOVER branch}
\label{alg:relay}
\begin{algorithmic}[1]
\Require ingress peer $p$, token $\tau_i$, key $X_i$, capsule $Q_i$, bounds
\State allocate branch context $b\gets\BranchT[p,\tau_i]$
\State $S\gets\mathsf{SelectChildren}(N(n_i)\setminus\{p\},f)$
\ForAll{$c\in S$}
  \State $\tau_c\sample\{0,1\}^{128}$
  \Repeat
    \State $\delta_c\sample\Zq^*$; $X_c\gets X_i+\delta_cB$
  \Until{$X_c\ne\Identity$}
  \State $\rho_c\sample\mathsf{Coins}_{\sigma}$
  \State $Q_c\gets\mathsf{ReRand}_{\sigma}(Q_i;\rho_c)$
  \State store $(c,\tau_c,\delta_c,X_c)$ in $b$
  \State reconstruct one canonical M2 message and assign a fresh W2 local identifier
  \State fragment canonically, generate fresh cell padding, and enqueue fresh adjacent-link ciphertexts
\EndFor
\end{algorithmic}
\end{algorithm}

\subsection{Loops and converging branches}

Immediate backtracking to the ingress peer is excluded. Exact duplicates on the same link epoch are rejected. A branch arriving over another peer or under another token is a different branch context, even if it belongs to the same initiator-local discovery. Longer cycles and converging branches therefore cause repeated state. The hop limit, fan-out, per-peer token bucket, per-node context ceiling, cumulative transmission budget, and expiry bound the amplification.

Attempt-wide first-parent suppression would reduce cost but requires an equality domain shared across hops. The current protocol chooses the privacy structure and measures the resulting cost rather than hiding it.

\section{Candidate return and route activation}
\label{sec:reverse}

\subsection{Responder candidate}

A node first evaluates the eligibility capsule using the M2-bound suite. If C2 decryption returns the fixed marker and the node is willing to respond, it constructs a candidate payload containing the endpoint descriptor, offer and limit classes, expiry, commit challenge, responder nonce, final reply key, and Ed25519 signature over \cref{eq:candidateth}. It encrypts the payload to $X_d$ using the retained \code{TR-KEM-R255} reply component.

The responder does not reveal its identity to intermediate relays. Those relays see only a fixed-class candidate record, local capabilities, and an opaque reverse capsule.

\subsection{Relay reverse layer}

Suppose relay $n_i$ previously transformed $X_i$ into $X_{i+1}=X_i+\delta_iB$ for the selected child. On receiving the child candidate capsule $C_{i+1}$, the relay creates a fresh parent candidate token $\gamma_i$ and forward label $\lambda_i^{\rightarrow}$, then computes
\begin{equation}
C_i=\Seal_{X_i}\left(
\Encode(\delta_i,C_{i+1},\lambda_i^{\rightarrow},\mathsf{limits},\mathsf{padding});
\mathsf{info}_i,\mathsf{aad}_i
\right).
\label{eq:reversewrap}
\end{equation}
The \code{info} and AAD bind the protocol version, suite, depth class, parent token, parent label, record class, link epoch, and offer expiry. A mutation of those fields causes AEAD failure.

The relay stores a tentative mapping from the parent-facing candidate capability and forward label to the child branch. It does not learn the responder payload or the contents of $C_{i+1}$.

\subsection{Initiator opening procedure}

The initiator begins with $x_0$. After opening $C_0$, it obtains $\delta_0$ and $C_1$, computes $x_1=x_0+\delta_0\bmod q$, and continues. At the innermost layer it verifies the endpoint descriptor, address, Ed25519 signature, final reply key, responder nonce, offer limits, and expiry.

\begin{algorithm}[ht]
\caption{Initiator: open the C1 candidate chain}
\label{alg:open}
\begin{algorithmic}[1]
\Require root secret $x_0$, outer capsule $C_0$, maximum depth $d_{\max}$
\State $i\gets0$
\While{$i\le d_{\max}$}
  \State $Y\gets\Open_{x_i}(C_i;\mathsf{info}_i,\mathsf{aad}_i)$
  \If{$Y$ is a responder candidate}
    \State verify descriptor, address, signature, final $X_i$, nonce, limits, and expiry
    \State \Return authenticated candidate
  \ElsIf{$Y=\Encode(\delta_i,C_{i+1},\Lambda_i)$}
    \State validate canonical non-zero $\delta_i$ and local transcript context
    \State $x_{i+1}\gets x_i+\delta_i\pmod q$
    \State $i\gets i+1$
  \Else
    \State \Return \textsc{Invalid-Crypto}
  \EndIf
\EndWhile
\State \Return \textsc{Invalid-Crypto}
\end{algorithmic}
\end{algorithm}

\subsection{Worked three-hop example}
\label{sec:workedexample}

Consider $n_0\rightarrow n_1\rightarrow n_2\rightarrow n_3$, where $n_3$ is the responder. The initiator creates $(x_0,X_0)$. Relay $n_1$ chooses $\delta_0$ and sends $X_1=X_0+\delta_0B$. Relay $n_2$ chooses $\delta_1$ and sends $X_2=X_1+\delta_1B$. The responder encrypts its candidate to $X_2$.

On the reverse path, $n_2$ seals $(\delta_1,C_2)$ to $X_1$ and $n_1$ seals $(\delta_0,C_1)$ to $X_0$. The initiator opens $C_0$ with $x_0$, derives $x_1=x_0+\delta_0$, opens $C_1$, derives $x_2=x_1+\delta_1$, and finally opens the responder candidate. Neither relay learns $x_0$, any later secret, or the responder payload.

\subsection{Commit and readiness}

A candidate creates only tentative state. The initiator selects at most one candidate and sends \textsc{Commit} through its first-hop forward label. Each relay validates the peer, label, route generation, local transcript digest, and capacity class; reserves route capacity; changes the mapping to \textsc{Pending-Ready}; assigns a finite deadline; and forwards the opaque end-to-end commit body.

The responder verifies the commit HMAC derived from the challenge embedded in the signed candidate. It returns \textsc{Ready} through reverse labels. Relays change the matching pending mapping to \textsc{Active}. The initiator exposes the route to the data plane only after verifying the final ready proof. If either control message is lost, all partial state expires locally.

\section{Event lifecycle profile E1}
\label{sec:lifecycle}

\subsection{Half-open deadlines}

A local state created at $t_c$ with deadline $t_e$ is valid exactly on
\begin{equation}
[t_c,t_e)=\{t\mid t_c\le t<t_e\}.
\label{eq:halfopen}
\end{equation}
It is invalid at $t=t_e$ and cannot be revived. Received lifetime classes are converted to local deadlines; synchronized clocks are unnecessary. If a valid transition replaces a deadline, an old timer is associated with the previous state generation and cannot shorten the new state.

\subsection{Equal-time precedence}

Events assigned the same local timestamp follow the strict order
\begin{equation}
\mathsf{Expire}\prec\mathsf{Cancel}\prec\mathsf{RouteControl}
\prec\mathsf{Candidate}\prec\mathsf{Discover}\prec\mathsf{WindowClose}.
\label{eq:precedence}
\end{equation}
A message at its state deadline therefore fails, but a candidate at the exact window boundary remains eligible because candidate processing precedes window closure.

\subsection{Candidate windows and delayed responses}

A ring begins at local time $a_r$ and closes at $w_r=a_r+\Delta_r$. A candidate from any already-started ring is eligible at $w_r$ if no route has been selected, its signed offer has not expired, and every required tentative mapping survived the reverse traversal. Thus a delayed candidate from an earlier ring may win during a later ring without exposing a ring identifier on the wire.

Selection is immutable. After choosing one candidate, the initiator sends \textsc{Commit} on the selected path and sends transformed \textsc{Cancel} messages through stored adjacent mappings into maximal off-route subtrees that belong to its own discovery. Cancel is an optimization; expiry remains authoritative.

\section{Logical messages M2, wire cells W2, and relay state}
\label{sec:messages}

\subsection{Why the protocol separates messages from cells}

A cryptographic ciphertext normally reveals its complete byte length even when its contents are confidential. For an authenticated-encryption scheme with a fixed tag length $t$,
\begin{equation}
  |C|=|P_{\mathrm{padded}}|+t.
  \label{eq:cipher-length}
\end{equation}
Consequently, encrypting a variable-length message after adding a variable or random quantity of padding does not remove length leakage: the observer still learns the resulting padded length. Padding to one fixed maximum would hide length, but it would also make the logical-message grammar dependent on one transport allocation and would impose a hard maximum on nested candidates.

\ProtoName{} therefore uses two distinct encodings. M2 defines one canonical, variable-length byte string for each logical control message. M2 contains no semantic padding and no fragmentation metadata. W2 carries an M2 byte string in one or more equal-length adjacent-link cells. Fixed size belongs to the cell layer; logical structure belongs to the message layer.

\begin{property}[Layer separation]
Reassembly of a complete M2 message and verification of M2/W2 suite agreement precede message-type dispatch, suite-specific processing, and route-state allocation. A relay never cryptographically transforms a fragment in isolation and never forwards received fragment bytes or padding in place.
\end{property}

\subsection{W2 fixed-size adjacent-link cell}

W2 uses one complete adjacent-link record length. Let $H_C$ be the public link header, $P_C$ the encrypted cell plaintext, and $T_C$ the authentication tag:
\begin{equation}
  \underbrace{H_C}_{12}
  \concat
  \underbrace{\operatorname{AEAD.Enc}_{K_\ell}(H_C,P_C)}_{1024+16}
  \quad\Longrightarrow\quad
  L_C=1052\ \text{bytes}.
  \label{eq:w2-record}
\end{equation}
The public header is $H_C=e_\ell\concat s_\ell$, where the epoch is a four-byte unsigned integer and the sequence is an eight-byte unsigned integer, both in network byte order. The 12 bytes are used as nonce and associated data. A link key and nonce pair MUST NOT be reused.

The first 32 plaintext bytes form the W2 fragment header; the remaining 992 bytes are fragment data followed by fresh random padding.

\subsection{Canonical fragmentation}

Let $p=992$ be the fragment payload capacity. The only valid fragment count is
\begin{equation}
  q(M)=\left\lceil\frac{|M|}{p}\right\rceil,
  \qquad 1\le q(M)\le17.
  \label{eq:fragment-count}
\end{equation}
Every non-final fragment has length 992. The final fragment has length
\begin{equation}
  |M|-992\bigl(q(M)-1\bigr).
  \label{eq:final-fragment}
\end{equation}
A sender MUST NOT express the same M2 message as additional short fragments. The receiver rejects a noncanonical count or size even when concatenation could produce the declared bytes. This rule gives one W2 fragmentation representation for a given M2 message length.

A relay generates a new $\mu$ after reconstructing and transforming a logical message. The identifier is never copied across a hop and is never derived from a discovery, candidate, endpoint, route, or prior-hop field. Received padding is discarded; outgoing padding and link ciphertext are generated afresh for every cell.

\subsection{Bounded out-of-order reassembly}

A reassembly context is keyed by the authenticated directional link scope $\ell$ and local message identifier $\mu$. It stores the immutable suite identifier, total-length and fragment-count metadata, a fragment bitmap, received bytes, a creation time, a half-open expiry, and a reservation equal to the declared logical-message length.

\begin{algorithm}[ht]
\caption{W2 receive, reassembly, and M2 admission}
\label{alg:reassembly}
\begin{algorithmic}[1]
\Require adjacent-link record $c$, peer/link scope $\ell$, local time $t$
\If{$|c|\ne1052$} \State \Return \textsc{Drop} \EndIf
\State authenticate and decrypt $c$ under $\ell$
\State parse and validate the W2 header and canonical fragment tuple
\State expire contexts whose deadline is $\le t$
\State $k\gets(\ell,\mu)$
\If{$k$ is absent}
  \State reserve one context and \code{total\_message\_length} bytes
  \State create $R[k]$ with immutable metadata and finite deadline
\ElsIf{metadata conflicts with $R[k]$}
  \State delete $R[k]$, release all reservations, \Return \textsc{Drop}
\EndIf
\If{fragment index already contains identical bytes}
  \State \Return \textsc{Duplicate}
\ElsIf{fragment index already contains different bytes}
  \State delete $R[k]$, release all reservations, \Return \textsc{Drop}
\EndIf
\State store the fragment
\If{some canonical index is absent} \State \Return \textsc{Collecting} \EndIf
\State $M\gets$ concatenation of fragments in index order
\State delete $R[k]$ and release fragment reservations
\State decode exactly one canonical M2 message from $M$
\If{M2 decoding, M2/W2 suite agreement, or message-class admission fails} \State \Return \textsc{Drop} \EndIf
\State \Return the parsed message to its E1 and suite-specific state machine
\end{algorithmic}
\end{algorithm}

An exact duplicate fragment is idempotent and consumes no new reservation. A conflicting duplicate or inconsistent metadata invalidates the entire context. An incomplete context expires locally without a response. Implementations MUST bound concurrent contexts, aggregate reserved logical bytes, maximum fragments per message, maximum message length, and timeout. Route-semantic state is not allocated while the message remains incomplete.

\subsection{Receive pipeline and control-message roles}

The normative receive order is:
\begin{enumerate}
  \item exact 1,052-byte cell-record length;
  \item public link epoch and sequence parsing, with an optional non-mutating replay-window precheck;
  \item adjacent-link AEAD authentication followed by replay-state commitment and authenticated exact-duplicate rejection;
  \item canonical W2 header and fragment validation;
  \item bounded reassembly, duplicate handling, and timeout;
  \item canonical M2 envelope and message-specific syntax;
  \item M2/W2 suite agreement and E1 lifetime, peer-rate, byte, state, and cryptographic-work admission;
  \item suite-selected eligibility processing plus required reply-KEM, AEAD, signature, and transcript validation;
  \item branch or route-state transition;
  \item reconstruction of outgoing M2 messages and fresh W2 cells.
\end{enumerate}
A failure cannot consume resources reserved for a later stage. Detailed failure remains local and maps to bounded silent discard unless a separately specified non-amplifying response is required.

\subsection{Relay state}

A branch context contains only local information: ingress peer and epoch, incoming branch capability, incoming reply key, eligibility capsule, expiry, bounded children, and the key material necessary for candidate return. It does not contain a source address, complete route, ring index, or logical-discovery identifier.

A tentative route mapping is separate from the branch context. It binds one parent candidate capability, one child candidate capability, one parent-facing forward label, one child-facing reverse label, one transcript digest, one generation, and one deadline. A valid \textsc{Commit} replaces the tentative deadline with a pending-ready deadline; a stale timer for the former generation cannot reclaim the new state. Only authenticated \textsc{Ready} changes it to active.

A W2 reassembly context is a third and strictly earlier state class. It is transport-local, contains no interpreted route semantics, and is deleted before the parsed M2 message is dispatched. This separation prevents an incomplete or conflicting fragment stream from manufacturing branch or route mappings.

\section{Unlinkability analysis}
\label{sec:unlinkability}

\subsection{Elimination of explicit equality handles}

Between an admitted incoming \textsc{Discover} and each outgoing child record, an honest relay changes:

\begin{enumerate}
  \item the branch token;
  \item the reply public key;
  \item the complete suite-selected eligibility capsule;
  \item the bounded propagation representation;
  \item the padding;
  \item the adjacent-link nonce and ciphertext;
  \item the output timing position within the declared batch policy.
\end{enumerate}

It also reconstructs the body rather than forwarding received bytes. Candidate tokens and route labels are likewise replaced on reverse and activation paths.

\begin{proposition}[No explicit stable handle]
Assume canonical suite-selected processing, independently sampled per-child randomness, and no implementation-added identifier. A conforming honest relay copies no protocol field unchanged from an incoming DISCOVER record into a non-adjacent outgoing DISCOVER record.
\end{proposition}

The proposition is syntactic. It does not imply that timing, topology, message scarcity, or maliciously chosen transformations cannot correlate the records.

\subsection{Conditional batch-local argument}

Let an honest relay release a batch of $k$ records with identical observable class and scheduling treatment. If the retained reply-key transformation and the concrete C2 rerandomization are unlinkable under their assumptions, link ciphertexts are fresh, and no hidden implementation field survives, then a passive observer's matching information is limited to cryptographic advantage and batch-policy information. In the ideal uniform batch, the baseline guessing probability is $1/k$.

The argument fails when $k=1$, when one logical message has a distinguishable cell count or release pattern, when a stable logging or tracing field leaks, or when the observer uses end-to-end timing. Accordingly, U1 conformance is profile-specific rather than a property of one cryptographic primitive alone.

\subsection{C1 persistent ratio tag as a negative control}
\label{sec:active-tagging}

The passive transformation argument does not extend to a compromised relay. In a valid C1 consistency pair,
\begin{equation}
(U_1,V_1)=(r_1A,r_1B), \qquad A=aB.
\label{eq:validconsistency}
\end{equation}
A malicious relay chooses a known non-zero scalar $c$ and replaces the pair by
\begin{equation}
(\widetilde U_1,\widetilde V_1)=(cV_1,V_1).
\label{eq:ratiotag}
\end{equation}
Both values remain canonical non-identity group elements. After an honest relay rerandomizes with non-zero scalar $s$, the pair becomes
\begin{equation}
(\widetilde U'_1,\widetilde V'_1)=(scV_1,sV_1).
\end{equation}
A colluding downstream relay tests
\begin{equation}
\widetilde U'_1\stackrel{?}=c\widetilde V'_1,
\label{eq:tagtest}
\end{equation}
which always holds. The relation is therefore a deterministic cross-hop tag that survives the honest transformation.

The destination computes the consistency value
\begin{equation}
T=\widetilde U'_1-a\widetilde V'_1=(c-a)sV_1.
\label{eq:tagfailure}
\end{equation}
Except when $c=a$, the destination rejects the capsule and returns no candidate. The attack combines linkability and denial of service; observation of the missing candidate or missing route activation may also provide confirmation.

\begin{proposition}[C1 active-unlinkability counterexample]
Under the C1 negative-control eligibility construction, two colluding compromised relays separated by any number of honest rerandomizing relays can link a tagged branch by the test in \Cref{eq:tagtest}. Consequently, C1 cannot satisfy the active-adversary eligibility requirement.
\end{proposition}

Adjacent-link authentication does not prevent the attack. It rejects modification by a third party on an edge, but a compromised relay can originate new syntactically valid outgoing M2/W2 traffic containing the tagged pair. Fixed cell length, canonical M2 and point encoding, non-identity checks, fresh link encryption, and generic endpoint failure are necessary controls but do not erase the algebraic relation.

\subsection{C2 tag game and symbolic behavior}

The C2-TAG experiment places an upstream compromised relay and a downstream compromised relay around at least one honest transforming relay. The upstream relay may replace a valid capsule by arbitrary same-suite bytes. The honest relay validates and applies \textsf{ReRand}, or rejects. The downstream relay receives an output only after successful honest processing. It wins when capsule contents identify the selected upstream branch with non-negligible advantage, excluding timing, topology, direction, and cell-count information that belongs to a traffic profile.

An acceptable active-security outcome is not necessarily continued delivery: a non-replay-equivalent mutation may be rejected at the first honest relay. Such rejection is still a denial of service, but it prevents a separated colluder from receiving a persistent transformed tag. Alternatively, a construction may normalize an allowed replay-equivalent transformation so that it is computationally indistinguishable from honest rerandomization.

The executable C2 ideal functionality realizes the rejection case by construction. A valid opaque capsule can be rerandomized to a fresh opaque capsule in the same hidden replay class. An attacker-controlled marker mutation is not registered as a valid class member, so the honest transformation fails and emits no child capsule. This validates the protocol state transition, suite binding, failure normalization, and measurement points. It is not a security argument for a concrete anonymous Rand-RCCA construction.

The concrete active-security gate remains closed until C2 has exact algorithms and encodings, a reviewed security mapping, bounded verification cost, and negative tests for algebraic, substitution, public-key, replay, truncation, composition, and selective-failure attacks.

\subsection{Timing limitation}

Fixed record sizes and per-hop cryptographic changes do not hide timing. TARANET's coordinated constant-rate approach and Loopix's stochastic mixing with cover traffic represent different latency--bandwidth trade-offs~\cite{taranet,loopix}. \ProtoName{} treats batching, release cadence, and cover traffic as separate scheduling profiles. Each profile must state its observer, latency, bandwidth cost, minimum anonymity set, and measured matching success.

\section{Resource and denial-of-service model}
\label{sec:resources}

\subsection{Why privacy increases state}

Without a shared attempt identifier, a relay cannot recognize all converging copies of one logical discovery. In a tree approximation with relay fan-out $f$ and depth $d$, the number of branch transmissions can approach
\begin{equation}
T(f,d)=\sum_{i=1}^{d}f^i=\frac{f^{d+1}-f}{f-1}, \qquad f>1.
\label{eq:treegrowth}
\end{equation}
Cycles and duplicate graph paths can increase repeated visits further. Privacy therefore requires hard limits rather than optimistic assumptions about deduplication.

\subsection{Required limits}

Every node defines finite limits for:

\begin{itemize}
  \item accepted branch contexts per ingress peer and globally;
  \item fresh branches per peer and time window;
  \item outgoing children per branch and total queued W2 cells;
  \item complete M2 message length, protected-body length, and fragments per message;
  \item concurrent W2 reassembly contexts and aggregate reserved logical bytes;
  \item fragment residence time, duplicate processing, and conflicting-fragment cleanup;
  \item suite-selected eligibility validation and rerandomization, group operations, KEM operations, and signature checks;
  \item candidate responses per branch and per endpoint identity;
  \item tentative, pending-ready, and active route capacity;
  \item logical-message count, cell transmissions, setup duration, retries, and cleanup retention.
\end{itemize}


Authenticated exact cell replay rejection occurs before route-level token-bucket consumption. A receiver may reject obviously stale public sequence values provisionally, but it advances the replay window only after link authentication. A fresh valid branch token is not a replay and consumes an ingress token before expensive route cryptography. Reassembly admission is bounded separately and occurs before route-semantic or public-key work. Per-peer buckets mitigate concentrated sources but do not provide Sybil or distributed-denial resistance.

\subsection{Amplification condition}

For one admitted branch $b$, define
\begin{equation}
\alpha_b=\frac{W_{\mathrm{out}}(b)+W_{\mathrm{state}}(b)+W_{\mathrm{crypto}}(b)}{W_{\mathrm{in}}(b)},
\end{equation}
where the numerator represents normalized outgoing, state, and cryptographic work. A profile must bound each component independently. A small response byte count does not compensate for unbounded group operations or retained state.

\section{Deterministic evaluation}
\label{sec:evaluation}

\subsection{Method}

The evaluation uses deterministic graph and event models rather than a packet-level network benchmark. The experiments use reproducible seeds, explicit topology size and average degree, responder density, fan-out, hop limits, state and transmission budgets, link delay, loss, exact duplication, and attacker generation. Results quantify design behavior under the model; they do not estimate Internet latency or prove security.

The retained C1 component implementation uses \code{libsodium} for group operations. Ed25519 and ChaCha20-Poly1305 use the Python \code{cryptography} package. Deterministic vectors cover the negative-control URE, wrong-key rejection, reply-key tweak consistency, KEM/AEAD opening, tamper and context mismatch, descriptor/address derivation, and candidate signature binding.

The C2 ideal functionality has a separate deterministic vector set covering opaque encryption, repeated rerandomization, replay equivalence, wrong-recipient rejection, arbitrary mutation, and suite integration. \subsection{Concrete C2 transcription audit}

The concrete audit uses the exact algorithmic structure in Section~6.3 and Figure~6 of Wang et al.~\cite{anonrcca2021}. The source requires related quadratic-residue groups obtained from a length-three Cunningham chain and proves the relevant tag-SPHF smoothness properties for $k\geq2$~\cite{anonrcca2021}. The audit fixes $k=2$ and a small deterministic prime chain solely to make byte-level tests reproducible. It does not claim that the parameter set has a modern security level.

The original ciphertext decrypts to the eligibility marker, a canonical encode/decode cycle preserves all 24 group elements, the wrong recipient rejects, and selected component mutations reject. Restricting the tag multiplier to the identity also validates the two linear strand-combination paths. The full source rerandomization, however, includes a non-identity multiplier that simultaneously changes the outer tag-SPHF values and the inner malleable encryption~\cite{anonrcca2021}. Under the literal finite-field map tested here, the required multiplicative equation fails before any security interpretation is considered. The audit therefore returns the machine-readable status \code{finite-field-tag-reduction-nonhomomorphic}, and the callable concrete \textsf{ReRand} interface raises a conformance-gap error.

\begin{claimbox}[Interpretation of the audit]
The result identifies an algebraic blocker in the literal finite-field instantiation. It does not refute the generic security framework, establish an attack on a corrected construction, or justify substituting an ad hoc coercion. A network suite can be assigned only after an author-confirmed correction or independently reviewed replacement is specified, full nontrivial rerandomization validates over randomized test populations, modern parameters are selected, and a second implementation reproduces the vectors.
\end{claimbox}

\section{Limitations and open problems}
\label{sec:limitations}

\subsection{Concrete realization of the C2 contract}

C2 states the active-security contract that the eligibility capsule must satisfy: recipient anonymity, public rerandomization, rerandomizable RCCA security, resistance to persistent tagging, and bounded failure behavior. The symbolic C2 functionality used in the executable model enforces this contract as an oracle: an honest transform accepts only a valid equivalence-class member, emits an independently distributed member of the same class, and rejects arbitrary mutation before a downstream colluder can observe a descendant capsule. This is useful for protocol integration and falsification, but it is not a cryptographic construction and supplies no computational reduction.

The selected construction is no longer unspecified: the repository contains a typed $k=2$ transcription of Section~6.3 and Figure~6 of Wang et al.~\cite{anonrcca2021}, an explicit related-group parameter set, canonical public-key and 412-byte ciphertext encodings, deterministic positive and negative vectors, and a fail-closed public interface. The audit validates the original-ciphertext path and proves that the literal integer-reduction tag map used by full rerandomization is non-homomorphic. The remaining gate is therefore an author-confirmed correction or independently reviewed replacement, followed by confirmation of the source-to-code mapping, reviewed modern parameters, and independent reproduction of all equations.

The ciphertext must continue to satisfy the M2/W2 resource bounds. The receiver-anonymity and rerandomizable-RCCA reductions of the cited construction must also remain applicable when the construction is composed with the surrounding protocol transcript. Until the complete rerandomization path is independently validated, the paper claims only the behavior of the symbolic functionality and the recorded arithmetic audit; it does not claim concrete active-adversary unlinkability.

\subsection{Independent cryptographic review}

Independent review must address both the selected C2 realization and the retained reply and candidate mechanisms. For C2, the review must examine recipient anonymity, equivalence-class handling, rerandomization soundness, chosen-ciphertext behavior, selective failure, active tagging, malformed group elements, composition with M2/W2, and side-channel behavior. For the retained components it must examine the additive related-key behavior of the custom reply KEM, CCA behavior of nested candidate layers, transcript and key privacy, point-encoding assumptions, failure timing, and implementation side channels. The custom reply construction is HPKE-inspired and is not an RFC~9180 HPKE suite.

\subsection{Fragmentation, reliability, and cell-count leakage}

M2/W2 removes a hard one-record candidate-depth limit, but it does not make message size invisible. A passive adjacent-link observer can count the cells in a burst and may infer a range for candidate depth or protected-body size. A traffic-scheduling profile must decide whether to interleave fragments, pad cell counts to declared classes, delay completion to a release schedule, or accept this leakage explicitly.

Multi-cell messages are also more exposed to loss. If a message uses $q$ indispensable cells and independent cell delivery succeeds with probability $p$, message delivery without retransmission is approximately $p^q$. Real losses are not independent, and a route setup contains several messages, but the expression explains the observed direction of the effect. Bounded retransmission, forward-error correction, or redundant scheduling must be designed without adding a stable cross-hop message identifier or an amplification channel.

Reassembly creates a distinct denial-of-service surface. The fixed limits on complete message length, fragment count, concurrent contexts, aggregate reserved bytes, and timeout are normative. Further work must evaluate authenticated fragment sprays, peer rotation, deliberately missing final fragments, conflicting duplicates, and eviction fairness.

\subsection{Post-quantum migration}

The retained reply, authentication, and negative-control components are classical, and the C2 contract does not by itself select a post-quantum realization. A hybrid KEM replacement is not enough because the eligibility selector must preserve destination-key privacy, public rerandomization, and active-tag resistance simultaneously. Post-quantum rerandomizable RCCA encryption, or a different private eligibility mechanism with equivalent protocol properties, is therefore a separate research problem.

\subsection{Directory and descriptor distribution}

Long-range descriptor resolution is outside the protocol defined here. A future directory must provide authenticated descriptor binding, freshness, replication, poisoning resistance, selective-denial analysis, enumeration resistance, and private queries. Repeated deterministic hashing of an endpoint address is not sufficient query privacy.

\subsection{Distributed abuse and fairness}

Per-peer token buckets remain vulnerable to Sybil distribution. Candidate and responder spam require quotas independent of branch admission. Evaluation must vary attacker distribution, peer churn, adaptive refill, honest convergence, and fairness by ingress peer rather than report only aggregate success.

\subsection{Traffic privacy}

Timing, direction, volume, cell count, fragment spacing, and topology remain major correlation surfaces. A traffic-privacy profile must define batching, fragment interleaving, cell-count padding, release cadence, cover traffic, overflow behavior, and observable classes, then measure bandwidth, latency, reassembly reliability, and matching success against a named adversary. Encryption and fixed cell length alone do not imply logical-message or traffic-flow unlinkability.

\section{Implementation and review strategy}
\label{sec:strategy}

Development should proceed through explicit gates:

\begin{enumerate}
  \item obtain an author-confirmed correction or select an independently reviewed replacement for the non-homomorphic literal finite-field tag map in the selected $k=2$ construction~\cite{anonrcca2021};
  \item publish the confirmed algebraic mapping, modern parameter-generation procedure, canonical public-key and ciphertext encodings, validity relation, generic failure behavior, proof obligations, and deterministic interoperability vectors;
  \item require a second implementation to reproduce encryption, decryption, full rerandomization, replay equivalence, wrong-recipient rejection, mutation rejection, and every tracked byte string before assigning a network suite;
  \item obtain independent review of the C2 construction and the retained reply-key, nested-candidate, and signature mechanisms;
  \item replace the symbolic C2 oracle in the simulator only after the concrete implementation passes the full tag, mutation, replay-equivalence, key-substitution, malformed-input, and selective-failure suite;
  \item define M2 and W2 in a reviewed machine-readable schema and implement an independent second codec;
  \item cross-check minimal VarUInt encodings, suite binding, message boundaries, canonical fragmentation, conflict handling, and cryptographic vectors across implementations;
  \item fuzz malformed M2 lengths, W2 headers, fragment order, duplicate conflicts, message identifiers, eligibility capsules, nested candidate boundaries, point encodings, transcript substitutions, and state races;
  \item model fragment-spray attacks and verify hard limits on contexts, bytes, fragments, cryptographic work, and expiry processing;
  \item define bounded message repair or retransmission without stable cross-hop identifiers or unbounded amplification;
  \item build a user-space overlay prototype over an existing authenticated transport;
  \item test interoperability under loss, duplication, reordering, partial messages, link churn, malicious peers, and distributed resource pressure;
  \item specify cell interleaving, cell-count padding, and traffic-scheduling profiles before making message-size, timing, or flow claims;
  \item design long-range descriptor resolution as a separate protocol with its own threat model.
\end{enumerate}

The first overlay prototype should use ordinary IP connectivity only as an experimental transport. It should not require special routers or a new link technology. Protocol state, cryptographic transformations, message/cell interoperability, failure behavior, and resource limits should be evaluated before lower-layer integration is considered.

\section{Conclusion}
\label{sec:conclusion}

\ProtoName{} defines a privacy-enabled route-discovery control plane rather than a replacement for IP or BGP. Its current form has a precise operational boundary. U1 removes explicit cross-hop equality handles under passive observation; E1 gives deterministic bounded route setup and cleanup; C2 states the receiver-anonymous, rerandomizable-RCCA active-security contract for endpoint eligibility; M2 gives each logical control operation one canonical suite-agile variable-length representation; and W2 carries those messages in independently authenticated fixed-size adjacent-link cells with bounded reassembly. The protocol-facing C2 realization remains symbolic. In parallel, a concrete $k=2$ transcription of the construction of Wang et al.~\cite{anonrcca2021} fixes dimensions, related groups, canonical bytes, and deterministic arithmetic tests, but deliberately refuses full rerandomization because the literal finite-field tag reduction is non-homomorphic. The reply KEM, nested candidate protection, signatures, and C1 negative control remain concrete classical components.

The separation between M2 and W2 resolves a layering defect. Fixed width is retained where it hides an observable transmission-unit length, while the protocol grammar remains compact and extensible. Deep candidates can span several cells instead of failing at a one-record boundary. The cost is explicit: cell count and timing may reveal a message-size class, multi-cell messages have greater loss exposure, and reassembly requires additional bounded state.

The integrated model shows that cryptographic interfaces, canonical encoding, fragmentation, reassembly, and lifecycle can be exercised together. Clean routes activate only after authenticated candidate, \textsc{Commit}, and \textsc{Ready} processing; malformed or unauthenticated cells fail before route-state allocation; incomplete messages expire; and every evaluated scenario reclaims all state. The C1 negative control retains the known persistent ratio tag. Under the symbolic C2 contract, arbitrary mutation is rejected at the first honest transformation and no descendant tag observation is produced. The concrete audit separately demonstrates that key generation, encryption, decryption, canonical encoding, and linear strand recombination are executable, while proving that the literal finite-field tag reduction cannot support the full transformation. These results establish protocol behavior, a reproducible source-to-code map, and a falsification harness, not the security of a concrete cryptosystem.

The protocol is therefore suitable as a falsifiable research specification and interoperability target, but not as a production anonymity system. The next gate is an author-confirmed correction or independently reviewed replacement for the failed literal finite-field C2 instantiation, followed by reviewed modern parameters and protocol integration vectors. Subsequent gates are an independent M2/W2 implementation with fuzzing, a bounded reliability profile for multi-cell messages, and a traffic scheduler that explicitly addresses cell-count and timing leakage.

\section{Canonical message and cell encoding note}

M2 uses minimal unsigned base-128 LEB128 for body, eligibility-capsule, and nested variable lengths. Every decoder MUST reject a longer encoding of a value, an unterminated integer, a value above its field-specific maximum, trailing bytes, or a nested length that exceeds its containing message. The M2 suite identifier selects the eligibility-capsule grammar and bound; fixed-width numeric fields declared by a selected suite or message body remain unsigned big-endian values.

W2 uses fixed-width unsigned big-endian integers in the public 12-byte link header and encrypted 32-byte fragment header. The authenticated fragment header carries the same suite identifier as M2, and every fragment in one reassembly context MUST agree. The fragment count is not freely selected: it is the unique value $\lceil |M|/992\rceil$. Every non-final fragment carries exactly 992 M2 bytes and the final fragment carries exactly the remainder. Alternative short-fragment encodings of the same message are invalid.

The fixed 1,052-byte W2 record length hides exact per-cell content length. It does not hide the number, direction, or timing of cells. These observables belong to a separately declared scheduling profile.

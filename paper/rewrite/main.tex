\begin{abstract}
Route discovery can reveal endpoint relationships, local topology, and stable correlation handles before a protected data path exists. \ProtoName{} is a privacy-enabled control-plane protocol that explores a bounded graph, returns authenticated gateway candidates through nested reverse encryption, and installs hop-local bidirectional forwarding state without transmitting a complete route or a network-wide discovery identifier.

The active design separates endpoint rendezvous from route discovery. A destination creates random, short-lived, single-use capabilities and registers their commitments at selected rendezvous gateways. An authorized initiator is assumed to obtain a descriptor containing the capability and acceptable short-lived gateway pseudonyms through a mechanism outside Core. The non-normative \Done{} profile sketches private-information-retrieval and oblivious-relay variants, but no complete directory design is active. Forward \textsc{Discover} messages contain a non-semantic routing nonce and one suite-sized eligibility field, which under the mandatory suite is a second non-semantic nonce. Every honest relay replaces both, the adjacent branch token, the reply public key, the logical-message representation, the link-local transmission identifier, the padding, and the link ciphertext. A gateway returns its pseudonym inside an authenticated end-to-end candidate. The initiator selects a candidate, completes \textsc{Commit} and \textsc{Ready}, and only then sends the rendezvous capability through the active route. Atomic redemption prevents a second successful use.

The protocol binds nine active or analysis profiles and records one non-normative directory strawman. \Uone{} defines per-hop replacement and conditional batch-local unlinkability. \Eone{} defines half-open deadlines, equal-time precedence, candidate windows, delayed responses, cancellation races, tentative state, \textsc{Commit}, \textsc{Ready}, and local expiry. \Rone{} specifies generic gateway discovery, post-activation redemption, and explicit trust boundaries. \Done{} makes the missing descriptor-distribution assumptions explicit without claiming a complete solution. \Mtwo{} gives each logical control operation one canonical variable-length encoding without semantic padding. \Wtwo{} defines canonical fragmentation into payloads of at most 992 bytes and bounded out-of-order reassembly. \Tone{} places those fragments in fixed 1,052-byte authenticated \textsc{Data}, \textsc{Ack}, or \textsc{Chaff} cells, applies cumulative selective acknowledgements, estimates a bounded hop-local retransmission timer, and retransmits only missing fragments with fresh link ciphertexts. \Ttwo{} defines fixed, quantized-adaptive, and work-conserving release modes, encrypted schedule negotiation, finite rate menus, hysteresis, weighted deficit-round-robin service, and fail-closed overload behavior. \Tthree{} defines an equal-bandwidth traffic-analysis experiment over multiple observable links, including correlated background traffic, observation-window scaling, a transparent route classifier, transition-boundary measurements, and bounded active demand probes. \Tfour{} converts those schedules into per-cell events with finite serializers, jitter, shared bottlenecks, heterogeneous observer clocks, route churn, partial observation, open-world unknown routes, and bounded selective-delay experiments.

The retained reply path uses independent first-hop reply keys and multiplicative Ristretto255 blinding factors. For a fixed non-identity incoming key, one honest uniform non-zero factor makes the outgoing public key exactly uniform. Candidate layers use nested ChaCha20-Poly1305 encryption, Ed25519 authentication, and one RFC~5869-style Extract-then-Expand HKDF-SHA-256 schedule. This public-key result does not prove key privacy or unlinkability of the complete encrypted reply composition. Deterministic experiments show that bounded selective recovery materially improves route activation under independent cell loss. Across 30 runs per configuration, both evaluated \Tone{} modes activated every route up to twelve hops at loss rates of two and five percent; at twelve hops and ten percent loss, selective recovery activated 96.7 percent and fixed scheduling 93.3 percent, while unrecovered delivery activated none.

The \Ttwo{} model makes the scheduling trade-off explicit. Under equal overload, a low fixed class dropped 15 percent of offered work; a high fixed class delivered all work but emitted 1,600 chaff cells; and hysteretic adaptation delivered all work with a peak queue of 98 cells and 370 chaff cells. A simple observer distinguishing traces by public rate class had zero advantage against the evaluated fixed-high active/idle pair and perfect advantage against both evaluated adaptive policies. Fixed scheduling therefore retains only a conditional link-local slot-shape property; adaptive scheduling makes no activity-presence claim.

The \Tthree{} evaluation compares fixed, adaptive, and hybrid schedules under the same exact per-link bandwidth budget. For 128 correlated-background epochs and four balanced route classes, the reference nearest-centroid classifier achieved 25.0 percent accuracy against fixed traces, 99.0 percent against adaptive traces, and 36.5 percent against hybrid traces. A bounded demand probe was undetectable from fixed count traces in the modeled experiment, but was detected with 90.0 percent true-positive and 7.5 percent false-positive rates under adaptive scheduling. These deterministic results show that equal total bandwidth and fixed cell length do not imply equal multi-link trace shape; they are not a proof against stronger learned, open-world, or packet-level attacks.

The \Tfour{} packet-event model preserves an exact 2,240-cell public budget in every tracked 40-epoch trace while adding finite link service, clock error, jitter, bottlenecks, partial observation, and churn. Its open-world result exposes incompatible error modes: under network noise, fixed scheduling had monitored true-positive rate 0.083 and unknown false-positive rate 0; adaptive scheduling had monitored true-positive rate 0.917 and unknown false-positive rate 0.938. A transparent 60~ms selective-delay detector did not consistently outperform chance. These values are falsification results for one deterministic model, not evidence against stronger attacks.

The paper also audits receiver-anonymous rerandomizable RCCA encryption and an updatable/randomizable public-key encryption proposal, with citations at the points where their results are used. Neither supplies an enabled endpoint-specific discovery primitive. The resulting protocol does not claim complete-system endpoint anonymity, private directory lookup, protection from a colluding directory and gateway, global traffic-flow unlinkability, end-to-end congestion control, post-quantum security, or production readiness. Its purpose is to provide a coherent, testable baseline whose security claims, failures, recovery limits, queue behavior, bandwidth costs, and external dependencies are explicit.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

Anonymous communication systems ordinarily concentrate on the data path. Before that path can carry application traffic, however, a control plane must locate an eligible service, explore one or more paths, return a response, and install forwarding state. If the discovery procedure carries a stable endpoint key, address hash, attempt identifier, or recognizable ciphertext, separated relays may correlate representations of the same exploration even when the subsequent data path is onion encrypted.

The design problem is therefore not only to encrypt route discovery, but to minimize equality handles while retaining bounded operation. A relay needs enough information to return a response and later forward selected traffic, but should not receive the complete route. The initiator needs authenticated candidates, but a responder identity should not be exposed to every relay. A deployment also needs strict limits because branch exploration without a stable global duplicate identifier consumes more state than conventional flooding.

\ProtoName{} addresses these constraints by separating two questions:

\begin{enumerate}
  \item Which nearby nodes can provide a rendezvous-gateway service?
  \item Which destination should that gateway contact after a route has been selected and authenticated?
\end{enumerate}

The first question is answered by bounded graph discovery. The second is answered after route activation by a one-time capability delivered through a separately obtained private descriptor. This separation relocates rather than solves the endpoint-anonymity problem: until descriptor lookup is private and directory--gateway collusion is addressed, the complete system has no meaningful endpoint-anonymity claim. This arrangement follows the general architectural lesson of rendezvous systems: service identity, introduction, and connection joining need not be represented by the same network-visible object. Tor onion services likewise separate descriptors, introduction points, and rendezvous points~\cite{toroverview,torrendezvous,torintro}. \ProtoName{} does not implement the Tor protocol and does not inherit its anonymity analysis; those specifications are cited as an operational precedent for separating discovery from endpoint rendezvous.

The protocol makes the following contributions.

\begin{enumerate}
  \item It defines branch-local discovery without a network-wide discovery identifier or a transmitted source route.
  \item It removes endpoint-specific cryptographic material from active forward discovery.
  \item It defines a one-time rendezvous capability that is revealed only after authenticated route activation.
  \item It replaces each adjacent branch token, routing nonce, eligibility field, reply key, message identifier, padding region, and link ciphertext at every honest forwarding step.
  \item It returns candidates through a nested reverse-encryption chain that permits the initiator to reconstruct the reply-key sequence without exposing it to relays.
  \item It separates tentative route creation from explicit \textsc{Commit} and \textsc{Ready} authorization.
  \item It separates canonical variable-length messages, canonical fragmentation, and fixed-size encrypted transport cells.
  \item It defines cumulative selective acknowledgements, bounded hop-local retransmission, fresh retry ciphertexts, fragment interleaving, and optional fixed-rate chaff scheduling.
  \item It defines equal-budget multi-link evaluation, transparent route classification, correlated-congestion traces, transition-boundary analysis, and bounded active demand probing.
  \item It refines those schedules into packet events with bounded clocks, jitter, bottlenecks, churn, partial observation, open-world rejection, and selective-delay evaluation.
  \item It specifies finite reassembly, recovery, route-state, work, time, queue, registration, and redemption limits.
  \item It distinguishes structural per-hop unlinkability, conditional batch-local unlinkability, active tagging, and traffic-flow privacy.
  \item It preserves failed cryptographic candidates as explicit negative controls instead of silently relying upon them.
\end{enumerate}

The remainder of this paper first places the design in relation to anonymity systems, universal re-encryption, and rendezvous protocols. It then defines the system model, notation, profiles, algorithms, codecs, state machines, security boundaries, and deterministic evidence.

\section{Related work and design context}
\label{sec:background}

\subsection{Anonymous forwarding and traffic analysis}

HORNET demonstrates high-speed anonymous forwarding with symmetric cryptography on the data-plane fast path and no per-flow forwarding state in intermediate routers~\cite{hornet}. TARANET combines setup mixing with coordinated constant-rate transmission to resist traffic analysis at the network layer~\cite{taranet}. Sphinx defines a compact mix packet with per-hop transformation, path-length hiding, reply support, and formal security goals~\cite{sphinx}. Loopix combines Sphinx packets with stochastic mixing and cover traffic~\cite{loopix}. These works motivate the separation between fixed record shape, release scheduling, mixing, and cover traffic; they do not imply that a constant-rate adjacent link alone defeats end-to-end correlation.

Those systems assume that a path or layered packet structure has already been selected. \ProtoName{} considers the earlier stage in which the initiator knows a destination descriptor but does not yet know a usable gateway path. Consequently, source-routed onion construction cannot be applied directly: exploration branches, converges, expires, and returns candidates before one path is selected.


Traffic-analysis research also shows why per-cell protection and one-link constant-rate statements are insufficient. DeepCorr learns end-to-end flow correlations from timing traces and reports robustness to network noise~\cite{deepcorr}. RAPTOR shows that routing-level and network-position observations can expand the attack surface beyond one compromised relay~\cite{raptor}. Dropmark and DUSTER demonstrate that an active adversary can create or detect distinctive traffic patterns by manipulating flow timing or downstream observations~\cite{dropmark,duster}; more recent flow-marking work continues to study robust active modulation against encrypted traffic~\cite{activeflowmark2026}. These attacks are not implemented as cryptographic forgeries: they exploit observable traffic shape.

Defenses based on deterministic shaping, padding, or adversarial perturbation can reduce particular classifiers but must be evaluated under an explicit workload and adversary. Wang et al. evaluate deterministic website-fingerprinting defenses and quantify their bandwidth--latency trade-offs~\cite{wang2014wf}. Nasr et al. show that blind adversarial perturbations can be generated without direct access to a target classifier, reinforcing that evaluation against one classifier is only a lower bound~\cite{blindperturb}. Online and realistic website-fingerprinting studies further emphasize temporal drift, realistic background conditions, and the gap between closed-world laboratory data and deployed observations~\cite{onlinewf,gtt23,realitycheck2026}. \Tthree{} therefore uses a transparent nearest-centroid classifier as a mandatory rejection test, not as evidence that stronger correlation attacks fail.

Controlled anonymity-system experimentation also requires explicit modeling assumptions. Shadow demonstrates reproducible large-scale experiments in a controlled environment, while methodical Tor modeling shows that topology, traffic, capacity, and workload choices must be justified and validated~\cite{shadow2012,tormodel2012}. Remote timing observations additionally combine clock skew, network jitter, and timestamp quantisation~\cite{clockskew2008}; temporal route and location changes can themselves degrade privacy~\cite{tempest2018}. \Tfour{} incorporates simplified versions of these effects to expose assumptions, not to claim fidelity to those systems.

\subsection{Universal re-encryption and active relations}

Golle, Jakobsson, Juels, and Syverson introduced universal re-encryption so that a mixer could rerandomize a public-key ciphertext without receiving the recipient key~\cite{gjjs}. The construction is attractive for discovery because a stable destination public key need not accompany the ciphertext. Rerandomization alone is not sufficient, however. Banfi, Maurer, and Ritsch show that security definitions for universal re-encryption must capture both anonymity and unlinkability, and they give a composable application-level treatment for mix networks~\cite{ure2023}.

Replayable chosen-ciphertext security permits transformations that preserve the plaintext while protecting against other chosen-ciphertext modifications~\cite{rcca2003}. Receiver anonymity additionally requires that a ciphertext not disclose which admissible public key was used; the closely related key-privacy objective was formalized by Bellare et al.~\cite{keyprivacy2001}. Prabhakaran and Rosulek combined rerandomization with RCCA security but did not realize their stronger receiver-anonymity objective in the concrete scheme~\cite{rcca2007}. Wang et al. present a receiver-anonymous rerandomizable RCCA framework and a concrete construction based on rerandomizable tag smooth-projective hash functions~\cite{anonrcca2021}. The source is important to the security target discussed in \cref{sec:researchcrypto}, but the project's literal representative-level transcription remains disabled because its mapping of the abstract operation does not satisfy the required equation. The likely explanation is a transcription or interpretation mismatch; this is not presented as a flaw in the cited construction.

Dowling et al. construct updatable and randomizable public-key encryption as a component of strongly anonymous ratcheted key exchange~\cite{urpke2022}. Their randomization interface updates an encryption key and a ciphertext together. That is useful in its intended ratcheting setting, but it is not the ciphertext-only, same-recipient, public transform needed by the earlier endpoint-specific discovery design. The paper is therefore treated as a related primitive rather than a drop-in replacement.

\subsection{Rendezvous architectures}

Tor onion services publish short-lived service descriptors containing introduction points. A client contacts an introduction point, while client and service establish separate circuits to a rendezvous point that joins the circuits~\cite{toroverview,torrendezvous,torintro}. The Tor specifications also discuss replay resistance, fixed-size padding for introduction messages, and the resource impact of replayed requests~\cite{torintro}.

\Rone{} adopts only the architectural separation: the route-discovery message selects a generic gateway; endpoint-specific capability material is sent later over the selected active route. Unlike Tor, \Rone{} does not yet specify a directory consensus, descriptor encryption system, introduction circuit, or complete rendezvous handshake. These missing parts are explicit dependencies.

\subsection{Standard cryptographic components}

HPKE defines hybrid public-key encryption from a KEM, KDF, and AEAD with explicit context binding~\cite{hpke}. The retained reply construction follows this discipline but uses multiplicative \code{ristretto255} public-key blinding in a custom KEM not registered by HPKE, and is therefore described as HPKE-inspired rather than RFC~9180 compatible. HPKE supplies no inherited receiver-anonymity theorem for this custom composition. Group encodings follow RFC~9496~\cite{ristretto}; key derivation uses HKDF-SHA-256~\cite{hkdf}; authenticated encryption uses ChaCha20-Poly1305~\cite{chacha}; and responder authentication uses Ed25519~\cite{eddsa}.

\section{System model, roles, and claims}
\label{sec:model}

\subsection{Graph and route model}

Let the communication substrate be an undirected graph
\begin{equation}
G=(V,E),
\label{eq:graph}
\end{equation}
where each node may act as an initiator, ordinary relay, rendezvous gateway, or combination of those roles. An edge $(u,v)\in E$ denotes an authenticated adjacent-link association. A route of length $d$ is
\begin{equation}
\rho=(n_0,n_1,\ldots,n_d), \qquad (n_i,n_{i+1})\in E.
\label{eq:route}
\end{equation}
The route is a conceptual object used in the analysis; it is never transmitted as one message.

The adjacent-link transport supplies confidentiality, integrity, exact record boundaries, a directional epoch, replay sequence management, and connection-state notification. \Wtwo{} defines canonical fragment payloads and the complete fixed cell length. \Tone{} adds hop-local acknowledgements, bounded selective retransmission, fragment interleaving, and a declared cell scheduler. Work-conserving \Tone{} does not hide idle periods; fixed-schedule \Tone{} fills every declared directional slot with \textsc{Data}, \textsc{Ack}, or \textsc{Chaff}. Neither mode, by itself, hides schedule-epoch boundaries, link direction, topology, or cross-link timing correlation.

\subsection{Rendezvous roles}

The active rendezvous profile uses five logical roles:

\begin{itemize}
  \item $D$: destination endpoint;
  \item $Q$: private directory or capability-distribution service;
  \item $G$: rendezvous gateway;
  \item $S$: route initiator;
  \item $R$: ordinary route relay.
\end{itemize}

Roles are logical rather than necessarily distinct machines. The directory distributes a private descriptor to an authorized initiator. The gateway stores capability commitments and, after redemption, receives a local endpoint handle. Core does not define how the directory hides queries, authenticates recipients, distributes records, or reaches consensus. \Done{} records a non-normative two-replica PIR and oblivious-relay strawman so this dependency is visible rather than buried.

\subsection{Adversary}

The adversary may observe links outside the declared adjacent-link protection profile; compromise a bounded set of nodes; inspect their keys, state, queues, and local timing; inject, drop, delay, duplicate, reorder, redirect, or replace messages at compromised nodes; generate fresh branches; collude across separated relays; steal capabilities from compromised initiators; and attempt state, queue, registration, or cryptographic-work exhaustion. For \Tthree{}, it may additionally observe timestamp, direction, and fixed record counts on several links over a declared window; train on labeled traces from the declared model; exploit correlated cross traffic; and inject a bounded positive-demand pattern at one ingress without modifying authenticated records.

The adversary cannot forge uncompromised adjacent-link authentication or break the assumptions assigned to the retained standard primitives. No cryptographic assumption is assigned to the symbolic C2 oracle or the disabled C2 transcription. A malicious directory and a malicious gateway may correlate descriptor delivery with redemption; the active profile does not claim to prevent this.

\subsection{Claim classes}

\begin{definition}[Per-cell length equality]
Every active \Tone{}/\Ttwo{} transmission has the same complete length independently of frame class, logical message type, fragment position, protected-body length, retry status, or chaff status.
\end{definition}

\begin{definition}[Endpoint-independent forward field]
A forward-discovery field is endpoint-independent if, conditioned on public protocol parameters and local branch state, its distribution does not depend on the selected destination descriptor.
\end{definition}

\begin{definition}[Passive structural unlinkability]
After at least one honest forwarding step, no protocol field available after adjacent-link decryption provides a deterministic equality test that links a designated incoming branch to a non-adjacent outgoing branch.
\end{definition}

\begin{definition}[Batch-local unlinkability]
After an honest transformation and an explicitly defined mixing boundary containing at least two identically treated cells, a passive observer cannot match an input to its output beyond the advantage induced by the retained cryptographic components and remaining cell-count, timing, and topology leakage.
\end{definition}

\begin{definition}[Lifecycle correctness]
Every accepted event causes one deterministic state transition or rejection; every state has a finite half-open lifetime; and loss of advisory cleanup messages cannot create permanent state.
\end{definition}

\begin{definition}[Fixed-schedule trace shape]
During a pre-existing schedule epoch with origin $T_0$, slot interval $\Delta$, finite end time, and no declared overload transition, one cell is emitted in each directed slot independently of whether the selected encrypted frame is \textsc{Data}, \textsc{Ack}, \textsc{Schedule}, or \textsc{Chaff}.
\end{definition}

\begin{definition}[Traffic-flow unlinkability]
An observer cannot correlate endpoints from direction, timing, volume, cell count, fragment bursts, retries, queue behavior, topology, or long-lived observation.
\end{definition}


\begin{definition}[Equal-budget comparison]
For a super-epoch of $W$ transport epochs and public budget $B$ cells per link per epoch, every compared profile emits exactly $WB$ fixed-size records on each observed directed link. Equality of this total removes aggregate byte count as a trivial feature but does not equalize trace shape, latency, transitions, or correlation.
\end{definition}

\begin{definition}[Route-classification advantage]
For $k$ balanced route classes and classifier accuracy $a$, the reported advantage is $a-1/k$. It measures one declared classifier and feature set under disjoint deterministic training and test samples; it is not an anonymity theorem.
\end{definition}

\begin{definition}[Active-probe detectability]
A bounded probe is detectable in a declared experiment when a classifier using only the known probe and downstream public traces separates probe-present from probe-absent samples above the balanced random baseline. Availability disruption and endpoint identification remain separate properties.
\end{definition}

\section{Profiles and notation}
\label{sec:notation}

\subsection{Bound profiles}

The protocol binds the following profiles:

\begin{itemize}
  \item \Uone{}: branch-local representation replacement and conditional batch-local unlinkability;
  \item \Eone{}: deterministic event ordering, route-state activation, cancellation, and expiry;
  \item \Rone{}: generic gateway discovery followed by one-time endpoint-capability redemption;
  \item \Mtwo{}: canonical variable-length logical messages without semantic padding;
  \item \Wtwo{}: canonical fragmentation, fixed payload bounds, and bounded reassembly;
  \item \Tone{}: fixed-size encrypted \textsc{Data}, \textsc{Ack}, and \textsc{Chaff} cells with hop-local selective recovery;
  \item \Ttwo{}: fixed or quantized-adaptive epochs, encrypted \textsc{Schedule} control, weighted service, and bounded overload behavior;
  \item \Tthree{}: equal-budget multi-link observation, route-level classification, boundary-phase measurement, correlated cross traffic, and bounded active-demand probing;
  \item \Tfour{}: packet-event timing, finite serializers, heterogeneous observer clocks, route churn, partial observation, open-world rejection, and bounded selective delay.
\end{itemize}

The profiles are composed rather than substituted for one another. \Rone{} removes endpoint-specific material from forward discovery; \Uone{} replaces branch-local representations; \Mtwo{} defines semantic encoding; \Wtwo{} defines fragmentation and reassembly; \Tone{} defines link-local recovery; \Ttwo{} defines service and public cadence; \Tthree{} defines equal-budget count-trace experiments; \Tfour{} refines them into packet-event and open-world experiments; and \Eone{} defines route-state evolution.

\section{R1 rendezvous capability profile}
\label{sec:r1}

\subsection{Capability issuance}

For each descriptor epoch, destination $D$ selects one or more gateways and samples
\begin{equation}
\tau \sample \{0,1\}^{256}\setminus\{0^{256}\}.
\label{eq:capability}
\end{equation}
For each selected gateway $G$, the destination registers
\begin{equation}
\left(h_\tau,t_{\mathrm{exp}},e_D,\pi_G\right),\qquad
h_\tau=\Hash(\code{Trahens-R1-capability-v1}\concat\tau),
\label{eq:registration}
\end{equation}
where $e_D$ is an ephemeral endpoint handle meaningful only to the gateway's local rendezvous process. The gateway MUST store $h_\tau$ rather than $\tau$. The record has a finite half-open lifetime and is atomically deleted upon successful redemption.

The directory privately supplies an authorized initiator with
\begin{equation}
\mathsf{RDesc}=\left(t_{\mathrm{epoch}},t_{\mathrm{exp}},\tau,
\{\pi_{G_1},\ldots,\pi_{G_k}\},\mathsf{auth}_D\right).
\label{eq:rdesc}
\end{equation}
The descriptor distribution protocol is deliberately outside Core. A deployment must specify client authentication, query privacy, record replication, enumeration resistance, and revocation.

\begin{warningbox}[Trust boundary]
Removing endpoint-specific cryptography from \textsc{Discover} does not remove trust; it relocates it. A directory can observe descriptor delivery, and a gateway can observe capability redemption. A colluding directory and gateway may correlate those events unless a separate private-directory and gateway-separation profile prevents it.
\end{warningbox}

\subsection{Discovery field}

A \textsc{Discover} message carries two independent per-hop values, separated in Core v1.6. The first is a suite-independent \emph{routing nonce}
\begin{equation}
\nu_i\in\{0,1\}^{256}\setminus\{0^{256}\},
\end{equation}
which binds this hop's link in the returned candidate chain and is the key from which per-offer labels are derived. The second is the active suite's \emph{eligibility field} $\eta_i$, whose width the suite fixes: \Rone{} carries a fresh $256$-bit nonce, C1~v2 a $1024$-bit universal-re-encryption capsule.

Earlier revisions used one $256$-bit value for both purposes. That coupling was not a property of the encoding --- the \Mtwo{} envelope has always length-prefixed the eligibility field and fixed a width per suite --- but of the route-discovery semantics above it, which read the same value they handed to the suite. Consequently every suite was forced to be $256$ bits wide, and a suite whose field is a capsule could not be selected at all. Separating the two makes the eligibility width a suite choice and leaves route discovery unchanged, at the cost of $32$ bytes in \textsc{Discover}.

Neither value carries an endpoint key, address, capability, commitment, or selector under \Rone{}. Every honest relay samples an independent $\nu_{i+1}$ for each forwarded child and separately asks the suite to transform $\eta_i$; the two replacements are independent, and what ``transform'' means is the suite's to define. A gateway responds because it locally provides the rendezvous service, not because either value matches an endpoint record.

The propositions below are stated for the routing nonce. Under \Rone{} they apply verbatim to the eligibility field, because that field is also a freshly sampled independent nonce. Under a suite whose field is endpoint-specific by construction, such as C1, they do not: there the field is intended to be meaningful to exactly one recipient, and Section~\ref{sec:researchcrypto} treats what that costs and provides.

\begin{proposition}[Endpoint independence of the forward field]
Assume the random generator is independent of the destination descriptor. For any two descriptors $r_0,r_1$ and any fixed public branch parameters,
\begin{equation}
\Pr[\nu_i=v\mid\mathsf{RDesc}=r_0]
=
\Pr[\nu_i=v\mid\mathsf{RDesc}=r_1]
=2^{-256}+\varepsilon_0,
\end{equation}
where $\varepsilon_0$ accounts only for rejection of the all-zero value.
\end{proposition}

\begin{proof}
The generation algorithm receives no descriptor input. It samples uniformly and repeats only when the sampled value is zero. Therefore its distribution is independent of descriptor choice.
\end{proof}

\begin{proposition}[Literal nonce tags do not survive an honest transform]
Let a compromised upstream relay place any chosen value $v$ in the nonce field. An honest relay replaces it by an independent non-zero sample $v'$. A downstream relay can test equality with $v$, but succeeds only with probability at most $(2^{256}-1)^{-1}$.
\end{proposition}

\subsection{Candidate filtering}

A gateway candidate contains $\pi_G$ only inside the end-to-end authenticated candidate payload. The initiator accepts the candidate only when
\begin{equation}
\pi_G\in\mathsf{RDesc}.\mathsf{acceptable\_gateways}
\quad\text{and}\quad t_{\mathrm{now}}<t_{\mathrm{exp}}.
\end{equation}
Ordinary relays do not learn the pseudonym or the destination descriptor.

\subsection{Post-activation redemption}

After the route reaches \textsc{Ready}, the initiator sends an end-to-end protected operation
\begin{equation}
\mathsf{RENDEZVOUS\_OPEN}=
\left(\tau,n_S,t_{\mathrm{exp}},\mathsf{handshake}_D\right).
\label{eq:open}
\end{equation}
The gateway computes $h_\tau$, locates a live record, verifies the interval and local policy, atomically deletes the record, and only then releases $e_D$ to its local rendezvous process. Repeated, expired, malformed, or wrong-gateway attempts produce the same externally observable failure class.

\begin{algorithm}[ht]
\caption{Atomic \Rone{} redemption at gateway $G$}
\label{alg:redemption}
\begin{algorithmic}[1]
\Require protected request $(\tau,n_S,t_{\mathrm{exp}},\mathsf{handshake}_D)$
\State $h\gets\Hash(\code{Trahens-R1-capability-v1}\concat\tau)$
\State $r\gets\mathsf{LookupAndLock}(h)$
\If{$r=\bot$ or $\tau=0^{256}$ or $t_{\mathrm{now}}\notin[r.t_c,r.t_e)$}
  \State \Return $\mathsf{generic\_failure}$
\EndIf
\If{$r.t_e\ne t_{\mathrm{exp}}$ or local policy rejects $\mathsf{handshake}_D$}
  \State \Return $\mathsf{generic\_failure}$
\EndIf
\State $\mathsf{DeleteAtomically}(r)$
\State \Return $\mathsf{OpenLocalRendezvous}(r.e_D,n_S,\mathsf{handshake}_D)$
\end{algorithmic}
\end{algorithm}

\begin{property}[Single successful redemption]
Under atomic lookup-and-delete semantics, at most one concurrent request for one capability commitment can obtain the endpoint handle.
\end{property}

\subsection{Local discovery state}

The initiator maintains an application request, private descriptor, expanding-ring schedule, cumulative budget, candidate set, and selection deadline. These values are local. The relay-visible object is a branch context bound to one ingress peer, one branch token, one incoming reply public key, one routing nonce, one eligibility field, finite expiry, and bounded child mappings.

The absence of a global attempt identifier prevents network-wide equality tests but also prevents perfect duplicate suppression when independently transformed branches converge. The resource model therefore treats each branch context as separately chargeable.

\section{Forward discovery and U1 transformation}
\label{sec:forward}

\subsection{Initiator behavior}

The initiator performs bounded expanding-ring discovery. The ring schedule, candidate threshold, retry policy, and cumulative budget remain local. For each selected first-hop peer, it creates an independent branch token $\beta_0$, reply key pair $(x_0,X_0)$, routing nonce $\nu_0$, and initial eligibility field $\eta_0$ obtained from the selected suite.

\begin{algorithm}[ht]
\caption{Initiator creates one first-hop branch}
\label{alg:initbranch}
\begin{algorithmic}[1]
\Require first-hop peer $p$, hop limit $d_{\max}$, local budget $\mathcal B$
\State $\beta_0\sample\{0,1\}^{128}\setminus\{0^{128}\}$
\State $x_0\sample\Zq\setminus\{0\}$; $X_0\gets x_0B$
\State $\nu_0\sample\{0,1\}^{256}\setminus\{0^{256}\}$
\State $\eta_0\gets\mathsf{Initial}()$ \Comment{suite-sized; a second nonce under \Rone{}}
\State $m\gets\mathsf{Discover}(\beta_0,X_0,\nu_0,\eta_0,d_{\max},\mathcal B.\mathsf{propagation})$
\State $M\gets\Encode_{\Mtwo}(m,\code{0101})$
\State send $\mathsf{W2FragmentAndSeal}(p,M)$
\State record $(p,\beta_0,x_0,t_e)$ in local discovery state
\end{algorithmic}
\end{algorithm}

\subsection{Receive and validation order}

A relay processes input in the following order:

\begin{enumerate}
  \item parse the public \Wtwo{} link header;
  \item perform a non-mutating preliminary replay-window check;
  \item authenticate and decrypt the cell;
  \item advance replay state only after successful authentication;
  \item validate the encrypted fragment header and suite;
  \item reserve bounded reassembly resources;
  \item complete and canonically validate the fragment set;
  \item decode one \Mtwo{} message and verify suite agreement;
  \item apply per-peer and global admission limits;
  \item allocate branch or route-semantic state;
  \item execute the message-specific transition.
\end{enumerate}

This order prevents unauthenticated traffic from reserving a future sequence number or allocating route-semantic state.

\subsection{Per-child transformation}

For each admitted child, an honest relay creates a representation independent of both the incoming branch and its other children.

\begin{algorithm}[ht]
\caption{Relay forwards one admitted \Rone{} child branch}
\label{alg:forwardchild}
\begin{algorithmic}[1]
\Require decoded branch $(\beta_i,X_i,\nu_i,\eta_i,d)$ and child peer $c$
\State enforce branch, peer, node, cell, byte, work, and time limits
\State $\beta_{i+1}\sample\{0,1\}^{128}\setminus\{0^{128}\}$
\State $b_i\sample\Zq\setminus\{0\}$
\State $X_{i+1}\gets b_iX_i$
\State $\nu_{i+1}\sample\{0,1\}^{256}\setminus\{0^{256}\}$ \Comment{routing: fresh randomness}
\State $\eta_{i+1}\gets\mathsf{Transform}(\eta_i)$ \Comment{eligibility: the suite decides}
\State store child mapping $(\beta_i,c,\beta_{i+1},b_i,X_i,X_{i+1},\nu_{i+1},t_e)$
\State $m'\gets\mathsf{Discover}(\beta_{i+1},X_{i+1},\nu_{i+1},\eta_{i+1},d-1,\ldots)$
\State $M'\gets\Encode_{\Mtwo}(m',\code{0101})$
\State $\mu'\sample\{0,1\}^{128}\setminus\{0^{128}\}$
\State fragment $M'$ canonically and emit fresh \Wtwo{} cells to $c$
\end{algorithmic}
\end{algorithm}

\subsection{Loops and convergence}

A relay rejects exact reuse of a live ingress token from the same peer and link epoch. It does not assume that two different tokens identify different logical discoveries. Immediate edge reversal is prohibited, and a relay MAY use bounded adjacent-local loop hints that do not cross a link boundary. Every accepted context is independently limited and expires locally.

\begin{proposition}[No explicit cross-hop equality handle]
In the mandatory \Rone{} forward transform, the outgoing branch token, routing nonce, eligibility field, reply public key, logical-message bytes, local wire message identifier, padding, AEAD nonce, and ciphertext differ from the incoming representation except with negligible collision probability.
\end{proposition}

\begin{proof}
Tokens, routing nonces, message identifiers, padding, and link nonces are freshly sampled, and the \Rone{} eligibility field is freshly sampled by the same argument. Under an experimental suite the eligibility field is transformed rather than resampled, and this proposition then holds for every listed value except that field, whose indistinguishability is the selected suite's obligation --- which is precisely what the C1 ratio-tag experiment of \cref{sec:researchcrypto} shows C1 does not discharge against an active adversary. The reply key is multiplied by an independently sampled non-zero scalar. In the prime-order group this makes the outgoing public key uniform over non-identity elements for any fixed non-identity input. The logical message is reconstructed and fragmented under a new local identifier. Adjacent-link ciphertext is produced under the outgoing link key. The only intentionally preserved values are bounded semantic controls such as remaining hop limit and profile identifiers.
\end{proof}

\section{Candidate return and route activation}
\label{sec:reverse}

\subsection{Gateway candidate}

A gateway that admits the branch constructs
\begin{equation}
P_G=(\pi_G,t_{\mathrm{offer}},X_d,c_G,n_G,\mathsf{params}),
\label{eq:candidatepayload}
\end{equation}
where $c_G$ is a commit challenge and $n_G$ is a fresh nonce. It signs the domain-separated transcript with its descriptor-authenticated Ed25519 key and seals the result to $X_d$ using the retained reply KEM.

The gateway pseudonym is protected inside the sealed payload. Relays learn only that a candidate is returning on a live branch.

\subsection{Nested reverse layers}

At relay $n_i$, the reverse layer contains the stored blinding factor, adjacent route labels, child candidate token, expiry, and child capsule:
\begin{equation}
L_i=(b_i,\lambda_i^{\rightarrow},\lambda_i^{\leftarrow},
\gamma_i,t_e,C_{i+1}).
\end{equation}
The relay seals $L_i$ to $X_i$ and forwards the resulting capsule to its parent under a fresh reverse token. The adjacent labels include the parent and child \emph{routing} nonces, which are $256$ bits whatever suite the link runs; a candidate layer therefore does not grow with the eligibility width, which is what makes a wide-field suite affordable rather than merely expressible.

The chain binds routing nonces and does not cover the eligibility field. That is a deliberate narrowing relative to earlier revisions, where one value served both purposes and binding it bound both. It is defensible because the eligibility field is hop-local, replaced or rerandomized at every hop, and integrity-protected by \Wtwo{} on the single adjacent link it crosses, while the chain exists to prove that a candidate returned along the branch the initiator opened --- which the routing nonce still proves. A suite whose eligibility field requires end-to-end authenticity must supply its own binding rather than inheriting one.

\subsection{Initiator opening}

Starting with $x_0$, the initiator opens the outer layer, obtains $b_0$, derives $x_1=b_0x_0\bmod q$, and repeats until it reaches the gateway payload.

\begin{algorithm}[ht]
\caption{Initiator validates one nested candidate}
\label{alg:opencandidate}
\begin{algorithmic}[1]
\Require root reply secret $x_0$, capsule $C_0$, private descriptor $\mathsf{RDesc}$
\State $x\gets x_0$; $C\gets C_0$; $\mathsf{path}\gets[\ ]$
\Loop
  \State $P\gets\Open_{\mathsf{TRKEM}}(x,C,\mathsf{context})$
  \If{$P$ is a relay layer $(b,\lambda^{\rightarrow},\lambda^{\leftarrow},\gamma,t_e,C')$}
    \State reject if expired or non-canonical
    \State append local route material to $\mathsf{path}$
    \State $x\gets bx\bmod q$; $C\gets C'$
  \ElsIf{$P$ is a signed gateway payload}
    \State verify transcript, descriptor key, offer deadline, and final reply key
    \State reject unless $P.\pi_G\in\mathsf{RDesc}.\mathsf{acceptable\_gateways}$
    \State \Return validated candidate and $\mathsf{path}$
  \Else
    \State \Return $\bot$
  \EndIf
\EndLoop
\end{algorithmic}
\end{algorithm}

\subsection{Commit and readiness}

Candidate return creates only tentative route mappings. The initiator selects one candidate and sends \textsc{Commit} using the first forward route label. Each relay verifies the expected parent label and challenge, reserves bounded capacity, moves the selected mapping to \code{PENDING\_READY}, and forwards under the next local label. The gateway returns \textsc{Ready}; each relay authenticates the reverse transition and moves the mapping to \code{ACTIVE}.

Application data and \textsc{Rendezvous-Open} MUST NOT be forwarded before the initiator authenticates final \textsc{Ready}. This separates discovery success from route authorization.

\section{E1 event lifecycle}
\label{sec:lifecycle}

\subsection{Half-open deadlines}

Every state created at $t_c$ with expiry $t_e$ is valid only on
\begin{equation}
[t_c,t_e)=\{t\mid t_c\le t<t_e\}.
\end{equation}
An event at exactly $t_e$ observes the state as expired. Timer rescheduling may extend a state only through an explicit transition; an older timer cannot shorten a later deadline.

\subsection{Equal-time precedence}

When events share one timestamp, an implementation applies this order:

\begin{enumerate}
  \item authenticated cell receipt and completion of already admitted reassembly;
  \item message-specific transition whose preconditions were valid immediately before the timestamp;
  \item local cancellation or selection decision;
  \item expiry and resource reclamation;
  \item advisory outbound cleanup.
\end{enumerate}

This order is deterministic but does not guarantee delivery. A candidate received after the local candidate window is closed is rejected even if remote branch state remains live.

Tentative/pending & \textsc{Cancel}/\textsc{Abort} & None & Best-effort early cleanup. \\
Active & \textsc{Close} or expiry & None & Reclaim active mapping. \\
\bottomrule
\end{tabularx}
\end{table}

Delayed candidates from earlier expanding rings MAY be accepted while the same logical candidate window remains open. They do not reopen a closed window and do not expand the cumulative budget.

\section{M2 logical messages and W2 fragmentation}
\label{sec:messages}

\subsection{Layer separation}

A logical protocol message, its canonical fragments, and an observable transport record solve different problems. \Mtwo{} therefore defines a compact canonical message. \Wtwo{} defines the unique fragmentation of that byte string into payloads of at most 992 bytes and the corresponding bounded reassembly rules. \Tone{}, specified in \cref{sec:t1}, places those fragments into fixed-size encrypted transport cells and adds hop-local recovery and scheduling. A short message normally occupies one data cell; a deeply nested candidate may occupy several. This separation removes the artificial route-depth limit caused by requiring every logical message to fit in one record.

\subsection{M2 envelope}

Every \Mtwo{} message has the canonical form
\begin{equation}
M=\mathsf{version}\concat\mathsf{type}\concat\mathsf{suite}
\concat\mathsf{body\_length}\concat\mathsf{body}.
\label{eq:m2}
\end{equation}
Version, type, and suite are fixed width. Variable lengths use minimal unsigned base-128 LEB128. A decoder rejects overlong encodings, unterminated values, trailing bytes, inconsistent nested lengths, and suite-specific field lengths outside their bounds.

The mandatory suite identifier is \code{0101}. Every \textsc{Discover} carries a 32-byte routing nonce independent of suite, followed by a length-prefixed eligibility field whose width the encoded suite fixes: 32 bytes for \Rone{}, 128 for C1~v2. A decoder that admits a suite MUST require exactly that suite's width, so the length prefix records the width rather than granting freedom in it. The raw capability $\tau$, its hash, gateway pseudonym, endpoint handle, and destination authentication material are prohibited from this message class.

\subsection{W2 payload and fixed-cell requirement}

Every transport profile carrying a \Wtwo{} fragment MUST preserve the complete record length
\begin{equation}
L_C=12+1024+16=1052\ \text{bytes}.
\end{equation}
The 12-byte public header contains a directional link epoch and sequence number. The encrypted 1,024-byte plaintext contains the selected transport header, fragment bytes or control information, and fresh random padding. ChaCha20-Poly1305 contributes the 16-byte authentication tag~\cite{chacha}. The active \Tone{} header is specified in \cref{sec:t1}.

\subsection{Canonical fragmentation}

For a logical message of length $L$,
\begin{equation}
q(M)=\left\lceil\frac{L}{992}\right\rceil,
\qquad 1\le L\le16{,}384,
\qquad 1\le q(M)\le17.
\label{eq:fragmentcount}
\end{equation}
Every non-final fragment contains exactly 992 message bytes. The final fragment contains the remainder. Alternative short-fragment decompositions are invalid.

\subsection{Bounded reassembly}

A context is keyed by authenticated directional link scope and a transport-local identifier. It reserves the declared total logical length, accepts out-of-order fragments, treats exact duplicates idempotently, invalidates the whole context on conflicting duplicate bytes or metadata, and expires after a finite deadline. Under \Tone{}, an authenticated cumulative acknowledgement may be generated from the retained bitmap before reassembly completes.

\begin{algorithm}[ht]
\caption{Bounded \Mtwo{}/\Wtwo{} reassembly pipeline}
\label{alg:reassembly}
\begin{algorithmic}[1]
\Require authenticated \Tone{} \textsc{Data} frame $f$ from peer scope $\ell$
\State require canonical suite, fragment count, index, total length, and fragment length
\State obtain or allocate bounded context $R[\ell,f.z]$
\State reject and invalidate context on metadata or byte conflict
\State store fragment or accept exact duplicate idempotently
\State update cumulative acknowledgement bitmap $A$ and queue a bounded \textsc{Ack}
\If{all canonical fragments are present}
  \State concatenate exactly $f.L$ bytes and retain a finite completion-cache entry
  \State decode one canonical \Mtwo{} message and require suite agreement
  \State only now invoke route-semantic processing
\EndIf
\end{algorithmic}
\end{algorithm}

\begin{property}[No route state before complete decoding]
A partial, unauthenticated, non-canonical, or cross-suite fragment set cannot allocate branch, candidate, tentative, pending, or active route state.
\end{property}

\section{T1 hop-local reliability and scheduled cells}
\label{sec:t1}

\subsection{Scope and termination at every relay}

\Tone{} is an adjacent-link transport profile. It does not create one end-to-end reliability association. For each directed authenticated link, the sender chooses a fresh non-zero 128-bit transmission identifier $z$, sends one canonical \Wtwo{} fragment set, and receives encrypted cumulative acknowledgements from the adjacent peer. A relay completely terminates that association, validates and reconstructs the \Mtwo{} message, applies the required \Uone{} or route-state transformation, chooses a new $z$, and starts an independent transmission on each selected outgoing link. The identifier, acknowledgement bitmap, timer state, and retry count never cross the relay.

This boundary is necessary for both privacy and resource accounting. An end-to-end fragment identifier would become a stable equality handle across separated relays. Link-local termination instead confines the unavoidable retry relation to the two adjacent peers that already know they communicate.

\subsection{Frame syntax}

Every \Tone{} cell preserves the 1,052-byte outer length. Its encrypted 1,024-byte plaintext begins with the 32-byte common header in \cref{tab:t1header}; the remaining 992 bytes contain fragment bytes or random padding. Frame type, transmission identifier, acknowledgement state, and padding are encrypted. The public header exposes only the directional link epoch and monotonically unique sequence number required for nonce construction and replay processing.

\begin{tabularx}{\textwidth}{@{}r r p{0.27\textwidth} X@{}}
\toprule
Offset & Bytes & Field & Requirement \\
\midrule

4--5 & 2 & cryptographic suite & Must agree across one reassembly context and the completed \Mtwo{} message. \\

For \textsc{Data}, the type-specific fields are four unsigned 16-bit integers: fragment index, fragment count, fragment length, and total \Mtwo{} length. The fragment set MUST satisfy \cref{eq:fragmentcount}. For \textsc{Ack}, they are the fragment count, receiver acknowledgement delay in milliseconds, and a 32-bit cumulative bitmap $A$. Bit $i$ acknowledges canonical fragment $i$; bits $i\ge q(M)$ MUST be zero. \textsc{Chaff} uses a fresh non-zero $z$, zero type-specific fields, and random protected bytes. It creates no reassembly or route-semantic state and receives no acknowledgement.

\subsection{Selective acknowledgement and sender state}

Selective acknowledgement is used only to avoid resending fragments already retained by the adjacent receiver. This resembles the conservative use of SACK information in TCP, but \Tone{} has a bounded message-fragment set rather than a byte-stream congestion window~\cite{rfc6675}. An exact duplicate fragment is idempotent and SHOULD trigger the current cumulative bitmap again; conflicting bytes or metadata invalidate the context.

For every live transmission the sender retains the canonical fragments, acknowledgement bitmap, per-fragment send count, most recent send time, bounded recovery-round count, and timer estimate. It releases the state when all required bits are authenticated or when the finite recovery budget is exhausted.

\begin{algorithm}[ht]
\caption{Hop-local selective recovery}
\label{alg:t1recovery}
\begin{algorithmic}[1]
\Require canonical fragment set $F=(f_0,\ldots,f_{q-1})$, local identifier $z$
\State $A\gets0$; $r\gets0$; initialize bounded timer state
\State queue each $f_i$ once under the declared scheduler
\While{$A\ne 2^q-1$ and $r\le r_{\max}$ and lifetime remains}
  \State emit queued fragments using a new link sequence, fresh padding, and fresh AEAD ciphertext
  \If{an authenticated \textsc{Ack} $(z,q,A',d_{ack})$ arrives}
    \State $A\gets A\lor A'$; discard acknowledged queue entries
    \State update the RTT estimate only from a fragment never retransmitted
  \ElsIf{the bounded retransmission timer expires}
    \State queue exactly the fragments whose bits are absent from $A$
    \State $r\gets r+1$; exponentially back off the timer within its configured maximum
  \EndIf
\EndWhile
\State return success iff every required bit is set; otherwise fail locally and reclaim state
\end{algorithmic}
\end{algorithm}

\subsection{Retransmission timer}

The timer follows the estimator structure standardized for TCP, including the prescribed update order, variance margin, exponential backoff, and exclusion of ambiguous retransmitted samples~\cite{rfc6298}. QUIC likewise uses acknowledgement-based loss detection, acknowledgement delay, and exponentially increasing probe timing, while integrating those mechanisms with an end-to-end congestion controller that \Tone{} does not adopt~\cite{rfc9002}. For an unambiguous round-trip sample $R$, the active equations are
\begin{align}
\widehat R &\gets R, & V_R &\gets R/2 &&\text{for the first sample},\label{eq:rtofirst}\\
V_R &\gets \tfrac34V_R+\tfrac14|\widehat R-R|, &
\widehat R &\gets \tfrac78\widehat R+\tfrac18R &&\text{thereafter},\label{eq:rtolater}\\
RTO &\gets \operatorname{clamp}\!\left(\widehat R+\max(G_c,4V_R),RTO_{\min},RTO_{\max}\right),\label{eq:rto}
\end{align}
where $G_c$ is the local clock granularity. A timeout doubles the current $RTO$ up to $RTO_{\max}$. All recovery rounds, queued bytes, retained contexts, timer lifetime, and cryptographic work are finite protocol parameters.

\begin{proposition}[Fresh retry ciphertext]
For a fixed fragment $(z,i,f_i)$, two valid emissions use distinct public sequence numbers, fresh padding, and newly computed AEAD ciphertexts. Subject to the adjacent-link AEAD assumptions and nonce uniqueness, ciphertext equality does not identify a retransmission to an unauthenticated observer.
\end{proposition}

\begin{proof}[Argument]
The semantic fragment bytes and local recovery coordinates may be unchanged, but the public sequence number changes the nonce and authenticated associated data; the protected padding is sampled again; and the authentication tag and ciphertext are recomputed. The adjacent receiver can link retries after decryption because it must update $A$. No value enabling that relation is copied into the forwarded \Mtwo{} message or the next link's transmission state.
\end{proof}

\subsection{Scheduler}

A fixed-schedule epoch declares a start $T_0$, directional slot interval $\Delta$, finite end, and queue budget. Exactly one 1,052-byte cell is emitted at each $T_0+k\Delta$ within the epoch. The encrypted frame selected for a slot obeys the priority in \cref{alg:t1scheduler}. Round-robin service among live transmissions prevents one multi-cell candidate from monopolizing all new-data slots.

\begin{algorithm}[ht]
\caption{Fixed-schedule \Tone{} sender for one directed slot}
\label{alg:t1scheduler}
\begin{algorithmic}[1]
\Require bounded ACK queue $Q_A$, retry queue $Q_R$, new-fragment queues $Q_N$
\If{$Q_A$ is non-empty}
  \State emit one cumulative \textsc{Ack}
\ElsIf{$Q_R$ is non-empty}
  \State emit one due retransmission
\ElsIf{some queue in $Q_N$ is non-empty}
  \State emit one new fragment by round-robin across live transmissions
\Else
  \State emit one fresh \textsc{Chaff} cell
\EndIf
\end{algorithmic}
\end{algorithm}

Work-conserving mode uses the same priority but emits nothing when all queues are empty. It provides recovery and interleaving, not a constant public trace. Fixed scheduling follows the same broad motivation as TARANET's constant-rate data phase~\cite{taranet}; Loopix instead combines stochastic mixing with cover traffic~\cite{loopix}. \Tone{} implements neither complete system and makes only the conditional property below.

\begin{proposition}[Conditional fixed-schedule trace shape]
During a pre-existing, non-overloaded fixed schedule epoch, the public record times, directions, and lengths on that link are independent of whether each encrypted slot contains \textsc{Data}, \textsc{Ack}, or \textsc{Chaff}.
\end{proposition}

\begin{proof}[Argument]
The schedule fixes one record at each directed slot. All frame classes have the same outer length, and the class is encrypted. Replacing an idle chaff cell by a real frame therefore does not change that link's public slot sequence. The statement excludes epoch negotiation, epoch boundaries, queue overflow, congestion-induced rate changes, compromised peers, and correlation with other links.
\end{proof}

\subsection{Replay, failure, and mandatory bounds}

The public sequence number is subject to a non-mutating preliminary replay check. Replay state advances only after successful adjacent-link authentication; an unauthenticated future sequence cannot reserve a number and suppress the valid cell. Wrong length, failed authentication, unsupported frame class, non-zero reserved flags, invalid $z$, non-canonical fragment metadata, ACK bits outside the declared count, conflicting duplicates, suite mismatch, and exhausted budgets map to normalized link-local rejection.

A conforming deployment specifies finite values for schedule-epoch length and rate; sender transmissions and bytes per peer and node; queued new and retry fragments; pending ACKs; receiver contexts and reserved bytes; ACK delay; minimum, initial, and maximum $RTO$; recovery rounds and attempts per fragment; completion-cache lifetime; malformed-input work; and chaff bandwidth. Recovery and chaff are charged to the same physical-link and node-global budgets as first transmissions.

\section{T2 congestion and quantized scheduling}
\label{sec:t2}

\subsection{Scope and design objective}

\Ttwo{} binds the recovery mechanisms of \Tone{} to a finite adjacent-link service policy. Its purpose is not to reproduce an end-to-end transport controller. It determines how one authenticated directed link admits queued cells, divides service among concurrent local transmissions, reacts when offered load exceeds the current schedule, and states what the resulting public cadence reveals. The general requirement that a sender limit injected traffic and avoid inappropriate bursts under uncertain capacity is central to established congestion-control standards~\cite{rfc5681,rfc9002}; \Ttwo{} applies a deliberately smaller contract to equal-size cells on one adjacent link.

The profile separates three questions that must not be conflated:
\begin{enumerate}
  \item \emph{recovery}: which missing fragment is sent again, as specified by \Tone{};
  \item \emph{service}: which admitted cell receives the next available slot;
  \item \emph{cadence}: how many public slots exist in an epoch.
\end{enumerate}
Recovery does not create capacity. Increasing cadence does not prove anonymity. Equal record length does not hide the number or timing of records.

\subsection{Epochs, classes, and pressure}

For one directed link, let
\begin{equation}
\mathcal{R}=(r_0,r_1,\ldots,r_K), \qquad 0<r_0<r_1<\cdots<r_K,
\label{eq:ratemenu}
\end{equation}
be the finite public menu of cells per epoch. Epoch $e$ has duration $\Delta_e$, selected class $c_e\in\{0,\ldots,K\}$, and exactly $r_{c_e}$ physical slots in fixed or adaptive mode. The schedule may be fixed for a declared interval, quantized-adaptive across epochs, or work-conserving.

\centering

The pressure signal is intentionally local and bounded:
\begin{equation}

\end{equation}
It is not transmitted as a precise value. A peer observes the negotiated class and may infer coarse pressure from its transitions.

\subsection{Encrypted schedule negotiation}

\Ttwo{} adds one encrypted adjacent-link frame class, \textsc{Schedule}. It occupies the same 1,052-byte outer record as \textsc{Data}, \textsc{Ack}, and \textsc{Chaff}. The public header remains the directional link epoch and sequence. The encrypted common body identifies wire profile \code{04}, profile and suite identifiers, and frame type \code{03}. The type-specific fields are shown in \cref{tab:t2schedule}.

A transition is valid only when both peers authenticate matching \textsc{Offer} and \textsc{Accept} frames for the same negotiation identifier, requested class, and effective epoch. An unauthenticated, stale, conflicting, incomplete, or rejected negotiation leaves the next epoch at the current class. Negotiation identifiers, rate history, deficits, weights, and pressure measurements terminate at the adjacent relay and are never copied into an outgoing \Mtwo{} message.

\subsection{Quantized adaptive rule}

Adaptive mode updates two consecutive-pressure counters. Subject to a minimum hold interval, it may move by at most one class:

\begin{algorithm}[ht]
\caption{Quantized adaptive class proposal}
\label{alg:t2adapt}
\begin{algorithmic}[1]
\Require current class $c_e$, pressure $\rho_e$, counters $h,\ell$, hold count $u$
\If{$\rho_e\ge\theta_\uparrow$}
  \State $h\gets h+1$; $\ell\gets0$
\ElsIf{$\rho_e\le\theta_\downarrow$}
  \State $\ell\gets\ell+1$; $h\gets0$
\Else
  \State $h\gets0$; $\ell\gets0$
\EndIf
\State $c'\gets c_e$
\If{$u\ge H_{\mathrm{hold}}$ and $h\ge H_\uparrow$ and $c_e<c_{\max}$}
  \State $c'\gets c_e+1$
\ElsIf{$u\ge H_{\mathrm{hold}}$ and $\ell\ge H_\downarrow$ and $c_e>c_{\min}$}
  \State $c'\gets c_e-1$
\EndIf
\State return an authenticated offer for $c'$ iff $c'\ne c_e$
\end{algorithmic}
\end{algorithm}

Asymmetric thresholds and counters suppress rapid oscillation but do not make the class sequence independent of traffic. The rate menu and boundary alignment limit the vocabulary available to an observer; they do not erase the signal.

\subsection{Bounded service and weighted fairness}

Within each epoch, the physical-cell budget is exactly $r_{c_e}$. Cells are selected in this bounded order:
\begin{enumerate}
  \item due cumulative \textsc{Ack};
  \item accepted or required \textsc{Schedule} control;
  \item due missing-fragment retransmission;
  \item new \textsc{Data} selected by weighted deficit round robin;
  \item \textsc{Chaff} if the active cadence requires a slot and no real cell is eligible.
\end{enumerate}
ACK and schedule-control reserves are finite and cannot create undeclared slots. Their configured limits must leave non-zero service for admitted DATA.

Deficit round robin provides efficient approximate fair queueing without per-packet finish-time sorting~\cite{drr}. Because every Trahens cell has the same outer length, one unit of deficit pays for one DATA cell. On a visit to a backlogged class $f$, the scheduler adds $w_fq_0$ to $d_f$, emits while $d_f\ge1$ and slots remain, and subtracts one per cell. Empty classes reset their deficit. Weights are local policy and never cross a relay.

\begin{algorithm}[ht]
\caption{One \Ttwo{} physical slot}
\label{alg:t2service}
\begin{algorithmic}[1]
\Require bounded queues $Q_A,Q_S,Q_R$, backlogged DATA classes $\mathcal{F}$
\If{$Q_A$ contains a due ACK within its reserve}
  \State emit one \textsc{Ack}
\ElsIf{$Q_S$ contains a due control within its reserve}
  \State emit one \textsc{Schedule}
\ElsIf{$Q_R$ contains a due retry within its reserve}
  \State emit one retransmitted \textsc{Data}
\ElsIf{some $f\in\mathcal{F}$ is backlogged}
  \State select and emit by weighted deficit round robin
\Else
  \State emit \textsc{Chaff} in fixed/adaptive mode; emit nothing in work-conserving mode
\EndIf
\end{algorithmic}
\end{algorithm}

The evaluation reports the Jain--Chiu--Hawe fairness index~\cite{jainfairness} over normalized throughputs $x_f=\operatorname{delivered}_f/w_f$:
\begin{equation}
J(x_1,\ldots,x_n)=\frac{(\sum_{i=1}^{n}x_i)^2}{n\sum_{i=1}^{n}x_i^2}.
\label{eq:jain}
\end{equation}
This metric detects unequal normalized allocation in the modeled horizon; it does not establish strategic fairness, admission fairness, or resistance to forged identities.

\subsection{Admission, overload, and burst loss}

Before admitting a new \Mtwo{} transmission, the sender knows its canonical fragment count. A conforming implementation SHOULD reserve the complete first-send set atomically. If that reservation exceeds the per-flow, per-peer, or global queue budget, the transmission is rejected before its first fragment is emitted.

At the maximum class, persistent overload MUST NOT silently accelerate the public cadence. The implementation expires stale contexts, rejects new over-budget work, bounds additional recovery rounds, expires queued work at finite deadlines, and reports a generic local transport failure. Dropping a slot from a declared fixed epoch is a visible profile break and terminates the fixed-trace claim for that interval.

Loss is not automatically treated as congestion. Wireless corruption, burst errors, and adversarial dropping may produce the same timeout symptom. The reference stress test therefore compares independent loss with the two-state burst-noise family introduced by Gilbert and developed by Elliott~\cite{gilbert1960,elliott1963}. This is a reproducible model, not evidence that one channel process fits a deployment.

\subsection{Privacy boundary}

\begin{proposition}[Conditional fixed-epoch shape]
During a pre-existing, non-overloaded fixed \Ttwo{} epoch, the public timestamps, directions, and lengths on one observed link are independent of whether each encrypted slot carries \textsc{Data}, \textsc{Ack}, \textsc{Schedule}, or \textsc{Chaff}.
\end{proposition}

\begin{proof}[Argument]
The epoch declares exactly $r_c$ equal-size slots. Frame class is encrypted, and a real cell replaces an otherwise emitted chaff cell without changing the slot time or outer length. The statement excludes epoch establishment, boundary observation, overload, peer compromise, route completion, and correlation with another link.
\end{proof}

Adaptive mode has a different claim. Its class sequence $(c_0,c_1,\ldots)$ and transition times are public and are treated as coarse traffic evidence. Research on adaptive padding and website-fingerprinting defenses demonstrates that efficiency gains and classifier resistance are highly workload- and model-dependent~\cite{wtfpad}. Consequently, \Ttwo{} does not infer activity hiding from quantization or hysteresis. Work-conserving mode makes no constant-trace claim. No mode provides a global-observer theorem.

A conforming deployment publishes finite values for the rate menu, epoch duration, negotiation guard time, hold and hysteresis counters, queue thresholds, weights, deficits, control reserves, retry work, residence deadlines, CHAFF budget, schedule lifetime, and malformed negotiation work.



\section{T3 multi-link adversarial traffic analysis}
\label{sec:t3}

\subsection{Purpose and scope}

\Tthree{} is an evaluation profile over \Ttwo{} traces. It introduces no new wire frame, cipher suite, route message, or congestion controller. Its purpose is to determine whether fixed record length and one-link schedule statements survive a multi-link observer with longer windows, correlated background traffic, route-level classification, and a bounded active demand probe. Learned flow correlation, routing-level observation, and active traffic manipulation have all been shown to expose relationships that are absent from ciphertext contents~\cite{deepcorr,raptor,dropmark,duster}. \Tthree{} therefore treats traffic analysis as a separate security gate rather than inferring it from encryption.

\subsection{Equal super-epoch budget}

Let $\mathcal{L}$ be the finite set of observed directed links. A comparison covers a super-epoch of $W$ \Ttwo{} epochs and assigns a public budget $B$ records per link per epoch. Every compared profile MUST satisfy
\begin{equation}
\sum_{e=0}^{W-1} y_{\ell,e}=WB,
\qquad \forall \ell\in\mathcal{L},
\label{eq:t3budget}
\end{equation}
where $y_{\ell,e}$ is the complete fixed-size record count. The experiment also reports
\begin{equation}
\sum_{\ell\in\mathcal{L}}\sum_{e=0}^{W-1} y_{\ell,e}=|\mathcal{L}|WB.
\label{eq:t3totalbudget}
\end{equation}
The equalizer changes only chaff allocation and MUST NOT delete authenticated DATA required by admitted work. Equal budget removes total bytes as a trivial feature; it does not equalize queueing, transition placement, inter-link delay, or count distribution inside the window.

\subsection{Compared release profiles}

The reference experiment uses three schedules:
\begin{itemize}
  \item \emph{fixed}: $y_{\ell,e}=B$ for every link and epoch;
  \item \emph{adaptive}: traffic-responsive quantized service with transitions aligned to public \Ttwo{} epoch boundaries, followed by deterministic chaff equalization over the complete super-epoch;
  \item \emph{hybrid}: a non-zero baseline, smoothed pressure response, route-independent decoy uplifts, non-boundary transition phases, and exact super-epoch chaff equalization.
\end{itemize}
The hybrid schedule is an analysis candidate, not a deployed protocol. A deployable sub-epoch transition mechanism would require precommitted envelopes, clock-skew limits, and a proof that phase selection preserves replay and service ordering. Deterministic shaping has known bandwidth and latency costs, while classifier resistance remains workload dependent~\cite{wang2014wf,wtfpad}.

\subsection{Boundary and correlation observables}

For each public schedule transition, let $\phi_{\ell,e}\in\{-1,0,\ldots,S-1\}$ denote its micro-slot phase; $-1$ means no transition and $0$ means an epoch-boundary transition. The boundary-alignment statistic is
\begin{equation}
A_{\partial}=\frac{\#\{(\ell,e):\phi_{\ell,e}=0\}}
{\#\{(\ell,e):\phi_{\ell,e}\ge0\}},
\label{eq:t3boundary}
\end{equation}
with value zero when no transition occurs. The evaluator also reports pairwise lagged Pearson correlation between observed count series. Correlation is descriptive evidence, not a proof of a causal route relation.

\subsection{Route workload and classifier}

The mandatory model exposes four directed links and four balanced labels:
\begin{equation}
0:\varnothing,\quad 1:(0,1,2),\quad 2:(0,1,3),\quad 3:(0,2,3).
\label{eq:t3routes}
\end{equation}
Each non-empty route receives a delayed target-demand signal. Background demand is either independently sampled per link or derived from a shared latent burst process. The final four epochs contain low demand so that queue cleanup remains inside the measured window.

The reference classifier $\mathcal{C}$ is intentionally transparent. For every trace, it concatenates binned per-link counts, binned first differences, transition count, boundary fraction, and pairwise lagged correlations. Columns are standardized with training statistics only. Each class centroid is the mean standardized training vector, and a test vector is assigned to the nearest centroid with deterministic numeric tie-breaking.

\begin{algorithm}[ht]
\caption{Reference \Tthree{} route classifier}
\label{alg:t3classifier}
\begin{algorithmic}[1]
\Require disjoint balanced training set $\mathcal{D}_{tr}$ and test set $\mathcal{D}_{te}$
\State extract declared public features from every trace
\State compute column means and scales from $\mathcal{D}_{tr}$ only
\State standardize training and test vectors with those values
\For{each route label $j$}
  \State $\mu_j\gets$ mean standardized training vector for label $j$
\EndFor
\For{each test vector $x$}
  \State output $\arg\min_j\lVert x-\mu_j\rVert_2$, breaking ties by smallest $j$
\EndFor
\end{algorithmic}
\end{algorithm}

For $k$ balanced classes and measured accuracy $a$, the reported advantage is
\begin{equation}
\operatorname{Adv}_{route}=a-\frac{1}{k}.
\label{eq:t3advantage}
\end{equation}
A low result against this classifier is only a minimum gate. Strong learned attacks can exploit representations and temporal structures that a centroid classifier ignores~\cite{deepcorr,blindperturb,gtt23,onlinewf,realitycheck2026}.

\subsection{Bounded active demand probe}

The active experiment injects a known positive-demand pulse sequence $p_e$ at one ingress. At downstream hop $h$, the evaluator compares $p_e$ against both public count $y_{\ell,e+h}$ and positive schedule differences. The score is the maximum absolute lagged correlation over the declared lag range. A threshold is learned halfway between the mean probe-absent and probe-present training scores.

The probe changes offered load only; it does not alter authenticated cells, route state, or cryptographic material. It is therefore a schedule-modulation attack rather than a forgery. Active flow-marking research motivates treating such modulation separately from passive classification~\cite{dropmark,duster,activeflowmark2026}. A positive detection demonstrates responsive scheduling, not destination identification by itself.

\begin{proposition}[Fixed count-trace independence in the reference model]
Conditioned on $W$, $B$, $|\mathcal{L}|$, and the declared fixed profile, the public count matrix $(y_{\ell,e})$ is independent of the route label.
\end{proposition}

\begin{proof}[Argument]
By definition, $y_{\ell,e}=B$ for every observed link and epoch. The route signal changes only the encrypted choice between real and chaff cells, not the public count matrix. The statement excludes epoch start and end, direction, loss-induced profile breaks, other packet metadata, and observations outside the modeled matrix.
\end{proof}

\begin{proposition}[Equal total bandwidth is insufficient]
Equation~\eqref{eq:t3budget} does not imply that two schedule profiles have equal multi-link trace distributions.
\end{proposition}

\begin{proof}[Argument]
The constraint fixes one sum per link. It permits different within-window count vectors, transition phases, queue delays, and cross-link correlations. A classifier may therefore distinguish traces while every link transmits the same total number of equal-size records.
\end{proof}

A conforming \Tthree{} experiment MUST report class balance, random baseline, observation window, cross-traffic condition, probe amplitude, total per-link budget, classifier definition, budget mismatches, queue overflow, delivery failure, cleanup failure, and all stated limitations. It MUST NOT describe one classifier result as a global-observer anonymity proof.

\section{T4 packet-level adversarial evaluation}
\label{sec:t4}

\subsection{Purpose and methodology}

\Tfour{} refines the public schedules of \Ttwo{} and \Tthree{} into timestamped cell events. Controlled simulation is valuable for anonymity-system research because live experiments are difficult to reproduce and may expose users; however, the credibility of a result depends on explicit topology, traffic, capacity, and timing assumptions~\cite{shadow2012,tormodel2012}. The reference emulator is therefore deliberately small, deterministic, and inspectable. It is a falsification harness, not a calibrated replacement for those experimental platforms or for deployment measurements.

\Tfour{} introduces no new frame, field, cipher suite, or congestion controller. Route labels, target/background classifications, and complete paths exist only inside the emulator. A target cell that continues after one relay is represented by a newly local token; no packet identifier crosses the modeled relay boundary.

\subsection{Packet events and service resources}

\begin{definition}[Packet event]
A packet event is a tuple
\begin{equation}
  e=(t,\pi,\sigma,\kappa,x),
\label{eq:t4event}
\end{equation}
where $t$ is true time, $\pi$ is a fixed event-class priority, $\sigma$ is a monotonically increasing insertion sequence, $\kappa$ is the event class, and $x$ is bounded model-local state. The event queue is ordered lexicographically by $(t,\pi,\sigma)$.
\end{definition}

The reference classes are demand arrival, epoch decision, public slot release, access-link completion, shared-bottleneck completion, next-hop arrival, and observation. Deterministic tie-breaking makes the complete experiment reproducible from its configuration and seed.

For a cell of $C$ bytes transmitted over a resource of rate $R$ bits per second, the serializer is occupied for
\begin{equation}
  S(C,R)=\left\lceil\frac{8C\cdot10^6}{R}\right\rceil \text{ microseconds}.
\label{eq:t4serialization}
\end{equation}
Every logical link has a finite FIFO and access serializer. Selected links may additionally contend for one finite-capacity shared serializer. Propagation delay on link $\ell$ is
\begin{equation}
  D_\ell=d_\ell+J_\ell,
  \qquad -J_{\max}\le J_\ell\le J_{\max},
\label{eq:t4jitter}
\end{equation}
with deterministic pseudorandom sampling from the experiment seed. Queue overflow, expiration, delay, and peak occupancy are reported rather than hidden.

\subsection{Heterogeneous observer clocks}

A multi-link adversary need not possess one perfect clock. Remote clock measurements are affected separately by skew, path jitter, and timestamp quantisation~\cite{clockskew2008}. For link $\ell$, \Tfour{} maps true observation time $t$ to
\begin{equation}
  \widehat t_\ell=
  Q_\ell\!\left((1+s_\ell)t+o_\ell+\eta_\ell\right),
\label{eq:t4clock}
\end{equation}
where $s_\ell$ is relative skew, $o_\ell$ is offset, $\eta_\ell$ is bounded measurement noise, and $Q_\ell$ is quantisation. This transformation is applied only when constructing the adversary trace. It cannot reorder internal protocol events.

\begin{remark}
Clock heterogeneity is not assumed to be a defense. It is a declared measurement condition. An attacker may estimate or compensate for clocks more effectively than the transparent reference classifier.
\end{remark}

\subsection{Exact public budget and route churn}

For $E$ measured epochs, $L$ observed logical links, and budget $B$ cells per link and epoch, every compared profile MUST satisfy
\begin{equation}
  N_{\mathrm{public}}=ELB.
\label{eq:t4budget}
\end{equation}
The scheduler constrains the remaining release budget online; it does not append an unobserved compensation interval. Equal record count removes one trivial feature but does not equalize timestamps, queueing, correlation, or delivery.

A churn trace declares $(r_0,r_1,e_c)$. Target work generated before $e_c$ follows route $r_0$; work generated at or after $e_c$ follows $r_1$; cells already in flight retain their existing path. Temporal changes in client location and network routing can materially change anonymity-system privacy, so churn is treated as a security variable rather than only a repair event~\cite{tempest2018}.

\subsection{Partial observation and open-world rejection}

The reference topology uses monitored routes
\begin{equation}
  1:(0,1,2),\qquad 2:(0,1,3),\qquad 3:(0,2,3),
\label{eq:t4monitored}
\end{equation}
and distinct route combinations for unknown calibration and unknown testing. Unobserved links continue to execute all queue and timing rules but are absent from the adversary trace; they are not supplied as privileged zero-valued observations.

Closed-world accuracy can misrepresent deployment conditions because most traces may not belong to any monitored class. Open-world website-fingerprinting research accordingly reports both recognition and false positives on non-monitored traffic~\cite{wang2014wf,onlinewf,gtt23,realitycheck2026}. \Tfour{} therefore uses three disjoint sets:
\begin{equation}
  \mathcal R_M=\{1,2,3\},\quad
  \mathcal R_C=\{4,5,6\},\quad
  \mathcal R_U=\{7,8,9,10\}.
\label{eq:t4splits}
\end{equation}
The first is monitored; the second calibrates rejection; the third tests previously unseen unknown routes.

Let $\mu_j$ be a monitored standardized centroid and
\begin{equation}
  d(x)=\min_{j\in\mathcal R_M}\lVert x-\mu_j\rVert_2.
\label{eq:t4distance}
\end{equation}
A threshold $\tau$ is selected from monitored validation and unknown-calibration traces only. The classifier outputs
\begin{equation}
  \mathcal C_{OW}(x)=
  \begin{cases}
    \arg\min_j\lVert x-\mu_j\rVert_2, & d(x)\le\tau,\\
    \bot, & d(x)>\tau.
  \end{cases}
\label{eq:t4openworld}
\end{equation}

\begin{algorithm}[ht]
\caption{Reference \Tfour{} open-world evaluation}
\label{alg:t4openworld}
\begin{algorithmic}[1]
\Require monitored training $D_M$, unknown calibration $D_C$, disjoint test $D_T$
\State extract public timestamp features from declared observed links
\State fit feature means, scales, and monitored centroids using $D_M$ only
\State choose rejection threshold $\tau$ using $D_M$ validation and $D_C$
\For{each $x\in D_T$}
  \State output \eqref{eq:t4openworld}
\EndFor
\State report monitored TPR, unknown FPR, monitored precision, macro-F1, and service metrics
\end{algorithmic}
\end{algorithm}

Overall accuracy MUST NOT be reported alone. A classifier that rejects every trace can appear accurate in an unknown-heavy dataset while providing no monitored recognition; conversely, a classifier can recognize monitored routes while labeling nearly every unknown route as monitored.

\subsection{Bounded selective-delay probe}

The active \Tfour{} adversary may add a declared finite delay $\Delta$ to target cells matching one link-local pulse pattern. It does not decrypt, forge, or modify an authenticated record. Both probe-absent and probe-present experiments use the same steady target workload. The transparent detector searches a finite set of phases and lags and scores correlation between the known pulse and downstream timestamp-derived features.

Traffic-confirmation and watermarking research shows that delay, loss, or bandwidth modulation can create downstream evidence without breaking link encryption~\cite{dropmark,duster,activeflowmark2026}. The \Tfour{} detector is intentionally weaker than that literature. A positive result rejects the evaluated profile. A negative result means only that this bounded detector did not separate the declared samples.

\begin{proposition}[Budget preservation]
If every link releases exactly $B$ complete cells in each of $E$ measured epochs, then all compared \Tfour{} traces have exactly $ELB$ public cells, independently of route label, churn, and encrypted cell class.
\end{proposition}

\begin{proof}
The claim follows by summing the per-link, per-epoch release invariant. It does not constrain release time inside an epoch, queue delay, inter-arrival distribution, or delivery of real cells.
\end{proof}

\begin{proposition}[Observer clocks do not change protocol causality]
Under \eqref{eq:t4clock}, clock skew, offset, noise, and quantisation may change the adversary feature vector but cannot change the true-time execution order of protocol events.
\end{proposition}

\begin{proof}
The event queue is ordered using true $(t,\pi,\sigma)$. The observer transformation is executed only when an observation is appended to the trace and is never fed back into the event scheduler.
\end{proof}

A conforming \Tfour{} report publishes all clock, jitter, capacity, bottleneck, route, churn, observation, class-balance, threshold, probe, queue, budget, delivery, and cleanup parameters. It MUST NOT describe one emulator or classifier result as resistance to a global or adaptive adversary.


\section{Retained cryptographic components}
\label{sec:crypto}

\subsection{Reply-key transformation}

For one branch, the initiator samples $x_0\in\Zq\setminus\{0\}$ and publishes $X_0=x_0B$. Relay $i$ samples $b_i\in\Zq\setminus\{0\}$ and computes
\begin{equation}
X_{i+1}=b_iX_i.
\label{eq:blindpublic}
\end{equation}
The initiator later reconstructs
\begin{equation}
x_{i+1}=b_ix_i\pmod q.
\label{eq:blindsecret}
\end{equation}

\begin{proposition}[Blinding consistency]
If $X_i=x_iB$, then the public and secret transformations in \cref{eq:blindpublic,eq:blindsecret} satisfy $X_{i+1}=x_{i+1}B$.
\end{proposition}

\begin{proof}
By compatibility of scalar multiplication,
$(b_ix_i)B=b_i(x_iB)=b_iX_i$.
\end{proof}

\begin{proposition}[Exact public-key distribution]
For fixed non-identity $X\in\Group$, if $b$ is uniform in $\Zq\setminus\{0\}$, then $bX$ is uniform over $\Group\setminus\{\Identity\}$.
\end{proposition}

\begin{proof}
Because $\Group$ has prime order and $X\ne\Identity$, $X$ is a generator. The map $b\mapsto bX$ is a bijection from the non-zero scalars to the non-identity group elements.
\end{proof}

This mirrors the multiplicative-blinding pattern used by Sphinx~\cite{sphinx}, but the proposition covers only the public-key sequence. It does not transfer the Sphinx proof to the custom reply format and does not establish key privacy of the encapsulation or unlinkability of complete ciphertext layers. Each first-hop branch uses an independent root key. Relays reject zero factors, identity keys, and non-canonical points according to RFC~9496~\cite{ristretto}.

\subsection{Reply KEM and nested encryption}

For encapsulation $R=eB$ and shared point $Z=eX$, the custom reply seal constructs a domain-separated context and performs one HKDF-Extract followed by one HKDF-Expand of 44 bytes. The output is split into a 32-byte ChaCha20-Poly1305 key and a 12-byte nonce, following the Extract-then-Expand structure of RFC~5869~\cite{hkdf}. No Expand output is reused as a new pseudorandom key.

The construction is HPKE-inspired because it combines ephemeral group agreement, a labeled KDF, and AEAD context binding~\cite{hpke,chacha}; it is not RFC~9180 HPKE and inherits no HPKE interoperability or receiver-anonymity claim. Context binds protocol version, C1 encoding version, message class, suite, direction, route stage, encapsulated point, recipient public key, and application information.

The production-facing sealing API generates $e$ internally from a cryptographically secure random source and accepts no deterministic-ephemeral parameter. A separately gated, non-exported test-support module supplies deterministic ephemerals solely for vectors and reproducible simulations. Reusing $e$ for the same recipient and context would repeat the encapsulated point, derived key, and nonce and is forbidden.

Fresh encapsulation randomness is required for every layer. Decryption, point-validation, transcript, and authentication failures map to one externally visible rejection class. Full passive reply-layer unlinkability remains conditional on key privacy or recipient anonymity of this custom KEM/PKE in the relevant multi-user chosen-ciphertext setting~\cite{keyprivacy2001}; it is not established by public-key blinding alone.

\subsection{Gateway authentication}

The signed candidate transcript includes, in fixed order, the protocol domain, version, suite, gateway pseudonym, offer deadline, final reply public key, commit challenge, candidate nonce, and selected parameter digest. Ed25519 verification follows RFC~8032~\cite{eddsa}. The descriptor must bind the verification key to the accepted short-lived pseudonym.

\subsection{Adjacent-link protection}

Link keys are distinct from reply and signing keys. Each directional link epoch provides unique nonces or sequence-derived nonce material. The replay window advances only after successful AEAD verification, preventing unauthenticated input from reserving future sequence numbers.

\section{Research cryptographic profiles and citations}
\label{sec:researchcrypto}

\subsection{C1 negative control}

The repository retains a GJJS-style universal-re-encryption capsule as a negative control~\cite{gjjs}. Its components can be rerandomized without a recipient key, but a compromised relay can multiply selected components by a related factor. The ratio between those components survives the honest rerandomization relation and is recognizable by a colluding downstream relay. This experiment demonstrates why byte-level freshness and passive rerandomization correctness do not imply resistance to active cross-hop tags, consistent with the stronger security distinctions discussed by Banfi, Maurer, and Ritsch~\cite{ure2023}.

That experiment stands unchanged, and C1 MUST NOT be cited as evidence for active unlinkability: the ratio tag is exactly a demonstration that it does not provide it.

What has changed in Core v1.6 is availability, not evidence. C1~v2 is now selectable as an experimental eligibility profile and is implemented end to end: an initiator encrypts an eligibility marker to a recipient key, every relay rerandomizes the capsule without learning anything, and only the recipient can decide that a discovery is addressed to it. Reaching it requires an explicit experimental profile as well as an explicit suite; the mandatory profile admits \Rone{} alone, and the retired C1~v1 and the disabled $k{=}2$ audit suite are refused on every profile.

The two statements are compatible and must be read together. C1 provides recipient-decidable eligibility against a passive path, which is a real property and is exercised by two network arms --- one where the gateway is the intended recipient and serves the route, one where it is not and declines. It does not provide active unlinkability, because the ratio tag survives an honest rerandomization. Making a research suite reachable under an explicit profile is not the same as promoting it, and no claim in this paper rests on it.

\subsection{Receiver-anonymous rerandomizable RCCA target}

Wang et al. define receiver-anonymous rerandomizable RCCA-secure public-key encryption and give a generic construction based on rerandomizable tag smooth-projective hash functions~\cite{anonrcca2021}. Their result is directly relevant to an endpoint-specific discovery ciphertext because the desired transform must preserve both plaintext and recipient while hiding the recipient and resisting non-replay modifications.

The protocol-facing security target was expressed independently as correctness, message confidentiality, receiver anonymity, public ciphertext-only rerandomization, transformed-ciphertext unlinkability, replay-equivalence handling, active-tag resistance, canonical encoding, and composition with the relay transform. The application-level URE treatment of Banfi et al. motivates separating these properties rather than relying on one syntactic rerandomization equation~\cite{ure2023}.

\subsection{Concrete k=2 audit}

A deterministic transcription implements the cited paper's $k=2$ key generation, encryption, decryption, canonical encoding, mutation rejection, and linear strand equations~\cite{anonrcca2021}. The project's literal representative-level transcription interpreted the relevant operation using the map
\begin{equation}
\mu(u)=u\bmod q
\end{equation}
from a quadratic-residue group modulo $p=2q+1$ into the field modulo $q$.

\begin{proposition}[Literal reduction is not generally multiplicative]
Under ordinary multiplication in $\operatorname{QR}^{*}_{p}$, the map $\mu(u)=u\bmod q$ is not a group homomorphism in general.
\end{proposition}

\begin{proof}
For the valid small chain $q=5$, $p=11$, and $r=23$, choose $u=3$ and $v=4$, both in $\operatorname{QR}^{*}_{11}$. Then $uv\bmod p=1$, hence $\mu(uv\bmod p)=1$, while
$\mu(u)\mu(v)\bmod q=3\cdot4\bmod5=2$.
\end{proof}

An exhaustive checker repeats this test over every admissible pair in several small Cunningham chains and finds a counterexample in every nontrivial chain examined. This is a narrow audit of the project transcription. The overwhelmingly plausible interpretation is that an abstract representation, embedding, projection, or group action was omitted or misread. The result does not refute the paper's generic framework, a correct concrete interpretation, or an author-confirmed correction. The corresponding suite identifier remains disabled and every network operation fails closed.

\subsection{Updatable and randomizable PKE}

Dowling et al. define updatable and randomizable signatures and public-key encryption for strongly anonymous ratcheted key exchange~\cite{urpke2022}. Their randomization operation transforms an encryption key and ciphertext together. The earlier \ProtoName{} endpoint-specific design required a relay that knows neither recipient key nor secret to transform only the ciphertext while preserving the same recipient. The interfaces are therefore different, and the cited construction is not enabled as an eligibility suite.

\subsection{Gate decision}

Because no reviewed concrete endpoint-specific primitive currently satisfies the complete protocol interface, the mandatory design adopts \Rone{}. This is a security-engineering decision rather than a claim that rendezvous capabilities dominate receiver-anonymous rerandomizable encryption. It trades a difficult cryptographic dependency for a directory-and-gateway trust boundary that can be specified, measured, and replaced independently.

The gate is a decision about what an interoperable implementation must speak, not about what the protocol can express. Core v1.6 keeps the endpoint-specific path reachable behind an explicit experimental profile, so a suite that later clears review can be selected without another route-discovery revision --- the previous coupling of nonce to eligibility field meant any such suite required one. That is the practical value of the separation: it converts ``blocked pending a primitive'' into ``selectable pending a review''.

\section{Security analysis}
\label{sec:security}

\subsection{Endpoint material absent from discovery}

The active \textsc{Discover} grammar contains no $\tau$, $h_\tau$, destination address, destination key, gateway pseudonym, or endpoint handle. The routing nonce $\nu_i$ is non-semantic by construction, and under the mandatory \Rone{} suite the eligibility field $\eta_i$ is a second independent nonce, so neither field carries endpoint material. A byte-search conformance test verifies that an issued capability does not occur in the encoded discovery message.

The claim is scoped to the mandatory profile, and the separation of the two fields is what lets it be scoped rather than global. Under an experimental endpoint-specific suite the eligibility field is meaningful to its intended recipient by design; the routing nonce remains non-semantic regardless of suite, so the route-discovery half of the property is unconditional and only the eligibility half depends on which suite is selected. Before v1.6 no such scoping was possible, because one value served both roles.

This property is stronger than merely encrypting a destination selector against passive observation: compromised ordinary relays also receive no endpoint-specific selector from the protocol. They may still infer destination information from topology, timing, gateway choice, or external knowledge.

\subsection{Per-hop replacement argument}

At an honest relay, all adjacent capabilities and wire representations are replaced. The initiator must reconstruct the reply-key sequence, but one honest multiplicative blinding factor makes the outgoing public point exactly uniform over non-identity elements. This removes the public key itself as an equality handle. It does not prove that the encapsulated point and ciphertext are key-private, nor that the full nested composition resists malicious algebraic tags. Candidate authentication and failure normalization limit accepted modifications, while the explicit active-tag experiment focuses on the eligibility field.

\subsection{Capability confidentiality and replay}

The capability is absent from discovery and candidate traffic. It is sent only after \textsc{Ready} inside end-to-end route protection. Atomic commitment lookup and deletion enforce at most one successful redemption. This does not protect a capability stolen from an initiator before first use; the attacker may race the legitimate user. A production descriptor profile should bind redemption to an authenticated client handshake and use short expiries.

\subsection{Gateway and directory exposure}

A gateway learns the registration commitment and observes successful redemption. The directory learns which descriptor it delivers unless private information retrieval, oblivious access, replication, or another privacy mechanism is specified. The active protocol therefore provides no unlinkability guarantee against directory--gateway collusion. Multiple gateways, short-lived pseudonyms, descriptor rotation, and separated operators may reduce exposure but are not proofs.

\subsection{Cell-length and fragmentation leakage}

Fixed cell length prevents exact per-cell length classification. Multi-cell messages still reveal a fragment burst unless scheduling hides it. A candidate's cell count can correlate with reverse-layer depth. \Wtwo{} therefore supports but does not itself provide message-count or timing privacy.


\subsection{Multi-link schedule leakage}

\Tthree{} demonstrates that exact per-link bandwidth equality does not remove route information from adaptive trace shape. In the reference model, boundary-aligned rate changes, cross-link count correlation, and response to an injected demand pulse remain observable. The hybrid candidate reduces those simple signals by smoothing, independent decoy uplifts, and non-boundary phases, but it does not establish indistinguishability. The result is consistent with prior flow-correlation and traffic-manipulation literature, which treats timing and volume as first-class attack surfaces even when payloads are encrypted~\cite{deepcorr,dropmark,duster,raptor}.

\subsection{Failure normalization}

Malformed capability, wrong gateway, expiry, replay, signature failure, nested decryption failure, disabled suite, cross-suite fragment, non-canonical message, and invalid route label all map to a generic protocol rejection at their observation boundary. Implementations must also normalize timing and logging sufficiently to avoid turning internal diagnostics into an oracle.

\section{Resource and denial-of-service model}
\label{sec:resources}

\subsection{Why privacy consumes state}

A stable attempt identifier allows broad duplicate suppression but creates a correlation handle. \Uone{} removes that handle, so converging branches may allocate separate contexts. The protocol therefore treats resource bounds as normative security properties rather than implementation suggestions.

\subsection{Required bounds}

An implementation MUST define finite limits for:

\begin{itemize}
  \item authenticated cells per peer, direction, and time window;
  \item concurrent reassembly contexts and aggregate reserved bytes;
  \item message length, fragment count, reassembly duration, and completion-cache lifetime;
  \item live \Tone{} senders, pending acknowledgements, retry queues, recovery rounds, timer work, schedule rate, schedule duration, and chaff bandwidth;
  \item branch contexts per ingress peer, per node, and globally;
  \item fan-out, hop limit, expanding-ring attempts, and cumulative transmissions;
  \item candidate, tentative, pending-ready, and active route mappings;
  \item cryptographic operations and queue entries;
  \item gateway registration records, failed redemptions, and endpoint-handle lifetime;
  \item logical discovery time and all state deadlines.
\end{itemize}

\subsection{T3 analysis bounds}

\Tthree{} analysis state is not forwarding state and MUST NOT appear in network messages. An implementation or evaluator nevertheless bounds the super-epoch duration, number of observed links, retained trace history, feature dimension, training and test samples, lag range, probe amplitude and duty cycle, hybrid decoy budget, transition metadata, raw-report size, and queue state used during budget compensation. A report that silently omits failed cleanup, queue overflow, or budget mismatch is non-conforming.

\subsection{T4 analysis bounds}

\Tfour{} analysis state is not forwarding state. The evaluator bounds packet events, link and bottleneck queues, observed timestamps, trace duration, route classes, training/calibration/test samples, feature dimension, threshold candidates, phase and lag search, selective-delay amplitude and duty cycle, raw trace retention, drain time, and report size. Exhaustion invalidates or terminates the experiment; it MUST NOT change a protocol message to satisfy an analysis budget.

\subsection{Admission order}

Cheap syntactic and authenticated-link checks precede expensive group, signature, or nested-decryption operations. Per-peer token buckets limit fresh-branch creation. Global and per-node caps remain necessary because an adversary can distribute traffic across peers. A failed stage does not consume resources reserved for later stages.

\subsection{Amplification}

Let $f$ be fan-out, $d$ hop limit, and $a_i$ the fraction of branches admitted at depth $i$. An upper bound on forward branch transmissions is
\begin{equation}
T\le \sum_{i=1}^{d} f^i\prod_{j=1}^{i}a_j.
\label{eq:amplification}
\end{equation}
This bound ignores convergence and early responder termination, but shows why broad fixed flooding is unsuitable. Expanding rings and cumulative budgets reduce expected cost when gateways are sufficiently dense.

\section{Deterministic evaluation}
\label{sec:evaluation}

\subsection{Method and scope}

The repository contains deterministic event models and exact conformance vectors. The results are regression and falsification evidence, not production benchmarks, cryptographic proofs, or measurements of a deployed network. Each scenario fixes seeds, topology parameters, timers, budgets, and attacker actions.

\subsection{Expanding-ring discovery}

On 500-node random graphs with average degree eight and 100 runs per responder density, expanding rings reduced transmissions relative to a fixed broad flood while retaining high discovery success. At two percent responder density, success was 100 percent and mean transmissions fell from 895.12 to 157.65, an 82.39 percent reduction. State allocations fell by 72.28 percent. These figures justify an expanding-ring default, not a universal parameter choice.

\subsection{U1 state cost}

Removing a stable identifier increases branch-context state because converging branches cannot be globally merged. With hop limit four and fan-out three, the model observed an 85 percent success rate, 118.34 mean transmissions, and 15.60 percent state overhead relative to the identifier-bearing control. With hop limit five and fan-out four, 91 percent of runs exhausted the configured budget. Privacy and scalability therefore depend on conservative fan-out and strict cumulative limits.

\subsection{Lifecycle and attack admission}

The event-driven model evaluates delayed candidates, loss, duplication, cancellation, and fresh-branch attack traffic. In the fresh-branch attack scenario, a per-ingress token bucket increased route success from 32 to 76 percent and reduced mean total transmissions from 1,440.33 to 1,176.56. Every evaluated run reclaimed all route state.

\subsection{Message and cell capacity}

A six-layer candidate encoded to 909 logical bytes and fit in one cell. Seven layers encoded to 1,024 bytes and required two cells. Twelve layers required 1,599 bytes and two cells; sixteen layers required 2,059 bytes and three cells. Variable-length messages over fixed cells therefore remove the single-record route-depth limit.

Under independent two percent cell loss and no retransmission, clean route success decreased with hop count: 80 percent at two hops, 65 percent at five, 50 percent at eight, and 30 percent at twelve. This result motivates the active \Tone{} profile. Because the unrecovered and \Tone{} models use different release windows and timer semantics, their latency columns are not treated as direct performance measurements.

\subsection{T1 reliability under independent cell loss}

The reference path model executes the four route-setup operations---\textsc{Discover}, \textsc{Candidate}, \textsc{Commit}, and \textsc{Ready}---over line routes of two, five, eight, and twelve hops. Candidate size grows with route depth and crosses canonical fragmentation boundaries. \section{Limitations and open problems}
\label{sec:limitations}

\subsection{Private descriptor distribution}

The largest unresolved dependency is $Q$. \Rone{} removes endpoint-specific selectors from forward discovery, but an authorized initiator still needs the current capability, acceptable gateway pseudonyms, and gateway authentication material. Therefore Core alone provides no meaningful complete-system endpoint-anonymity claim.

\Done{} is a non-normative strawman. For each epoch the destination derives an unlinkable lookup handle and descriptor-encryption key from an authorization secret, encrypts a padded short-lived descriptor, and publishes the record to independently operated replicas. The preferred mode uses at least two non-colluding private-information-retrieval replicas, following the architectural precedent that private presence and rendezvous systems such as DP5 make directory trust and leakage assumptions explicit~\cite{dp5}. A weaker deployment mode sends a fixed-size encrypted lookup through an Oblivious HTTP relay; this separates the client's network address from the request content only while relay and gateway do not collude, and it does not hide the queried handle from the gateway~\cite{ohttp}.

Before \Done{} can become active, the protocol must select an exact query construction and specify publication padding, epoch overlap, authorization, revocation, rollback and equivocation handling, replica independence, source-address protection, enumeration resistance, and denial-of-service limits. Directory--gateway correlation, synchronized publication and lookup timing, or colluding replicas can still identify the endpoint. These are load-bearing security assumptions, not optional operational details.

\subsection{Gateway correlation}

A gateway can correlate registration time, redemption time, endpoint handle, and route-local observations. Multiple gateways and short epochs limit concentration but do not remove this visibility. A gateway may also selectively refuse service or create distinguishing delays.

\subsection{Reliability, congestion, and scheduling}

\Tone{} supplies bounded adjacent-link selective recovery, and \Ttwo{} now defines finite fixed, adaptive, and work-conserving release policies. The result remains an experimental link-local model rather than an end-to-end congestion controller. Schedule-control loss, simultaneous offers, restart after peer state loss, strategic weight assignment, and adversarial ACK behavior require fuller state machines. Forward error correction and bounded redundancy remain unevaluated alternatives to retransmission. Fixed scheduling can waste substantial bandwidth, adaptive scheduling exposes public rate transitions, and work-conserving scheduling exposes cell presence directly. Timing and count correlation across links remain outside the claim. \Tthree{} measures equal-budget count traces. \Tfour{} adds packet timestamps, heterogeneous observer clocks, shared bottlenecks, route churn, partial observation, open-world rejection, and one bounded selective-delay detector. Neither covers calibrated Internet topologies, strong learned open-set classifiers, adaptive watermarks, long-term concept drift, or deployment traces.

\subsection{Reply-key analysis}

Multiplicative blinding establishes an exact uniform distribution for the public reply key after one honest relay. The custom reply KEM still requires an independent key-privacy and multi-user chosen-ciphertext analysis, including malicious point selection, active tagging, transcript substitution, failure timing, and side channels. Standard components do not automatically prove security of their composition.

\subsection{Post-quantum migration}

The active reply, signature, and link profiles are classical. Cryptographic agility is encoded, but a post-quantum suite must define exact key sizes, candidate expansion, cell impact, and transition rules. Merely adding an identifier is not a migration strategy.

\subsection{Network economics and policy}

The protocol does not define transit incentives, inter-domain policy, Sybil resistance, gateway admission, reputation, or abuse adjudication. These concerns can dominate deployment viability even when the control-plane mechanics are sound.

\section{Reference implementation and measured behaviour}
\label{sec:reference}

The mandatory profile is implemented as three separately started user-space processes --- initiator endpoint, relay, and rendezvous gateway --- communicating over UDP with fixed-length \Tone{} records. The implementation is the reason several statements in this paper are testable rather than merely specified, and it is the source of the numbers below. It is a research prototype: it is not hardened, not audited, and carries no production claim.

All numeric identifiers, field widths, and limits are generated from one machine-readable registry, which also generates the corresponding constants for the independent reference model and the human-readable registry document. A repository check regenerates all three and compares them byte for byte, so a constant cannot drift between the specification and either implementation. The canonical and malformed conformance corpus is produced by a separate encoder that reads only the registry, so a decoder bug and an encoder bug cannot cancel.

\subsection{Profile gating in the implementation}

The mandatory profile admits \Rone{} alone. Selecting C1~v2 or adaptive \Ttwo{} requires explicitly requesting an experimental profile, and each has its own continuous-integration job with its own assertions rather than sharing the mandatory ones. Retired and disabled suite identifiers are refused on every profile, and the two experimental paths are exercised by arms that assert what they claim: for C1, one run in which the gateway is the intended recipient and serves the route, and one in which it is not and declines with the eligibility-specific identifier rather than the generic malformed-message one.

Separating those identifiers matters for the reasons of \cref{sec:security}: a node that is not the intended recipient and a node that received a malformed message are different events for an operator and identical on the wire, and conflating them in the implementation would have made the second indistinguishable from a bug.

\section{Implementation and review strategy}
\label{sec:implementation}

A staged implementation should preserve module boundaries:

\begin{enumerate}
  \item independent \Mtwo{}, \Wtwo{}, \Tone{}, and \Ttwo{} codec implementations with differential tests and fuzzing;
  \item a typed eligibility-provider boundary containing active \Rone{} and research-only controls;
  \item a deterministic \Eone{} state machine separated from transport I/O;
  \item constant-time or timing-normalized cryptographic failure paths;
  \item a persistent, atomic gateway capability store with concurrency tests;
  \item an independent implementation and game-based review of the reply KEM, multiplicative blinding chain, and candidate transcript;
  \item a concrete private-directory prototype derived from \Done{}, including directory--gateway collusion and enumeration tests;
  \item property-based and network-emulation tests for selective ACKs, timeout ambiguity, replay, and bounded retry cleanup;
  \item a complete schedule-negotiation state machine covering loss, simultaneous offers, rejection, restart, and peer disagreement;
  \item differential scheduler tests for weighted service, queue admission, maximum-class overload, and fixed-profile breaks;
  \item reproducible \Tthree{} equal-budget experiments with disjoint training and test data;
  \item independent reproduction of \Tfour{} packet events in a higher-fidelity emulator, with calibrated topology, capacity, jitter, clocks, shared bottlenecks, partial observation, and route churn;
  \item stronger learned open-world classifiers and adaptive selective-delay, loss, congestion, and watermarking adversaries;
  \item external cryptographic, transport, side-channel, and protocol review before any production claim.
\end{enumerate}

The disabled C2 transcription should remain reproducible and should be described as a project interpretation/transcription audit, not as evidence of a defect in the cited construction. An author query should identify the exact equation, parameter chain, interpretation, counterexample, and executable checker, and ask whether an omitted embedding, different group action, or erratum resolves the discrepancy. A correction may reopen an endpoint-specific suite, but must not silently change the active \Rone{} security model.

\section{Conclusion}
\label{sec:conclusion}

\ProtoName{} defines bounded route discovery with no transmitted source route or network-wide discovery identifier. The protocol removes endpoint-specific material from forward exploration, discovers generic rendezvous gateways, authenticates candidates through nested reverse encryption, activates one selected route through \textsc{Commit} and \textsc{Ready}, and presents a single-use capability only after activation.

The semantic, fragmentation, recovery, and scheduling layers are distinct. Logical messages remain canonical and variable length; canonical fragments are bounded and reassembled before route semantics execute; and every adjacent-link cell has fixed length. Cumulative selective acknowledgements and bounded retries repair missing fragments without copying a recovery identifier across a relay. \Ttwo{} then chooses fixed, quantized-adaptive, or work-conserving release, bounds rate transitions and overload, and divides admitted new DATA with weighted deficit round robin.

Route, reassembly, sender, acknowledgement, retry, negotiation, queue, schedule, registration, and redemption state have explicit lifetimes and budgets. The measured reliability and overload improvements are accompanied by explicit retry, queueing, chaff, and public-rate costs. The security claims distinguish per-hop representation replacement and conditional fixed-epoch shape from adaptive-rate leakage and global traffic-flow anonymity, exposing the directory/gateway and congestion-management trust boundaries rather than hiding them. In particular, Core does not complete endpoint anonymity until a private descriptor-distribution profile is implemented and reviewed. \Tthree{} demonstrates that equal total bandwidth is not equal count-trace shape. \Tfour{} then shows that packet timestamps, clock assumptions, partial observation, route churn, and unknown routes materially change the evaluation. Its bounded selective-delay detector is retained as a regression test but supplies no active-security theorem.

The unresolved universal-rerandomization candidates remain cited, executable, and falsifiable but are not active dependencies. The resulting document is a coherent interoperability and review baseline, not a production-ready anonymity guarantee.

\section{Canonical encoding note}

\Mtwo{} uses minimal unsigned base-128 LEB128 for variable lengths. Every decoder rejects a longer encoding, an unterminated value, a value above its field limit, trailing bytes, or a nested length exceeding its container. Fixed-width numeric fields are unsigned big-endian values.

\Wtwo{} defines the unique 992-byte fragment decomposition. \Tone{} and \Ttwo{} use fixed-width unsigned big-endian integers in the public 12-byte header and encrypted 32-byte common header. The suite identifier in every \textsc{Data} fragment must agree with the completed \Mtwo{} message. Every non-final fragment contains exactly 992 message bytes and the final fragment exactly the remainder. \textsc{Ack} bits outside the declared fragment count are invalid. A \textsc{Schedule} request must name the current class and either the same or one adjacent class, and its maximum class must be canonical for the configured menu. The 1,052-byte record length hides frame class and exact per-cell content length. Work-conserving mode reveals cell presence; adaptive mode additionally reveals the public class sequence; fixed mode leaves epoch boundaries, direction, topology, and overload behavior visible. \Tthree{} and \Tfour{} operate only on resulting public traces and introduce no additional wire encoding.

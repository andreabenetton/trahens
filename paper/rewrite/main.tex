\begin{abstract}
Route discovery can disclose endpoint relationships, local topology, and stable correlation handles before an anonymous data path is established. The original \ProtoName{} draft proposed a network-layer control plane based on local flooding, ephemeral routing labels, reverse acknowledgements, distributed registration, and traffic-analysis countermeasures. This revision retains the formal objective of privacy-enabled route discovery while reducing the mechanism to a bounded and falsifiable core.

Core v0.4 retains the branch-local U1 construction: every outgoing discovery branch replaces its capability, blinds the reply public key, rerandomizes the responder-eligibility capsule, reconstructs the canonical message, and transmits a fresh fixed-size ciphertext through a mixing boundary. Candidate return uses a nested encrypted key-blinding chain. The new E1 lifecycle defines half-open state deadlines, deterministic equal-time precedence, candidate windows, delayed candidates across initiator-local rings, cancellation races, tentative reverse mappings, forward COMMIT reservation, reverse READY activation, loss, exact duplication, and local cleanup. The initiator does not expose a route to the data plane until it authenticates the final READY.

The unlinkability statement remains conditional on a reviewed universally rerandomizable encryption construction, a tweakable reply KEM, and a traffic-scheduling profile. The event-lifecycle statement is narrower: under the modeled delay, loss, duplication, expiry, and attack events, every state transition has a deterministic bounded outcome. In 100 deterministic 500-node runs, clean route setup succeeded in 89\% of cases; 2\% loss with 5\% exact duplication reduced success to 80\%. A concentrated fresh-branch attack reduced success to 32\%; a one-token ingress-peer bucket raised it to 76\% and reduced attack transmissions by approximately 25\%. Every evaluated scenario reclaimed all branch, responder-offer, initiator-candidate, tentative, pending, and active state. These results establish a reproducible lifecycle and resource baseline, not a production security or performance claim.
\end{abstract}

\section{Introduction}
\label{sec:introduction}

Low-latency anonymity systems commonly separate route or circuit establishment from data forwarding. This separation is operationally useful, but it creates a privacy boundary: the mechanism that discovers a destination, gateway, service, or sequence of intermediaries may expose stable identifiers and topology even when the resulting data path is encrypted. Network-layer systems such as HORNET and TARANET demonstrate that anonymous forwarding and traffic-analysis countermeasures can be integrated with high-speed network architectures, whereas Sphinx and Loopix provide formal and system-level foundations for per-hop unlinkability, fixed-size packets, mixing, and cover traffic~\cite{hornet,taranet,sphinx,loopix}.

The 2020 \ProtoName{} draft addressed this boundary directly. Its central proposal was to distribute routing state among intermediate nodes, use short-lived labels rather than a complete source route, and transform discovery messages so that non-adjacent observations could not be matched by a stable bit pattern. The draft was, however, incomplete: global registration and resolution were unspecified; cryptographic functions were abstract; non-hardened BIP32-style derivation was used outside its original domain; resource bounds were absent; and the stated unlinkability property did not separate cryptographic message transformation from timing correlation.

A subsequent Core v0.2 revision introduced bounded expanding rings, cumulative budgets, explicit route commitment, and fresh identifiers between retries. Those changes improved correctness and denial-of-service analysis, but a single wire-visible identifier remained constant inside each attempt. That identifier contradicted the original non-adjacent message-unlinkability objective.

Core v0.3 corrected the stable-identifier defect. Core v0.4 retains that construction and adds a complete event-driven setup lifecycle. The current contribution is sevenfold:

\begin{enumerate}[leftmargin=*,itemsep=0.35em]
  \item it replaces attempt-wide wire identity with peer-bound branch contexts;
  \item it defines a per-hop reply-key blinding chain that the initiator can reverse during candidate processing;
  \item it requires a rerandomizable eligibility capsule so that the destination selector is not itself a stable ciphertext;
  \item it formalizes wire-image, batch-local, lifecycle, and traffic-flow properties separately;
  \item it defines candidate windows and delayed-candidate behavior without transmitting a ring identifier;
  \item it makes route use conditional on forward COMMIT and reverse READY, with deterministic expiry and cancellation;
  \item it quantifies both branch-local amplification and fresh-token denial-of-service under explicit admission limits.
\end{enumerate}

The protocol remains a research design. In particular, universally rerandomizable encryption (URE) is treated as a named cryptographic dependency rather than silently approximated by repeated hashing or ordinary HPKE. Recent work has clarified that URE security must include anonymity and composable application-level requirements~\cite{ure2023}; HPKE remains appropriate for ordinary recipient encryption but does not itself specify universal ciphertext rerandomization~\cite{hpke}.

\section{Background and related work}
\label{sec:background}

\subsection{Anonymous network-layer forwarding}

HORNET establishes anonymous channels while avoiding per-flow state in intermediate routers during data forwarding, using symmetric cryptography on the fast path~\cite{hornet}. TARANET extends the network-layer setting with mixing during setup and coordinated constant-rate transmission during data forwarding~\cite{taranet}. These systems demonstrate that the control plane and data plane require different mechanisms and performance analyses.

\subsection{Per-hop packet unlinkability}

Sphinx defines a compact mix packet format with path-length hiding, indistinguishable replies, replay resistance, and per-hop unlinkability under a formal model~\cite{sphinx}. Loopix combines Sphinx packets with Poisson mixing, cover traffic, and stratified topology to obtain stronger resistance to traffic analysis~\cite{loopix}. \ProtoName{} differs in that the route is not known to the initiator before discovery; it must therefore transform a branching exploration rather than a preselected path.

\subsection{Rerandomizable encryption}

A universally rerandomizable encryption scheme permits a party without the decryption key to transform a ciphertext into a fresh ciphertext of the same plaintext under the same public key. This property is directly relevant to a hidden responder selector that must survive multiple forwarding hops without remaining bitwise stable. Security definitions for URE require care: rerandomization alone is not sufficient if encryption anonymity, malformed-ciphertext behavior, or active tagging permit linkage~\cite{ure2023}. Core v0.4 therefore specifies the required interface and proof obligations but does not select a production construction.

\section{Problem definition}
\label{sec:problem}

\subsection{Network model}

Let the communication substrate be an undirected graph
\[
G=(V,E),
\]
where a node \(n\in V\) may act as an endpoint, relay, or responder, and an edge \((u,v)\in E\) denotes an authenticated adjacent-link association. A route from initiator \(n_0\) to responder \(n_d\) is an ordered sequence
\[
\rho=(n_0,n_1,\ldots,n_d)
\]
such that \((n_i,n_{i+1})\in E\) for every \(0\le i<d\). The complete sequence \(\rho\) is a mathematical object used for analysis; it is not carried in a protocol message or stored by a relay.

The degree of node \(n\) is denoted \(\lvert n\rvert\). The maximum propagation depth is \(d_{\max}\). A relay selects at most \(f\) children for one admitted branch. All values that bound propagation, state, and cryptographic work are finite.

\subsection{Underlay contract}

The baseline underlay provides authenticated encryption, message boundaries, a link epoch, replay-domain sequence numbers, and peer connection events. The stronger \Uone{} profile additionally provides fixed-size record classes, batching, permutation, release scheduling, and declared chaff behavior. Adjacent-link encryption alone is not interpreted as traffic-flow anonymity.

\subsection{Threat model}

The principal adversaries are:

\begin{itemize}[leftmargin=*]
  \item a passive or active compromised relay;
  \item multiple colluding relays at declared positions;
  \item a partial or global link observer that sees timing and size;
  \item a resource adversary that creates branches, candidates, malformed capsules, or incomplete commitments;
  \item a compromised endpoint.
\end{itemize}

The \Uone{} message-unlinkability game is narrower: the challenge messages are transformed by at least one honest relay, the adversary is passive with respect to those messages, and precise timing and queue side channels are excluded. Active tagging and global timing correlation are separate research problems.

\subsection{Security and privacy goals}

\begin{definition}[Route-position privacy]
A relay has route-position privacy if its protocol state reveals no complete ordered route and no non-local forwarding label. The relay may learn its predecessor, selected successors, local timing, and local state lifetime.
\end{definition}

\begin{definition}[Wire-image unlinkability]
Two non-adjacent protocol messages have wire-image unlinkability if no deterministic protocol field, unchanged opaque ciphertext, or reusable capability provides an equality test that links them across an honest transformation boundary.
\end{definition}

\begin{definition}[Batch-local message unlinkability]
Let an honest relay receive a batch of \(s\ge2\) conforming records, independently transform each record, and release a uniform random permutation. An adversary has batch-local advantage
\[
\Adv^{\Uone}_{\mathcal A}
=
\left|\Pr[\mathcal A\text{ matches a challenge input to its output}]-\frac{1}{s}\right|.
\]
The profile achieves batch-local unlinkability when this residual advantage is negligible under its declared cryptographic assumptions.
\end{definition}

\begin{remark}
Batch-local message unlinkability does not imply traffic-flow unlinkability. A global observer may correlate fixed-size ciphertexts using timing, volume, topology, or induced delays even when the ciphertext bodies are cryptographically unrelated.
\end{remark}

\section{Protocol design}
\label{sec:design}

\subsection{Phase overview}

The protocol consists of four control-plane phases:

\begin{enumerate}[leftmargin=*]
  \item \textbf{branch discovery}: the initiator propagates independently transformed \textsc{Discover} records;
  \item \textbf{candidate return}: eligible responders return end-to-end protected offers while relays install tentative local mappings;
  \item \textbf{commit}: the initiator selects one candidate and reserves pending route mappings;
  \item \textbf{ready}: the responder confirms the transcript and activates mappings in the reverse direction.
\end{enumerate}

\subsection{Branch initiation}

For each selected first-hop peer, the initiator creates independent cryptographic material. In particular, it does not reuse a root reply key or eligibility ciphertext among first-hop branches.

\begin{algorithm}[ht]
\caption{Initiator: create one first-hop branch}
\label{alg:init}
\begin{algorithmic}[1]
\Require first-hop peer \(n_1\), logical budget \(\mathcal B\), eligibility public key \(pk_E\)
\If{\(\mathcal B\) cannot reserve one branch}
  \State \Return failure
\EndIf
\State \(x_0\sample\Zq^*\); \(P_0\gets x_0G\)
\State \(\tau_0\sample\{0,1\}^{128}\)
\State \(Q_0\gets \mathsf{URE.Enc}(pk_E,\mathsf{EligibilityRequest})\)
\State \(M_0\gets\Encode(\mathsf{DISCOVER},\tau_0,P_0,Q_0,\mathsf{bounds})\)
\State \(M_0\gets\mathsf{PadToClass}(M_0)\)
\State store \((n_1,\tau_0,x_0,\mathsf{expiry})\) in local branch table
\State enqueue \(\mathsf{LinkSeal}_{n_1}(M_0)\)
\end{algorithmic}
\end{algorithm}

\subsection{Relay transformation}

A relay first rejects malformed, replayed, expired, or over-budget input. It then creates one branch context. It does not search for an attempt-wide duplicate because such a key would reintroduce a stable correlation handle.

For incoming reply key \(P_i\), child \(j\), and fresh \(\delta_{i,j}\sample\Zq^*\), the relay computes
\begin{equation}
P_{i+1,j}=P_i+\delta_{i,j}G.
\label{eq:keyblind}
\end{equation}
The eligibility capsule is transformed as
\begin{equation}
Q_{i+1,j}\gets\ReEnc(pk_E,Q_i;r_{i,j}).
\label{eq:rerand}
\end{equation}

\begin{algorithm}[ht]
\caption{Relay: transform and forward one admitted branch}
\label{alg:relay}
\begin{algorithmic}[1]
\Require ingress peer \(p\), token \(\tau_i\), key \(P_i\), capsule \(Q_i\), bounds
\If{link replay, expiry, parse, or budget check fails}
  \State discard without amplified response
\EndIf
\State allocate \(b\gets\BranchT[p,\tau_i]\)
\State \(S\gets\mathsf{SelectChildren}(V(n_i)\setminus\{p\},f)\)
\ForAll{\(c\in S\)}
  \State \(\tau_c\sample\{0,1\}^{128}\)
  \State \(\delta_c\sample\Zq^*\)
  \State \(P_c\gets P_i+\delta_cG\)
  \State \(Q_c\gets\ReEnc(pk_E,Q_i;r_c)\)
  \State store \((c,\tau_c,\delta_c,P_c)\) in \(b\)
  \State \(M_c\gets\Encode(\mathsf{DISCOVER},\tau_c,P_c,Q_c,\mathsf{nextBounds})\)
  \State reconstruct, pad, and enqueue \(\mathsf{LinkSeal}_{c}(M_c)\) into the mixing batch
\EndFor
\end{algorithmic}
\end{algorithm}

\subsection{Loop and duplicate behavior}

Exact retransmission on the same adjacent-link epoch is rejected using the link sequence and branch token. A message that reaches a relay over another peer or another token is an independent branch. The relay excludes the ingress peer from child selection, preventing immediate backtracking. Longer cycles and branch convergence remain possible and are bounded by \(d_{\max}\), fan-out, per-node context limits, global state limits, and transmission budgets.

This choice is fundamental. Attempt-wide first-parent suppression is efficient but provides a stable equality domain. Branch-local processing removes that domain at the cost of repeated state.

\subsection{Candidate construction and return}

An eligible responder opens \(Q_d\), constructs an authenticated candidate payload \(M_d\), and seals it to the received reply public key:
\begin{equation}
C_d=\Seal(P_d,M_d,\mathsf{aad}_d).
\label{eq:respcapsule}
\end{equation}
A relay at depth \(i\) returning a child capsule \(C_{i+1}\) constructs
\begin{equation}
C_i=\Seal\left(P_i,\Encode(\delta_i,C_{i+1},\Lambda_i),\mathsf{aad}_i\right),
\label{eq:nestedcapsule}
\end{equation}
where \(\Lambda_i\) contains only protected local offer parameters required by the initiator. The relay replaces the candidate token and creates tentative forward labels.

\begin{algorithm}[ht]
\caption{Relay: return a candidate through one branch}
\label{alg:candidate}
\begin{algorithmic}[1]
\Require child mapping \((c,\gamma_c,\delta_i,P_i)\), child capsule \(C_{i+1}\)
\If{candidate replay, mapping, expiry, or budget check fails}
  \State discard
\EndIf
\State \(\gamma_p\sample\{0,1\}^{128}\)
\State \(L_i^+\sample\{0,1\}^{128}\)
\State \(C_i\gets\Seal(P_i,\Encode(\delta_i,C_{i+1},L_i^+,\mathsf{limits}),\mathsf{aad}_i)\)
\State store tentative mapping \((\gamma_p,L_i^+,c,\gamma_c,\mathsf{expiry})\)
\State reconstruct, pad, and send \(\mathsf{CANDIDATE}(\gamma_p,C_i,L_i^+)\) to parent
\end{algorithmic}
\end{algorithm}

The initiator opens the chain iteratively.

\begin{algorithm}[ht]
\caption{Initiator: open a nested candidate capsule}
\label{alg:open}
\begin{algorithmic}[1]
\Require root secret \(x_0\), outer capsule \(C_0\), maximum depth \(d_{\max}\)
\State \(i\gets0\)
\While{\(i\le d_{\max}\)}
  \State \(Y\gets\Open(x_i,C_i,\mathsf{aad}_i)\)
  \If{\(Y\) is an authenticated responder candidate}
    \State \Return candidate
  \ElsIf{\(Y=\Encode(\delta_i,C_{i+1},\Lambda_i)\)}
    \State validate \(\delta_i\) and transcript context
    \State \(x_{i+1}\gets x_i+\delta_i\pmod q\)
    \State \(i\gets i+1\)
  \Else
    \State \Return generic failure
  \EndIf
\EndWhile
\State \Return generic failure
\end{algorithmic}
\end{algorithm}

The concrete KEM must ensure that public-key tweaking, key privacy, CCA security, and nested failure behavior satisfy the declared security model. Equation~\eqref{eq:keyblind} is therefore a protocol requirement and proof obligation, not an instruction to improvise a construction over X25519.

\subsection{Commit and readiness}

The initiator chooses at most one authenticated candidate and sends \textsc{Commit} through the first-hop tentative label. Each relay validates the incoming peer, route generation, local label, and protected transcript. It reserves route capacity, changes the mapping from \textsc{Tentative} to \textsc{Pending-Ready}, assigns a finite ready-hold deadline, and forwards the protected commit body. A global candidate identifier is unnecessary.

The responder verifies a commit challenge supplied inside the candidate payload and returns \textsc{Ready} through reverse labels. A relay accepting \textsc{Ready} changes the matching pending mapping to \textsc{Active}. The initiator MUST NOT expose the route to the data plane before authenticating the final \textsc{Ready}. If \textsc{Commit} or \textsc{Ready} is lost, pending or partially active state is reclaimed by local deadlines.

\section{Event lifecycle}
\label{sec:lifecycle}

\subsection{Time and equal-time precedence}

Let a local state be created at time $t_c$ with expiry $t_e$. Under E1 the state is valid exactly when
\begin{equation}
t_c \le t < t_e.
\label{eq:halflife}
\end{equation}
It is invalid at $t=t_e$ and cannot be revived by a delayed message. Synchronised clocks are unnecessary because a received lifetime class is converted into a local deadline. If a valid transition replaces $t_e$, an expiry event bound to the prior state generation is stale and MUST NOT shorten the replacement deadline.

For events assigned the same local timestamp, E1 defines the strict precedence
\begin{equation}
\mathsf{Expire} \prec \mathsf{Cancel} \prec \mathsf{Control} \prec
\mathsf{Candidate} \prec \mathsf{Discover} \prec \mathsf{WindowClose}.
\label{eq:eventorder}
\end{equation}
Consequently, a message at its state deadline fails, whereas a candidate at the exact candidate-window deadline remains eligible.

\subsection{Candidate windows and delayed candidates}

A ring $r$ is local initiator policy
\[
\mathcal R_r=(d_r,f_r^{(0)},f_r,\Delta_r),
\]
where $d_r$ is the hop bound, $f_r^{(0)}$ and $f_r$ are initial and relay fan-out, and $\Delta_r$ is the candidate-window duration. The tuple and its index are never transmitted. If a ring starts at $a_r$, its decision boundary is $w_r=a_r+\Delta_r$.

A candidate from any started ring is eligible at $w_r$ if no decision has been made, its offer deadline exceeds $w_r$, and every required tentative mapping survived the reverse traversal. Thus a delayed candidate from ring $r-1$ may be selected during ring $r$. Selection freezes the decision, sends \textsc{Commit} on the selected path, and sends \textsc{Cancel} through stored adjacent mappings into maximal off-route live subtrees belonging to that logical discovery.

\begin{algorithm}[ht]
\caption{Initiator: process one candidate-window boundary}
\label{alg:window}
\begin{algorithmic}[1]
\Require ring index $r$, valid local candidate set $\mathcal C$, ring schedule $\mathcal R$
\State remove candidates whose authenticated offer has expired
\If{$|\mathcal C|\ge k_{req}$ or ($r$ is final and $|\mathcal C|>0$)}
  \State $c^*\gets\mathsf{Select}(\mathcal C)$
  \State freeze $c^*$; reject later candidates
  \State send \textsc{Cancel} into every maximal live subtree not on $c^*$
  \State send \textsc{Commit} through the tentative path of $c^*$
\ElsIf{another ring exists}
  \State start ring $r+1$ with independent first-hop branch material
\Else
  \State terminate with \textsc{No-Candidate}; cancel live branches
\EndIf
\end{algorithmic}
\end{algorithm}

\subsection{Cancellation races and cleanup}

\textsc{Candidate} and \textsc{Cancel} may cross. If the candidate traverses a context first, the relay may create tentative state; if cancellation removes the context first, the candidate is discarded. A candidate reaching the initiator after selection is late and cannot change the decision. Correctness does not depend on cancellation delivery because branch, offer, tentative, pending, active, replay, and initiator-transaction states have independent finite deadlines. An initiator cannot cancel unrelated or attacker-created branch contexts; those are reclaimed only by their owners, local admission policy, or expiry.

\begin{proposition}[Bounded cleanup]
Assume finite state deadlines and finite event delivery or loss decisions. After the initiator terminates and no data-plane renewal occurs, every branch, tentative, pending, and active state created by that logical discovery is eventually removed without peer cooperation.
\end{proposition}

\begin{proof}
Every state class has a current local deadline and a generation-bound expiry event. A successful cancellation or abort may remove it earlier. A stale timer cannot shorten a valid replacement deadline, a lost control record cannot extend the current deadline, and a delayed record cannot recreate state after Equation~\eqref{eq:halflife} fails. The finite union of finite-lived entries therefore becomes empty after the maximum remaining deadline.
\end{proof}

\section{Unlinkability profile}
\label{sec:unlinkability}

\subsection{Required per-hop transformation}

An honest \Uone{} relay independently performs the following operations for each child:

\begin{enumerate}[leftmargin=*]
  \item replace the branch token;
  \item blind the reply public key;
  \item rerandomize the eligibility capsule;
  \item replace candidate and route capabilities when returning state;
  \item reconstruct the body canonically;
  \item pad to the declared record class;
  \item encrypt using a fresh adjacent-link nonce;
  \item release through a batch permutation.
\end{enumerate}

An unchanged variable-length field invalidates the unlinkability claim unless the field's selected primitive explicitly proves rerandomization unlinkability.

\subsection{Conditional security argument}

\begin{assumption}[Primitive security]
The selected URE scheme provides ciphertext anonymity and rerandomization indistinguishability in the declared passive game. The reply-key KEM provides key privacy and CCA-secure sealing under additive public-key tweaks. Link AEAD provides ciphertext integrity and fresh-nonce confidentiality.
\end{assumption}

\begin{proposition}[Direct matching resistance]
Consider two observations of one logical branch separated by more than two forwarding positions. If at least one intermediate relay is honest, all fields listed in Section~\ref{sec:unlinkability} are independently transformed, records have the same observable class, and timing is excluded, then the message bodies expose no deterministic equality test. Under Assumption~1, the remaining cryptographic matching advantage is negligible.
\end{proposition}

\begin{proof}[Argument]
The branch and candidate tokens are independently uniform and link-local. The outgoing reply key is the sum of the incoming public key and an independent random group element. The eligibility ciphertext is rerandomized. The canonical body, padding randomness, adjacent-link nonce, and adjacent-link ciphertext are fresh. Therefore no protocol-visible value is preserved as an equality handle. A non-negligible residual body-matching advantage would distinguish at least one selected primitive from its assumed random or rerandomized distribution. The statement does not include timing, batch position, or active modification.
\end{proof}

\begin{proposition}[Batch correspondence]
If an honest relay transforms \(s\ge2\) conforming records and releases a uniform random permutation without a timing side channel, then a passive adversary's baseline correspondence probability is \(1/s\), plus the residual cryptographic advantage of Proposition~1.
\end{proposition}

\begin{remark}
The propositions are proof obligations for a concrete suite, not a completed reduction. In particular, active tagging can invalidate the argument if malformed rerandomized ciphertexts preserve an adversarial marker. The current profile therefore does not claim active-adversary unlinkability.
\end{remark}

\section{Resource and denial-of-service model}
\label{sec:resources}

Removing attempt-wide duplicate suppression changes the resource invariant. A physical relay may admit several independent branch contexts for one logical discovery because converging branches are intentionally not linked. Let \(B\) be accepted branch contexts and \(U\) be unique relays. The context-amplification measure is
\begin{equation}
A_c=\frac{B}{U}.
\label{eq:amplification}
\end{equation}
A first-parent identifier-based flood tends toward \(A_c=1\); \Uone{} can exceed one.

A conforming relay enforces finite limits at the peer, link-epoch, branch, physical-node, time-window, mixing-queue, and node-global levels. Budget checks precede URE rerandomization, group operations, signature verification, and full state allocation whenever the encoding permits. Recommended eviction order removes malformed input, excess chaff, new over-budget branches, additional candidates, and tentative state before admitted active routes.

The protocol excludes only immediate backtracking. Longer cycles are not hidden by a stable path vector and are instead bounded by hop count and budgets. This is less efficient than global duplicate suppression but consistent with the privacy objective.

A fresh-token adversary is not an exact replay. Before expensive processing, E1 therefore admits a fresh branch through an ingress-peer token bucket. For capacity $b$, refill amount $a$, and refill interval $r$, the token count is capped by $b$ and one admitted branch consumes one token. The bucket is scoped at least to the link epoch, ingress peer, and receiving node. Per-peer admission is combined with per-node and node-global capacities because a distributed adversary can aggregate many buckets.

Cumulative allocation is insufficient as a safety measure. E1 separately records the peak concurrent counts
\[
S_{peak}=\max_t(S_B(t),S_T(t),S_P(t),S_A(t)),
\]
where $S_B,S_T,S_P,S_A$ are live branch, tentative, pending-ready, and active state. Final state counts and cleanup completion are mandatory evaluation outputs.

\section{Limitations and open problems}
\label{sec:limitations}

\subsection{Concrete cryptographic suite}

The largest unresolved dependency is the selection of a URE scheme and a tweakable reply KEM with a reviewable proof and test vectors. Ordinary HPKE provides interoperable hybrid public-key encryption but does not supply the universal rerandomization required for the eligibility capsule~\cite{hpke}. A concrete profile must also define route-depth padding, canonical scalar validation, error indistinguishability, and post-quantum migration.

\subsection{Active tagging}

A malicious relay may modify a rerandomizable ciphertext or its surrounding fields so that a downstream colluder recognizes the result. The protocol needs either a primitive whose active security definition covers this behavior or a verifiable transformation mechanism that does not introduce a stable proof handle. Until then, the unlinkability claim is passive.

\subsection{Timing and traffic analysis}

Fixed-size records and cryptographic transformation do not remove timing. TARANET and Loopix illustrate two distinct design spaces: coordinated constant-rate traffic shaping and stochastic mixing with cover traffic~\cite{taranet,loopix}. \ProtoName{} should treat these as deployable privacy profiles with explicit latency, bandwidth, and correlation measurements rather than one mandatory and unevaluated assumption.

\subsection{Long-range resolution}

The legacy beacon and authority design is not part of Core v0.4. Deterministic repeated hashes of endpoint addresses can become stable query handles and enumeration targets. A future resolution protocol requires independent ownership, freshness, replication, poisoning, selective-denial, and private-query analysis.

\subsection{Distributed denial of service and fairness}

Ingress-peer buckets mitigate a concentrated fresh-token source but do not provide Sybil resistance or distributed-denial resistance. Bucket parameters can also reject legitimate converging branches. Future experiments must vary attacker distribution, peer churn, adaptive refill, responder spam, and candidate spam, and must report fairness by ingress peer rather than only aggregate success.

\section{Conclusion}
\label{sec:conclusion}

\ProtoName{} is best understood as a research protocol for privacy-enabled route discovery, not as an immediate replacement for IP or BGP. Core v0.4 combines two separate advances. U1 removes attempt-wide identifiers and transforms every forwarding representation, restoring the structure required for non-adjacent message unlinkability. E1 defines event time, candidate windows, delayed reverse messages, cancellation races, tentative and pending state, final readiness, loss, duplication, fresh-token admission, and deterministic cleanup.

The simulations expose the corresponding systems costs. Unlinkability is inexpensive for narrow exploration but broad U1 flooding can approach global resource limits. Event-driven setup behaves deterministically under the modeled faults, but fresh-token attacks can dominate capacity even when exact replay is solved. Per-peer buckets materially improve availability without eliminating the attack. The next release gate is therefore cryptographic and adversarial: select concrete URE and reply-KEM constructions, publish canonical vectors, test active tagging, and extend abuse analysis to distributed identities before implementing network I/O.

\section{Normative requirement summary}

The keywords ``MUST'', ``MUST NOT'', ``REQUIRED'', ``SHOULD'', ``SHOULD NOT'', and ``MAY'' are interpreted according to BCP~14~\cite{rfc2119,rfc8174}.

A Core v0.4 implementation using U1 and E1 MUST:

\begin{enumerate}[leftmargin=*]
  \item omit logical-discovery and attempt identifiers from the wire;
  \item replace every branch and candidate token at every hop;
  \item use independent root reply keys for first-hop branches;
  \item blind the reply key independently for every child;
  \item rerandomize the eligibility capsule independently for every child;
  \item reconstruct and pad fixed-size canonical records;
  \item use fresh adjacent-link nonces and replay domains;
  \item enforce finite branch, transmission, cryptographic-work, queue, and route limits;
  \item make batch-local unlinkability claims only when an honest mixing boundary contains at least two indistinguishable records;
  \item treat every state deadline as a half-open validity boundary and define equal-time precedence;
  \item keep ring and window identifiers local to the initiator;
  \item create tentative state on CANDIDATE, reserve pending state on COMMIT, and authorize data only after final READY;
  \item reclaim all setup state by local expiry without peer cooperation;
  \item admit fresh branches through per-peer and node-global limits before expensive cryptography;
  \item report peak and final state, not only cumulative allocation;
  \item refrain from active or timing-resistance claims until the corresponding profiles are specified and tested.
\end{enumerate}

\section{VarUInt note}

The legacy document defined a one-to-one MSB base-128 variable-length integer. Core v0.4 does not yet select a canonical binary encoding because variable-length public fields can reveal value classes and complicate fixed-size records. The future codec may retain VarUInt inside encrypted and padded bodies, but all encodings must be canonical and rejected on alternate representations.

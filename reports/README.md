# Reports

Tracked report files are deterministic outputs generated by repository tools.

- `iteration-0002-sweep.csv` - fixed bounded-discovery parameter sweep.
- `iteration-0003-policy-comparison.csv` - fixed broad flood versus expanding rings.
- `iteration-0004-unlinkability-comparison.csv` - identifier-based versus U1 branch-local resource cost.
- `iteration-0005-lifecycle-comparison.csv` - E1 clean transport, loss/duplication, and fresh-branch attack scenarios.
- `iteration-0006-crypto-conformance.json` - deterministic C1 component conformance.
- `iteration-0007-wire-tagging-comparison.csv` - integrated C1 ratio-tag negative control.
- `iteration-0008-message-cell-capacity.csv` - M1/W2 historical capacity comparison.
- `iteration-0008-lifecycle-fragmentation.csv` - multi-cell lifecycle and loss comparison.
- `iteration-0009-c2-active-security.csv` - C1 negative-control versus symbolic C2 active-mutation scenarios.
- `iteration-0011-r1-gate-b.csv` - active R1 discovery and post-READY rendezvous fallback comparison.
- `iteration-0012-t1-reliability.csv` - unrecovered W2 versus T1 selective recovery and fixed scheduling under 2%, 5%, and 10% cell loss.
- `iteration-0012-t1-trace-equivalence.csv` - active-versus-empty fixed-schedule public trace comparison.
- `baseline.json`, `conservative.json`, `dense.json` - deterministic single-run discovery examples.

Reproduce them with:

```bash
make reproduce
```

These outputs are model results. The symbolic C2 report is not evidence that a concrete cryptographic construction satisfies the C2 games. The T1 fixed-schedule report establishes only the modeled per-link slot-shape property under its declared finite epoch and no-overflow assumptions.
